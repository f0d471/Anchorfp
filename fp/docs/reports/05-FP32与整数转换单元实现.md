# FP32 与整数转换单元实现

## 一、动机

量化与反量化是推理负载里最常见的循环之一，主体是 32 位整数与 FP32 的互相转换。
在软件浮点实现里，整数转浮点与浮点转整数各是一次函数调用，数十个周期。

两个方向的电路深度都不大，按第 01 章的延迟准则，这个单元与比较器一样做成 1 拍。

## 二、为什么两个方向的步骤不对称

### 两种编码的差别在于小数点的位置

int32 与 FP32 都是 32 位，区别在于小数点在哪：

```text
   int32     小数点固定在最低位右边，每一位的权重写死

             b31 b30 ... b1 b0 .
              |               |
             2^31            2^0

   fp32      小数点位置由阶码给出，浮动

             1 . f f f f f f f  x  2^(e-127)
```

互转就是在两种编码之间搬运有效位，搬的时候要回答"有效位现在在哪、应该挪到哪"。
两个方向对这个问题的处境不同，步骤的不对称由此而来。

### 整数转浮点：位置未知，要先找

给一个整数，它的最高有效位在第几位不确定，而 FP32 要求最高有效位固定放在隐藏位。
所以第一件事是找：数出前导零个数，才知道要左移多少位。
找到的位置本身就是阶码：最高位在第 k 位，这个数的量级是 `2^k`，阶码是 `k + 127`。

整数最多有 32 位有效位，而 FP32 只能存 24 位，超过 `2^24` 的整数转过去必然丢低位，所以要舍入：

```text
   取绝对值  ->  找最高位  ->  左移到位、算阶码  ->  舍入
```

### 浮点转整数：位置已知，但范围有限

反方向，阶码直接给出小数点位置，移位量是算出来的：

```text
   移位量 = (阶码 - 127) - 23
   结果为正  ->  左移
   结果为负  ->  右移，丢掉小数部分
```

但 int32 能表示的范围是固定的，FP32 很容易超出去，所以要饱和：超上界给最大值，超下界给最小值，
无符号还要处理负输入。截断方向按 C 语言 `(int)` 的定义向零截断，不做舍入：

```text
   拆包补隐藏位  ->  算移位量并移位  ->  向零截断  ->  范围判断与饱和
```

### 两个方向的对照

```text
                 整数转浮点                浮点转整数
   位置          未知，要找前导零            已知，由阶码算出
   精度          32 位装不进 24 位，要舍入   向零截断
   范围          整数一定装得进 FP32        FP32 可能装不进整数，要饱和
```

两个方向合在一个单元里，由输入 `mode` 选择方向、`is_unsigned` 选择有无符号。

## 三、每一步做了什么

### 3.1 端口与方向选择

```text
   mode = 0   整数转浮点，就近舍入到偶数
   mode = 1   浮点转整数，向零截断，越界饱和
   is_unsigned = 0 / 1   整数一侧按有符号 / 无符号解释
```

分发层用 `fpu_imm` 的低两位传递这两个选择位。两个方向的组合逻辑共用一级输出寄存器。

### 3.2 整数转浮点：找最高位

```text
   输入     00000000 01101101 xxxxxxxx xxxxxxxx
                     ^ 最高位在 bit22
                     |
                     v  数出前面有 9 个零，左移 9 位
            01101101 xxxxxxxx xxxxxxxx 000000000
            ^ 最高位挪到 bit31，即隐藏位该在的位置

   阶码 = 22 + 127 = 149 = 158 - 9
```

常数 158 是 127 加 31：最高位在 bit31 时量级为 `2^31`。前导零每多一个，阶码减一。
找最高位写成 32 路并列判断，与加法器的前导零计数是同一类电路。

### 3.3 整数转浮点：舍入

左移到位之后，低位有一段装不进 24 位尾数，用 G、R、S 三位判进位，与乘法器相同。
舍入确实会发生：超过 `2^24` 的整数一定丢低位。

### 3.4 浮点转整数：移位与截断

```text
   输入 5.75 = 1.0111 x 2^2

   补隐藏位后的 24 位尾数
   +-+-----------------------+
   |1|0111000...             |
   +-+-----------------------+
      |
      v  按阶码算出的量移位，隐藏位落到 2^2 的位置
   +------------------+-------------+
   |     整数部分 101  | 小数部分 11 |
   +------------------+-------------+
                        |
                        v  向零截断，直接丢掉
                       101 = 5
```

补回隐藏位后，隐藏位在 24 位尾数的最高位，目标整数最高位的位置为 `exp - 127`，
所以尾数的有符号移位量为 `exp - 150`。

### 3.5 浮点转整数：范围判断与饱和

```text
   输入            有符号            无符号
   ----------------------------------------------
   |x| < 1         0                 0
   正的超上界      0x7FFFFFFF        0xFFFFFFFF
   负的超下界      0x80000000        0
   负数（未越界）  正常转换           0
   NaN             0                 0
   denormal        0（按 DAZ）        0
```

有符号与无符号的上界差一档阶码：有符号能装到 `2^31 - 1`，无符号能装到 `2^32 - 1`。
`INT32_MIN` 这一点走饱和分支，饱和值恰好是 `0x80000000`，结果正确。

整个模块只有移位与加减，没有乘法器。

## 四、遇到的问题

### 4.1 随机激励的 bit31 几乎恒为 0

第一现场。统计生成的随机向量，bit31 的分布：

```text
   5 万条随机向量中
   bit31 = 0 :  49998
   bit31 = 1 :      2
```

解读。对这个单元，bit31 是符号位。受影响的路径：

```text
   整数转浮点   负整数            取绝对值那一支        几乎没执行过
   浮点转整数   负浮点            符号恢复那一支        几乎没执行过
   浮点转整数   无符号 + 负输入   钳零那一支            几乎没执行过
```

三条路径在随机段里几乎全是空转，只靠定向用例支撑，而"随机 5 万条全过"读起来像是覆盖得很好。

定位。随机数来自 `rand_r()`，返回范围是 0 到 `2^31 - 1`，bit31 恒为 0，
那 2 条来自别的路径。一半的取值空间从来没有被采样。

根因与修法。改为拼两次随机数取满 32 位，重新生成。改完之后 bit31 为 1 的有 49,861 条，
全部通过，设计本身没有问题。但在修改之前，这件事是不可知的。

原判据为什么没有覆盖到它：随机激励的取值域没有单独验证过。C 标准只保证 `rand()` 返回 0 到
`RAND_MAX`，而 `RAND_MAX` 通常是 `2^31 - 1`。
