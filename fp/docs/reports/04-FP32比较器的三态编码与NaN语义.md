# FP32 比较器的三态编码与 NaN 语义

## 一、动机

加、减、乘做完之后，浮点比较成了下一个目标。在浮点密集的负载里，裁剪、排序与分支条件
大量使用比较；前几项算术变快之后，比较在剩余开销中的占比随之上升。

比较与前面三个单元的性质不同：

```text
   加减乘   FP32, FP32  --->  FP32        要规格化、要舍入
   比较     FP32, FP32  --->  一个关系     不产生新的数
```

不产生新的数，就没有规格化、没有舍入、没有上下溢。按第 01 章的延迟准则，这个单元做成 1 拍。

## 二、为什么是这五步

### 电路部分几乎是现成的

IEEE 754 的字段顺序是符号、阶码、尾数，从高位到低位，阶码是偏置编码的无符号数。
阶码大的数绝对值就大，阶码相同时尾数大的绝对值就大，所以同号的两个浮点数直接当整数比，
结果与按浮点比相同。比较的主体是一个整数比较器。

### 工作量在语义对齐上

真正要做的是把 IEEE 的序关系映射到调用方使用的返回值约定上。
软件浮点库的比较例程返回一个三态整数，调用方拿到后再与 0 比较：

```text
   a < b   ->  返回负值
   a == b  ->  返回 0
   a > b   ->  返回正值
```

IEEE 的序关系与这个约定有三处对不上，每一处生出一步：

```text
   对不上之处 1：零有两个位模式
       +0 = 0x00000000    -0 = 0x80000000
       位不同，但 IEEE 规定它们相等；直接当整数比会得出 -0 < +0

   对不上之处 2：NaN 与任何数都不可比
       IEEE 说含 NaN 的比较是"无序"，而三态码只有三个取值，没有第四种

   对不上之处 3：六个比较符号遇到 NaN 时方向相反
       lt、le、eq、ne 这一族遇到 NaN 要返回正值
       gt、ge 这一族遇到 NaN 要返回负值
       硬件要知道调用方属于哪一族
```

再加上三态码的输出格式与 DAZ 规整，一共五步：

```text
   一  比较主体      异号看符号位，同号比低 31 位整数值
   二  处理零        正负零判相等
   三  返回三态码    与软件比较例程的约定一致
   四  处理 NaN 方向  六个符号分两族
   五  DAZ 规整      与加法器、乘法器同一套契约
```

## 三、每一步做了什么

### 3.1 比较主体与零

```text
   异号        负的那个小                   只看符号位

   同号为正    直接比低 31 位               位序即数值序
               a[30:0] < b[30:0]  =>  a < b

   同号为负    比低 31 位再取反             绝对值大的负数反而小
               a[30:0] < b[30:0]  =>  a > b

   两个都是零  判相等                       +0 与 -0 位不同但数值相等
```

零那一支必须先判，否则 `+0` 与 `-0` 会被异号分支接管，判成 `-0 < +0`。

### 3.2 返回三态码

输出是 32 位有符号数，取值 -1、0、+1。

返回三态意味着调用方还要再做一次整数比较与分支。这层开销是否会抵消收益，
用一个紧循环探针测过：循环体写 `(a < b) ? 1 : 0`，调用方的整数比较与分支都计在内，
单次比较的开销与一次浮点加法相当，没有抵消掉收益。

### 3.3 NaN 的方向

调用方对返回值的判断方向不同，而含 NaN 的任何比较都应当为假。
要让两族都判成"条件不成立"，返回值必须往相反方向给：

```text
                     硬件返回      调用方的判断         结果
   lt 族遇到 NaN       +1          +1 < 0 ？ 否        条件不成立
   gt 族遇到 NaN       -1          -1 > 0 ？ 否        条件不成立

   若两族都返回 +1：
   gt 族遇到 NaN       +1          +1 > 0 ？ 是        条件成立，错误
```

所以单元有一个输入 `gt_family`：0 表示 lt、le、eq、ne 族，1 表示 gt、ge 族。
六个比较符号共用同一个操作码，差别只在这一位。分发层用 `fpu_imm` 的最低位传递它。

### 3.4 DAZ 规整

入口把 denormal 规整成同符号的零，与加法器、乘法器使用同一套契约。
这一步不影响性能，它保证多个消费者对同一个位图给出同一种解释：
若比较器说 `d != 0` 而乘法器说 `d == 0`，同一个程序里两个单元会对同一个数给出矛盾的答案。

### 3.5 三态码不是全序

含 NaN 时 `cmp(NaN, x)` 与 `cmp(x, NaN)` 返回同号（lt 族都返回 +1，gt 族都返回 -1）。
这是软件比较例程约定的语义，因此三态码不能直接交给排序函数当比较器用。
排序类场景要在排序前自行处理 NaN。

## 四、遇到的问题

### 4.1 族位接反，常规值一条都验不出来

第一现场。族位若接反，用常规浮点值做激励，一条用例都不会失败。

解读。对有序的输入，两族返回的是同一个值：

```text
                   lt 族返回    gt 族返回    是否相同
   a < b             -1           -1         相同
   a == b             0            0         相同
   a > b             +1           +1         相同
   任一是 NaN        +1           -1         不同，只有这一行
```

方向的差别只在 NaN 上体现，而 NaN 不会出现在随机浮点激励里，除非专门构造。
这与第 03 章 4.2 节的零符号是同一类问题：一个控制位只在某个窄输入子集上可观测，
不覆盖那个子集的判据对它的鉴别力为零。

根因与修法。补四条 NaN 定向用例：

```text
   qNaN vs 1.0        lt 族应返回 +1，gt 族应返回 -1
   1.0  vs qNaN       同上，NaN 在第二个操作数位置
   qNaN vs qNaN       两边都是 NaN
   sNaN vs 1.0        信号 NaN 走同一条路
```

再加四条 DAZ 用例，把规整契约也固定下来：

```text
   dmin  vs +0        应当相等    denormal 按零处理
   -dmin vs +0        应当相等
   dmax  vs 1.0       应当小于
   dmin  vs -1.0      应当大于    denormal 变成 +0，大于 -1.0
```

原判据为什么没有覆盖到它：写定向用例时没有先想清楚，实现若接反，会在哪一类输入上露馅。

### 4.2 调用方的判据把三态码当布尔比

第一现场。调用方的一个测试程序对 16 × 16 组输入比较硬件结果与软件结果，报出：

```text
fcmp: 240/256 mismatch
```

解读。失配 240，总数 256，匹配的只有 16 条。256 等于 16 × 16，激励是一个组合矩阵；
匹配的恰好 16 条，等于矩阵一条对角线的长度：

```text
        b0  b1  b2  ...  b15
   a0   ok  X   X        X
   a1   X   ok  X        X
   ...              ok
   a15  X   X   X        ok

   匹配的全在对角线上，也就是 a == b 的那 16 组
```

真正的实现缺陷很少会精确放过一个有结构的子集。匹配集有结构，说明失配是系统性的，
而且与"相等"这个关系有关。

定位。硬件返回三态整数，判据把它当布尔值比：

```text
   关系      硬件返回    判据期望   是否相符
   a < b       -1          1         不符
   a > b       +1          0         不符
   a == b       0          0         相符，即对角线
```

根因与修法。硬件没有错，判据错了。判据改为按三态对照：

```c
int hw = cmp_lt_family(a, b);          /* 硬件返回 -1 / 0 / +1 */
int lt = (a < b), gt = (a > b);
if ((hw < 0) != lt || (hw > 0) != gt) mismatch++;
```

改完之后同一组输入失配为 0，硬件一个字没改。

原判据为什么没有覆盖到它：判据写错了接口约定。
失配数等于"总数减去某个可解释的子集"时，应当先怀疑判据。
