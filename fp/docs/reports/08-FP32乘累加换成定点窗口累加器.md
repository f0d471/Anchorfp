# FP32 乘累加换成定点窗口累加器

## 一、动机

[第 07 章](07-FP32乘累加反馈环的启动间隔.md)把三级流水的加法器接成反馈环，
量出相邻两项之间必须隔 4 拍；要恢复每拍一项，就得摆 4 个累加器交错使用，再加一棵归约树。
这个办法绕开了问题，付出的是一整条链：

```text
   反馈环 3 拍
     -> 单累加器的喂积间隔是 4
     -> 摆 4 个累加器交错，把间隔压回 1
     -> 于是需要一棵归约树与一份归约控制，每份例化各一套
     -> 于是累加器成了数组，多路选择器进了环内
     -> 于是求和次序变成累加器个数的函数，金标准得复刻这个次序
     -> 而且每一项乘积各自舍入一次，误差随项数累积
```

这一章去掉链的源头：让反馈环只有一拍。链上其余几条随之消失。

同时要回答一个一直被回避的问题：误差。逐项舍入的累加器在长点积上误差随项数增长，
而把累加器换成定点尺子之后，"会丢什么、丢多少、什么时候看得见"必须能写成使用者可以推理的契约。

## 二、为什么是这几步

### 三拍花在哪里

加法器的三级分别是对阶移位、加减与规格化、舍入组装。放进反馈环，三件事都在环里：

```text
   acc ---> 对阶 ---> 加减+规格化 ---> 舍入 ---> acc
            (1 拍)      (1 拍)        (1 拍)
```

只有中间那个加是累加真正需要的。对阶在环里，是因为累加器的阶码是动态的，
下一项要移多少位得等这一次的结果出来；规格化与舍入在环里，是因为累加器保持着 FP32 的形式，
而中间结果没有人看，只在最后一项之后才需要变回 FP32。

### 把小数点钉死，两件事都能搬到环外

整组要相加的数若先对齐到一个共同的阶码基准，就成了同一把尺子上的定点整数。
定点整数相加不用对阶、不用规格化、不用舍入：

```text
   项 --->[对阶]--->+---> [ 定点加 ] ---> [ acc ]
         (环外)     |          ^             |
                    |          +-------------+
                    |            环长 1 拍
   末项之后 --------+---> [规格化+舍入] ---> FP32 结果
                          (环外，一块只做一次)
```

对阶能搬到环外，是因为移位量是"基准减这一项的阶码"，只跟这一项有关，跟累加器当前值无关。

### 基准不能是常量

尺子钉在哪里是下一个问题。一个点积内乘积的阶码可以跨几十位，第一项没有理由是最大的那一项，
所以基准必须会动，而且动的那一步不能把环拉长。

### 项从哪里来

窗口要的是 48 位定点积。乘法器第 2 级做的是把 48 位积规格化、舍入成 24 位尾数，
在这条通路上是多余的：它先扔掉低位，窗口再把尾数零扩展回去。所以累加器直接取乘法器第 1 级的未舍入积，
这就是融合乘加。

### 步骤

```text
   统一刻度       乘积与部分和换算成同一个二元组             <- 定点相加的前提
   动态基准       基准跟着运行最大值走，量子化上调           <- 全指数域不能饱和
   窗口定宽       上方裕度、量子、下方余量、求和增长         <- 决定精度与项数上限
   特殊值旁路     NaN 与 Inf 装不进定点窗口                  <- 加法器撤掉后那条通路断了
   融合乘加       直接取乘法器第 1 级的未舍入积              <- 省掉一次多余的舍入
   共享移位器     对阶与规格化共用一个桶形移位器             <- 面积的主要杠杆
   误差契约       五类信息损失分开说清楚，给出一条恒成立的界   <- 使用者要能推理
   调用契约       五条调用约定，仿真断言与例化期检查           <- 违约不能静默
```

## 三、每一步做了什么

### 3.1 统一刻度

乘积与部分和 `psum_in` 都换算成二元组 `(mant48, E)`，约定它代表的值恒为：

```text
   值 = mant48 x 2^(E - 173)
```

173 由三处对齐得出：

```text
   FP32     a = ma x 2^(ea-127-23)，ma = {1,frac} 落在 [2^23, 2^24)
   两个相乘 a x b = (ma x mb) x 2^(ea+eb-254-46)
   令 E = ea + eb - 127，则 a x b = (ma x mb) x 2^(E-173)
```

于是乘积的 `mant48` 就是 `ma x mb`，`E` 就是 `ea + eb - 127`，这两个量乘法器第 1 级已经算好。
单个 FP32 数换算到同一把尺子取 `mant48 = mx << 24`、`E = ex - 1`。

### 3.2 动态基准

维持一条不变式：进窗口的每一项都满足 `B >= 这一项的阶码 + WinUp`。
来了一项不够高就把基准往上抬，抬多少位，累加器就在同一拍算术右移多少位：

```text
   新项的阶码高于基准的容量
        |
        v
   基准 += delta      累加器 >>= delta      本项按新基准对齐
   (delta 是 WinG 的整数倍)
```

这一步不拉长反馈环。`delta` 量子化为 16 位的整数倍，只有少数几档，
环里加的是一个多选一的移位选择，每位一个 LUT6，后面串 88 位进位链：

```text
   acc ---> [多选一移位] ---> [ 加法器 ] ---> acc
              1 级 LUT          进位链
```

`delta` 跟着项一起在流水里走，判断在环外做，环里只有选择与加。

跨块的部分和以 FP32 回灌进来，也要进窗口。只要 `psum_in` 非零就让它先定基准，
它自己的移位量恒等于 `WinUp`，是编译期常量，直接接线，不占桶形移位器；
第一个乘积在下一拍才用移位器，两者不冲突。

新来的项若比当前基准高出整个累加器的宽度，旧的累加和已无法右移保留，
这时基准重新锚定、累加器清空。这一类事件的后果见 3.7 节第 4 类。

### 3.3 窗口定宽

```text
   TW   = 48 + WinUp + WinG + WinFrac     = 80    对齐后一项占的位宽
   AccW = 48 + WinG + WinFrac + GrowW + 1 = 88    累加器位宽
```

- 48 是乘积尾数的位宽，24 乘 24；
- `WinUp = 8` 是不变式要求的最小上方裕度；
- `WinG = 16` 是基准上调的量子，量子化之后最大项落在 `WinUp` 到 `WinUp + WinG` 之间，这一段也得算进窗口；
- `WinFrac = 8` 是最大项最低位之下还留的位数，决定认证精度；
- `GrowW = 15` 是求和增长位，撑得住 `2^15 = 32768` 项；末尾 1 位给符号。

`AccW` 的式子里没有 `WinUp`：不变式保证任何单项对齐之后的最高位都不超过 `TW − 1 − WinUp`，
窗口顶上那 `WinUp` 位不是项的落点，本来就是求和增长的空间。

给定项数上限 N 与精度参数，位宽由两条式子确定：

```text
   AccW = 48 + WinG + WinFrac + ceil(log2 N) + 1
   Q    = 46 + WinFrac − ceil(log2 N)
```

`Q` 的含义见 3.7 节。默认档 `WinFrac = 8`、`GrowW = 15` 得 `AccW = 88`、`Q = 39`。
只做 255 项的使用者把 `GrowW` 传成 8，得 81 位、`Q = 46`；
`GrowW` 传成 482，窗口覆盖 FTZ 全域，退化为一位不丢的精确累加器，555 位。
88 位是这条设计空间上的默认点，平坦段的测量见第五节。

### 3.4 特殊值旁路

定点窗口里没有 NaN 与 Inf 的位置。用三个粘滞标志记录：见过 NaN、见过 +Inf、见过 -Inf。
末项组装时优先输出：见过 NaN 或正负 Inf 都见过则出 qNaN，单向 Inf 出对应符号的 Inf，否则走定点结果。
分类位在乘法器第 1 级已经算好，直接引出。

结果精确得零时的符号：IEEE 的规定是全部参与项都是负零才出 -0，其余一律 +0，
所以另有一个零项符号的与，和一个"有没有非零项参与过"的标志。

### 3.5 融合乘加

乘法器拆成两个模块（第 02 章 3.6 节）：第 1 级输出未规格化、未舍入的 48 位积，第 2 级做规格化与舍入。
标量乘法走两级，乘累加单元只取第 1 级。参数 `FuseMul = 0` 时改取第 2 级舍入后的结果，
这一档只用于测量融合买到的精度（第五节）。

拆模块而不是给乘法器加一组旁路输出端口，是为了不在每一处标量例化上留下一组未连接的端口。

### 3.6 共享移位器

对阶要一个 88 位右移器，规格化要一个 88 位左移器。两者从不同拍使用：对阶在累加期，
规格化在末项之后。所以共用一个桶形右移器，左移由输入输出两侧的位序翻转实现，翻转是纯连线：

```text
   对齐期    尾数放进 TW 位域顶端，右移 (B - E)
   规格化期  累加值绝对值位序翻转后右移 lz，再翻回来，等价于左移 lz
```

这是本模块面积上的主要杠杆，拆开的实测见 4.10 节。

流水划分：

| 级 | 内容 |
|---|---|
| A | 项源选择、基准推导、上调量、移位量 |
| B | 桶形移位、取二补数 |
| ACC | 累加：多选一移位加 88 位加法 |
| Na | 取模、前导零检测 |
| Nb | 规格化移位，复用同一个移位器 |
| Nc | 就近舍入到偶数、组装 |

末项 `prod_valid` 到 `out_valid`：融合档 7 拍（乘法第 1 级 1 + 对阶 2 + 累加 1 + 规格化舍入 3），
非融合档 8 拍。喂积间隔为 1。延迟常数写在 `fp32_lat.vh`，由 `tb_fp_lat.v` 实测。

### 3.7 误差契约

一项要进尺子，得先右移到共同刻度上。丢信息的地方一共五处：

```text
   进来一项 ---> 右移对齐 ---> 加进累加器
                    |
                    +--(1) 移出去的低位没了

   来了个更大的项 ---> 抬基准 ---> 整个累加器右移
                                        |
                                        +--(2) 累加器的低位没了
                                        +--(3) 累加器为负时，截断方向与正数相反

   来的项大得离谱 ---> 基准重锚 ---> 累加器清空
                                        |
                                        +--(4) 旧的和整个没了

   一块算完 ---> 结果转回 FP32 ---> 当下一块的初值
                                        |
                                        +--(5) 每个块边界舍一次
```

五类的量级相差几十个二进制位，只报一个总的 ULP 等于把五件事搅在一起，
所以逐位金标准里给每一类挂了计数器。

**第 1、2、3 类有一条可算的界。** 被丢掉的位全都在窗口最低位以下，而窗口最低位的实数权重是
`λ = 2^(B - 205)`。基准的不变式给出 `λ <= 2^(-47-WinFrac) · M`，`M` 是最大项的绝对值。
每一项对齐丢位、每一次换基各引入不超过一个 `λ`，N 项合计：

```text
   |Z − S| < 2N·λ <= 2^-Q · M <= 2^-Q · A        Q = 46 + WinFrac − ceil(log2 N)
```

`Z` 是末项舍入之前的窗口累加值，`S = Σ tᵢ` 是精确和，`A = Σ |tᵢ|` 是输入的绝对和。
这条界只用到基准的不变式，不依赖"保护位固定多少"一类假设。
第 3 类另有一条证据：把整组向量取反再运行，结果严格互为相反数。

**第 1 类的极端档会稳定地差 1 个 ULP。** 构造：

```text
   第一项   M                  一个尾数末位为偶数的数
   第二项   M 的半个 ULP        正好落在两个可表示数的中点上
   第三项   一个极小的数        小到整项被移出窗口
```

精确的和严格大于中点，正确答案是进位；硬件看到的正好是中点，按规则向偶数取，不进位。
这一族构造稳定复现。末项的舍入作用在窗口内的值上，窗口之外的位不参与平局判定，
这是一条规则，使用者可以据此判断自己的数据会不会踩上。处置是写进契约，不修，理由见 4.10 节。

**第 4 类是结构的固有代价。** 序列 `[s, X, -X]`：先累加出一个小和 `s`，
来一个巨大的项 `X` 使旧和被清掉，再来 `-X` 与之精确抵消，正确答案是 `s`，硬件给 0。
任何"基准跟着最大值走、尺子长度有限"的累加器都有这一条，消除它的办法是把尺子加长到覆盖整个指数范围。
上面那条界在这里依然成立：`S` 变小时 `A` 不变小，误差被 `A` 约束。
所以契约不写"抵消场景不在承诺内"，而写一条恒成立的不等式；代价是验收要按绝对误差与输入尺度检查，
不能要求接近零的 `S` 仍保持固定的相对误差。

**第 5 类不属于累加器。** 部分和走 FP32 这个接口，每块边界舍一次。
分块求和的误差正比于条件数 `Σ|tᵢ| / |Σ tᵢ|`，而条件数没有上界，
所以任何形如"n 块最多 n 个 ULP"的上界都是错的。要设回归闸门，只能取实测值加余量。

### 3.8 基准重锚事件 mac_prec

第 4 类是灾难性损失确定发生过的一次，硬件确切知道它发生了。
单元把它单独引出一位 `mac_prec`：条件是新项比当前基准高出整个累加器的宽度、旧和被丢弃，
逐块粘滞，`acc_load` 清零。调用方可以把各条 lane 的这一位或起来汇成一位状态；
置位时取上升沿，挂电平会在下一块起头被重新置起而清不掉。

这一位只报第 4 类，不报普通对齐右移丢掉的非零低位。
另一个信号 `win_rescale` 报的是"本块抬过基准"，它在移出位全零时也置位，假阳性率高到几乎恒为真，
所以不引出端口。

### 3.9 调用契约

五条调用约定，网表里不检查，仿真断言 C1 到 C5 各带独立计数器接住，断言在 `fp32_mac_assert.vh`：

1. C1：相邻 `prod_valid` 的间隔不小于 `FP32_MAC_PACE`（当前为 1，恒成立）；
2. C2：`last` 与末项的 `prod_valid` 同拍；
3. C3：末项之后到 `out_valid` 之前不许再喂积。区间从末项开始，此时流水线里还有在飞的项，
   而模块内部没有任何忙标志是高的，只盯忙标志的断言抓不到；
4. C4：末项到 `out_valid` 的实测拍数等于 `FP32_MAC_OUT_LAT_F(FuseMul)`；
5. C5：一块之内进窗口的项数不超过 `2^GrowW`，`psum_in` 非零时也算一项。

第 5 条另有例化期的一道：调用方用参数 `MaxTerms` 声明自己每块最多喂多少项，
超过 `2^GrowW` 就在例化期报错。分块深度在综合前就完全确定，能在编译期查的就在编译期查。
两道各管一段：`MaxTerms` 管调用方要不要得起，C5 管运行起来之后有没有真的超出。

## 四、遇到的问题

### 4.1 以第一项定基准，300 组里 95 组饱和

第一现场。第一版以第一项定基准：`B = 第一项的阶码 + 24 位上方裕度`，
比第一项大得多的项装不下就饱和并置标志。随机点积激励跑 300 组，95 组置了饱和标志。

解读。饱和之后结果是错的，不是不够精确。95/300 说明这是常态：随机向量里第一项恰好是最大项的概率只有 1/K。

根因与修法。一个点积内乘积的阶码跨度可达几十位，以第一项为锚的窗口会把窗口之上的部分整个丢掉。
这不是裕度取 24 位还是 32 位的问题：FTZ 语义下最小乘积是 `2^-252`、最低有效位在 `2^-299`，
最大乘积不到 `2^256`，覆盖全域要 555 位。修法是 3.2 节的动态基准。

原判据为什么没有覆盖到它：判据当场覆盖到了。值得记的是量窗口够不够宽，看的是撑破的比例，而不是最大误差。

### 4.2 第一版切少了，一拍装不下

第一现场。第一版把基准推导、移位量、桶形移位、取二补数放在同一拍，总延迟 5 拍，仿真全绿。
单 lane 离线综合，20 ns 约束，关键路径：

```text
   exp_r --> need --> raise/dq --> base_nxt --> sh_s --> sh_big/sh_al
         `--> 88 位桶形右移器（4 级 LUT6）--> 取反 --> term_q

   36 级逻辑，24.07 ns（逻辑 10.5 ns，布线 13.5 ns）
```

解读。路径超过 20 ns 周期 4 ns。四个 12 位加减器串在一起，后面再挂一个 88 位桶形移位器。

根因与修法。按 3.6 节的 A、B 两级切开，同一条路径降到 18 级、12.1 ns。
一条路径的级数不能按"里面有几个运算"估，要按报告里的逻辑级数算。

原判据为什么没有覆盖到它：功能仿真不检查时序。

### 4.3 切级之后，acc_load 那一拍算出一次假的上调

第一现场。切级后，300 组里 75 组的 `win_rescale` 与金标准不符，2 组结果差 1 ULP。

解读。结果只差 1 ULP 的那 2 组，单看结果很容易当成容差放过；75 组的精度标志不符才暴露出问题。

根因与修法。`acc_load` 那一拍基准重新锚定，而基准寄存器里还是上一块的值。
切级之前那一拍不经过基准推导；切级之后部分和与乘积走同一条路，于是那一拍拿旧基准算出一次上调，
部分和也移错了位。修法是在 `acc_load` 那一拍把"基准已落定"当成假。

原判据为什么没有覆盖到它：判据覆盖到了，因为 `win_rescale` 进了逐位判据。
这个信号没有下游消费者，却是这个缺陷唯一的可观测点。把两条通路合并成一条时，要连同它们的初始状态一起合并。

### 4.4 进位保存累加器：先判"等价但净亏"，后改判"不等价"

第一现场。反馈环里的加法器还能更快：把累加器存成和向量加进位向量，环里换成不做进位传播的 3:2 压缩器，
末项之后再做一次进位传播加法。单 lane 离线综合：

| 累加器实现 | LUT | FF |
|---|---:|---:|
| 行波进位 | 1408 | 386 |
| 进位保存 | 1751（+24.4%） | 471（+22%） |

解读。在 7 系列上它净亏：N 位行波进位加法器映射成 N 个 LUT6 加专用进位链；
3:2 压缩器没有专用资源，和位与进位位各一个 LUT6，还要多一组寄存器，末项之后仍要一次进位传播加法。
换来的时序余量在 20 ns 周期下用不上。当时的结论是"两档逐位相同，同一份金标准跑两遍都通过，只是不启用"。

定位。那句"逐位相同"是错的。基准上调时，进位保存档的和向量与进位向量各自算术右移，
分别截断再相加，不等于先相加再截断。差别只在被截掉的那一位上，只有低位重新成为主角时才看得见，
也就是发生抵消时。换上抵消激励，64 组里 10 组不同。

根因与修法。判据没有错，它比对了它拿到的那份激励，而常规激励走不到抵消路径。
错的是没有规定"两档逐位相同"这句话该用什么激励去验：同一批向量在两档下结果相同，
只有在向量走到差异路径时才有证伪力。这一档撤出支持集合，例化期检查挡住 `UseCarrySave != 0`，
那一档回归删除。判死的理由从"净亏且等价"改为"净亏且不等价"。

原判据为什么没有覆盖到它：激励没有覆盖声称被验证的那个性质所依赖的路径。

### 4.5 项数上限：式子算漏，断言误报，编译期没查

第一现场。最初的累加器位宽写的是 `AccW = TW + 8`，把末尾 8 位解释成"7 位给求和增长、1 位给符号"，
项数上限因此写成 255。同时 C5 断言对完全合法的满额分块报警。

解读。两处问题不同。位宽式子漏算了 `WinUp` 已经贡献的增长空间（3.3 节）：两种写法在默认参数下都得 88，
网表一位没变，错的是理由，代价是项数上限被说小了 128 倍，实际是 32768。
C5 数的是复位以来的累计项数，不是当前块的，前面跑够了量，合法的满额块也会被误报；
一条会对合法输入报警的断言，用不了几次就会被当成噪声忽略。

根因与修法。位宽式子改为 3.3 节的形式；C5 改为数当前块，`acc_load` 那一拍重置，`psum_in` 也算一项；
加 `MaxTerms` 例化期检查。判据加两档：`2^GrowW` 项满额必须不报，多一项必须报，
上限从 RTL 里现取，不在脚本里另写数值。

`MaxTerms` 的判据设计也踩了一个坑：原本打算的判据是"去掉 `MaxTerms != 0` 这个短路条件后，
不传参的例化必须报错"。这条不成立：不传参时 `MaxTerms` 为 0，去掉短路后判的是 `0 > 上限`，仍然为假。
换成三点边界才量得准：`MaxTerms` 取 0 与取上限必须编译通过，取上限加一必须报错。

原判据为什么没有覆盖到它：满额那一档从未跑满过，一直只跑 64 项；项数上限只有仿真期一道防线。

### 4.6 误差界第一版的推导用了不成立的前提

第一现场。误差界的第一版是这样推的：最大项的移位量恒为 `WinUp = 8`，
所以它的尾数固定落在第 71 到 24 位，下面固定有 24 位保护位；结果的最低有效位在第 48 位；
一块最多 255 项，累计丢失量小于 `255 / 2^48`，约 `2^-40` 个 ULP。

解读。结论方向没错，前提是假的。基准按 16 位量子上抬，最大项的移位量在 8 到 23 之间取值，
保护位最少只剩 9 位；独立模型实测到的最大移位量正是 23。另一处前提也不成立：
发生抵消时结果变小，它的最低有效位往下走，不在第 48 位。

根因与修法。换成 3.7 节只依赖不变式的那条界。一个错误的推导配一个正确的结论，比错误的结论更难发现，
而使用者不会只抄结论，会照着推导去算自己的数据，"保护位固定 24 位"用来估余量会偏出 14 位。

原判据为什么没有覆盖到它：推导没有独立验证。现在由一个独立的大整数模型逐前缀检查不等式，
不调用逐位金标准的代码。

### 4.7 判据自己也要被验：五个注错里四个没红

第一现场。把金标准改坏五处，检查逐位判据是否当场报错：给移出位补粘滞位、换基改成对称截断、
清空那一档改成不清、末项舍入改成截断、窗口加长八位。第一次运行，五个里四个没有报错。

解读。四个都不是判据坏了，是配错了激励：

- 对称截断配到了反复换基那组激励上，那组的丢位量在结果最低位之下几十位，换个截断方向照样看不见；
  必须让换基之后发生抵消，被丢掉的低位重新成为主角。
- 清空改成不清的第一版写法是把旧和右移到窗口最底下再留着，移完就是零，与清掉结果相同；改成原地不动才是有效注入。
- 舍入改成截断配到了中点那组激励上，那组每条都精确卡在中点、尾数取偶，向偶数取与截断给出同一个答案。
- 窗口加长八位配到了长串小项那组激励上，那组丢的位本来就看不见。

另有一层更隐蔽的：换基注入一开始怎么都不报错，原因是单个 FP32 数换算到定点尺子上时低 24 位是零填充，
只有初值、没有真乘积的累加器右移多少位都不丢位；必须先垫两个真正的 24 × 24 位乘积。

根因与修法。每个注入点配一类能观测到它的激励之后，五个全部报错，固定在 `run_mac_audit.sh` 里。
这一轮同时是 3.7 节结论的独立证据：有几条路径改坏了都看不出来，比"测下来是零"更强。

同一轮还发现金标准的两层参考共用同一份位型解释与乘积构造代码，那份代码若有错两层会一起错，
"两层都过"发现不了它。把第二层的位型解释、乘积构造与特殊值分类各写一份，
拆分前后所有归因数字逐个不变；再把第一层的乘积阶码改坏一位，两层对拍从最大 0 ULP 变成 139809444，
这个数才是两层真正独立的证据。第一次注入改的是 48 位积的最低位，没有报错，
因为那一位在结果有效位之下 40 位，本来观测不到；改成阶码差 1 立即报错。

还有一个环境层面的坑：Python 的字节码缓存按秒级时间戳判断源文件是否变化，
注错、运行、恢复、再运行若发生在同一秒内，第二次运行的仍是注错版本，现象是恢复之后还是红的。

原判据为什么没有覆盖到它：一次注错不红有两种可能，判据无效，或者注入的路径在当前激励下不可达。
不区分这两种，就会去修一个没坏的判据。

### 4.8 窗口形态的面积比旧形态多七成

第一现场。换成窗口形态后，每条 lane 的面积比旧形态多约七成：省下了一个三级加法器、
3 个多余的累加器和一份归约控制，抵不过新增的 88 位桶形移位器与 88 位累加器。

解读。结构已经定下，问题是在不改结构、不改语义的前提下，能回收多少。
能回收的只有三类来源：寄存了下游用不到的位；控制集，即复位与使能网的接法决定触发器打包密度；
组合逻辑的形状，即功能确定而综合结果由写法决定的那一段。

根因与修法。三条逐位等价的回收：

- **规格化结果只寄 26 位。** 最后一级原来寄存整条 88 位规格化结果，而末项舍入只用得到高 24 位、
  guard 位与其余位的或。只寄这 26 位，或归约提到上一级做，每条 lane 省 62 个 FF。
- **数据寄存器不接复位。** A、B 两级原来由一个复位块统管数据位与控制位，拆成两个 `always`：
  数据位无复位，有效位与末项标记有复位。下游只经 `a1_valid` 与 `a1_last` 看这一级，
  复位期间它们恒为零，数据位里是什么都进不了任何状态。FF 数不变，控制集变少，打包更密。
  模块输出 `mac_out` 保留复位。
- **前导零检测改成两级。** 原来是一条 88 级的级联扫描，综合成什么形状完全看工具。
  改为每 8 位一组先求或，再对组标志与组内分别优先编码，形状确定。拼接结果先赋给一条更宽的线再零扩展，
  否则在当前参数下会写出一个非法的 0 宽度填充。

同一轮把仅仿真使用的调用契约断言外提到 `fp32_mac_assert.vh`，主文件只剩数据通路。
外提前后单 lane 综合结果一位不变，这本身证明那段断言不进网表。
主数据通路不按流水级拆模块：共享移位器横跨 A 级与 Nb 级，按级拆就要把移位器提成独立模块再加一层仲裁，
相邻两级之间要传七组信号，综合器也看不见跨模块的常量传播。

结果见第五节的单 lane 表。

原判据为什么没有覆盖到它：面积不是缺陷，没有判据指向它。

### 4.9 复位被综合成了时钟使能

第一现场。三条回收做完，在一个例化 32 条 lane 的集成设计中，实现后的最差 setup 路径变成：

```text
   slack = 0.053   levels = 0
   from  <复位同步器>/delay_reg[1]/C
   to    <阵列中的一条 lane>/n1_mag_reg[11]/CE
```

解读。`levels = 0` 说明起点与终点之间没有一级组合逻辑，整条余量都花在布线上；
终点是 CE 脚而不是 D 脚，说明这条路径驱动的是时钟使能；起点是复位同步器的输出。
三样合在一起，这是复位网，与数据通路无关。

定位。Na 级只给 `n1_go` 一个复位值，其余十来个数据寄存器写在复位块的 `else` 分支里。
乍看与 4.8 节"数据位不接复位"是同一个规矩，实际相反：数据寄存器在复位期间保持不变，
而"保持不变"正是时钟使能的语义，综合器于是把 `rst_n` 接成了这一整组寄存器的 CE。
88 位乘 32 条 lane，几千个 CE 端挂在复位同步器的一个输出上，布线延迟吃掉整条余量。

根因与修法。控制位一个 `always` 带复位，数据位另一个 `always` 无条件更新，Nb 级同样处理：

```verilog
    always @(posedge clk) begin
        if (!rst_n) n1_go <= 1'b0;
        else        n1_go <= acc_last_q;
    end
    always @(posedge clk) begin
        n1_mag <= acc_mag;  n1_lz <= lz_c;  n1_sign <= acc_neg;
    end
```

功能等价：复位期间 `n1_go` 恒零，下游不看这些数据位。修改后阵列内的最差 setup 路径余量为 1.550 ns，
路径形态从零级纯布线变成 17 级真实数据通路。`syn/scan_reset_as_ce.py` 能把这种写法从整个 RTL 目录里扫出来，
本仓已不在它的输出里。

这一条单 lane 离线综合量不出来：修改前后是 1275 与 1277 个 LUT，差在噪声里。
一条 lane 只有 88 个 CE 端，不构成高扇出，问题在这个尺度上不存在。凡是一个信号扇出到几千个端的问题，
只能在多份例化的层面量，而且要到布线之后才看得见。

原判据为什么没有覆盖到它：4.8 节做回收时看到 Na、Nb 级只复位控制位，判断它们本来就是对的写法。
两种写法的区别在于复位期间数据位是被清零还是被保持：前者接复位网，后者接使能网，后者更糟。

### 4.10 两个看起来应该更好的改法，实测判死

**拆开共享移位器。** 共享让对齐那一侧也被迫用满 88 位，常量传播不了。拆成两个专用移位器会不会净省？

| 档 | LUT | FF |
|---|---:|---:|
| 共享 | 1275 | 495 |
| 拆成两个 | 1303 | 485 |

拆开多 28 个 LUT，共享是对的。

**给对齐移出位补粘滞位，修掉 3.7 节那 1 个 ULP。** 修法已挑了便宜的写法：对齐输入的低位恒零，
"移出去的位里有非零"等价于"尾随零个数小于被丢的位数"，一个 48 位尾随零计数器加一个比较器即可。
实验副本由 `syn/mk_exp2.py` 生成：

| 档 | LUT | FF |
|---|---:|---:|
| 现状 | 1275 | 495 |
| 补粘滞位 | 1469 | 500 |

多 194 个 LUT（+15.2%），恰好把 4.8 节三条回收省下的面积花光。而且它买到的不是正确性：
一个布尔粘滞位恢复不了被丢残差的符号，正负项抵消时可能把结果推向错误的方向。
真要那 1 个 ULP，正解是把尺子加长到覆盖整个指数范围，那是 3.3 节 555 位那个设计点。不采纳。

### 4.11 综合脚本的计数静默失效

第一现场。扫描窗口宽度的一批实验日志里，LUT 一栏全空；另一个单 lane 脚本报出 `DSP=0`，
一度被解读为离线综合时乘法器落在 LUT 上。

解读。两处都是计数口径静默失效，而不是电路的性质。

定位。第一处，抓结果的正则要求名字后面直接跟空白，而报告里那一行叫 `Slice LUTs*`，带一个星号，
匹配不上，那一行被静默跳过。第二处，脚本按 `PRIMITIVE_GROUP == DSP` 计数，这个组名不存在，计数恒为 0。

根因与修法。正则允许星号；单元计数改为直接数网表单元，DSP 与 BRAM 按 `REF_NAME` 计数。
修正后单 lane 的 DSP48 为 2，乘法器在离线综合里同样走 DSP。

原判据为什么没有覆盖到它：一个只会漏、不会报错的过滤器让人以为量过了。
新的离线综合脚本在需要 ROM 的顶层上找不到 RAMB 单元时直接报错，不让后续检查在空集合上通过。

81 到 96 位这一段是平的：15 位精度换约 11% 的 LUT，时序不动，级数恒为 17；
两个维度上 LUT 只由 `AccW` 决定，与这些位分给精度还是分给容量无关。
相邻两档的非单调说明扫描噪声约 ±5%。真正的代价在通向 555 位的路上：面积 7.1 倍，
级数从 17 涨到 49，20 ns 下的余量从 7.53 ns 降到 0.61 ns。精确累加的代价首先是频率，其次才是面积。
88 位取在平坦段上，取在这里的理由是 3.3 节的两条式子。

## 六、还欠什么

没有。窗口在 3.7 节构造下差 1 个 ULP 与抵消场景的损失是写进契约的性质，不作为待办。
