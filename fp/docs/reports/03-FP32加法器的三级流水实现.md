# FP32 加法器的三级流水实现

## 一、动机

乘法做完之后，下一个单元是加法与减法。

加法比乘法难，原因在下一节能直接推出来：乘法的三个字段各算各的，
加法的三个字段从一开始就纠缠在一起。

加法器还有一个比延迟更硬的约束：它会被放进反馈环。点积、残差累加这类负载把加法器的输出
接回自己的输入，环里若只能容纳一拍，加法器就不能切流水。这个约束曾经直接否决了切级，
经过在第四节 4.1。

## 二、为什么是这三步

### 加法的三个字段是纠缠的

两个数：

```text
   a = (-1)^sa x 1.ma x 2^(ea-127)
   b = (-1)^sb x 1.mb x 2^(eb-127)
```

加法要求两个数的小数点在同一个位置，而小数点的位置正是由阶码决定的：

```text
   ea = 5      1 . m m m m m m m .................
                 ^ 小数点在这里

   eb = 2                 1 . m m m m m m m .......
                            ^ 小数点在这里，差 3 位

   两排位对不齐，不能逐位相加
```

所以加法的第一件事不是相加，是把两个数改写成同一个指数。

### 改写只能往一个方向，生出第一步

要改写成同一指数，可以抬高小的那个，也可以压低大的那个：

```text
   抬高小的：  1.mb x 2^2   =   0.001mb x 2^5      尾数右移 3 位
   压低大的：  1.ma x 2^5   =   1000.ma x 2^2      尾数左移 3 位
```

压低大的会让尾数往高位长出去，而尾数字段宽度固定，左移出去的是最高有效位，丢了就是数量级错误。
抬高小的让尾数右移，移出去的是最低有效位，丢了只是精度损失。只能抬高小的，这一步是**对阶**。

它同时决定了对阶必然丢位，所以要给丢掉的部分留位置，这就是三个保护位的来历。

### 加减之后范围失控，生出第二步

对齐之后是一次定点加减，结果的范围与乘法不同：

```text
   同号相加   结果落在 [1, 4)    可能大于 2，要右移 1 位
   异号相减   结果落在 (0, 2)    可能远小于 1，要左移，而且左移多少位取决于抵消掉多少高位
```

要左移就得先知道移几位，也就是数出前面有多少个零。这一步是**规格化**，
它比乘法的规格化重得多：前导零计数是一个 26 路的优先级判断，是整个模块最长的组合路径。

### 位数装不下，生出第三步

与乘法一样，算完之后的位数多于格式能存的，要扔掉一部分。这一步是**舍入与组装**，做法与乘法相同。

### 三步的由来

```text
   拆包与对阶     两个数的小数点必须对齐，只能右移小的     <- 加法的定义
                  右移必然丢位，所以要留保护位

   加减与规格化   结果范围是 (0, 4)，两个方向都要修        <- 加减的值域
                  左移量是变量，要数前导零

   舍入与组装     位数装不下                             <- 与乘法同一个原因
```

三步各占一级流水。

## 三、每一步做了什么

### 3.1 拆包与对阶

拆包与乘法器相同，指数字段为 0 时按 DAZ 把尾数置零。对阶做两件事。

**先比大小，再固定位置。** 对阶要右移小的那个，所以先比较两个操作数的绝对值，
比出来之后把两路数据交换到固定位置：

```text
                a          b
                |          |
                +----+-----+
                     |
                  比绝对值
                     |
        +------------+------------+
        |                         |
       big                       sml
   （不动的那个）           （要右移的那个）

   从这里往下，数据通路里只有 big 和 sml
```

代价是几个多路选择器，换来后面没有分支。它还保证了两个隐含前提：阶码差恒为非负，
后面那个减法恒不借位。

**右移，并把移出去的位归约成一位。** 小尾数右移之前，先在它后面接三个空位 G、R、S。
右移之后，掉出去的位全部求或并进 S。阶码差大于等于 27 时，小的那个数整个落在窗口之外，
只要它非零就把 S 置 1。

三个保护位够用，分两种情况看：

```text
   阶码差大   右移很多位，丢掉很多信息
              此时大的数主导结果，小的只影响舍入，而舍入只需要"比半个 ULP 多还是少"

   阶码差小   只有 0 或 1，右移最多 1 位
              预留的三个位本来就是零，右移 1 位掉出去的还是零，一位真实数据都没丢
```

中间情况不存在：阶码差大于等于 2 时，小的数不到大的一半，相减之后至少剩下大的一半，
最多左移一位，不会发生大量抵消。

### 3.2 加减与规格化

加减用比尾数宽一位的宽度做，多出来的一位接进位。big 恒大于等于 sml，减法永远不借位。

规格化分三种情况：

```text
   情况 1    最高位进位，值 >= 2
             整体右移 1 位，阶码 +1，被挤掉的最低位并进新的最低位

   情况 2    正好规格化，不动

   情况 3    有前导零，值 < 1
             数出前导零个数，整体左移同样位数，阶码减去同样的数
```

阶码中间量用 10 位带符号，与乘法器同一个理由（[第 02 章](02-FP32乘法器的流水与舍入实现.md) 4.2 节）。

### 3.3 舍入与组装

舍入与乘法器相同，G、R、S 三位判进位，就近舍入到偶数。
组装时判定：最终阶码小于等于 0 写同符号零（FTZ），大于等于 255 写同符号无穷。

组装多了一条乘法器没有的规定：结果是零时符号取什么。零有两个来源，规则不同：

```text
   来源 A   尾数减出来正好是零（两个数精确相消）
            同号     (-0) + (-0)  ->  -0     保留符号
                     (+0) + (+0)  ->  +0
            异号      1.0 - 1.0   ->  +0     IEEE 754 规定就近舍入模式下恒为正零
                     (-0) + (+0)  ->  +0

   来源 B   尾数非零，但阶码太小被冲成零（FTZ）
            保留数学上的符号，很小的负数下溢得 -0
```

来源 A 的异号那一条是 IEEE 754-2008 第 6.3 节的明文规定：两个非零的数精确相消，
结果的符号在数学上没有定义，标准指定为正零。实现上：

```verilog
wire zero_sgn = s2_sign_big & s2_same_sign;
```

### 3.4 窄信号重建

级 1 到级 2 之间传递符号信息时，不寄存现成的结果位，而是寄存两个更窄的信号，
到级 2 再用一级逻辑算回来：

```verilog
s2_sign_big  <= s1_sign_sml ^ s1_sxor;
s2_same_sign <= ~(s1_sign_big ^ s1_sign_sml);
```

第一行在数学上等价于 `~s1_sxor`，但不能这样写。7 系列触发器的 D 端没有反相输入，
综合器遇到"寄存一个信号的反相"，会改用"寄存正相副本、输出端再取反"的实现，
级 1 到级 2 的路径退化为零逻辑直连，最短路径的延迟保护随之失效。
写成两个不同信号的异或，综合器必须用一个 LUT 实现它。
这一行在功能仿真里与简写版完全相同，只在网表上有区别，所以源码注释里写明不得化简。来历见 4.3 节。

### 3.5 为什么正好切三级

```text
   +----- 级 1 -----+  +------ 级 2 ------+  +---- 级 3 ----+
   | 比大小         |  | 定点加减         |  | GRS 判进位   |
   | 变长右移       |->| 26 路前导零判断  |->| 上下溢判断   |-> 输出寄存
   | 归约 S 位      |  | 变长左移         |  | 拼三段       |
   +----------------+  +------------------+  +--------------+
```

级 2 最长，决定这个模块的频率。再切细可以，但按第 01 章的准则，
多一级就是每次浮点加法多付一拍。

### 3.6 减法不单独做

`a - b = a + (-b)`，分发层把第二个操作数的符号位取反，再送进同一个加法器。
减法与加法共用对阶与规格化通路，省下一整套减法器。

## 四、遇到的问题

### 4.1 单周期版本被整个撤回

第一现场。最早的版本是单周期的，对阶、加减、规格化、舍入全在一段组合逻辑里。
功能正确，25 万条向量 0 ULP。综合报告：

```text
Path delay:      26.0 ns
Logic levels:    42
Requirement:     20.0 ns
Slack (setup):   -6.365 ns   VIOLATED
```

解读。`Requirement 20.0 ns` 是 50 MHz 的周期，`Path delay 26.0 ns` 是这条路径实际需要的时间，
两者之差就是负余量，要降到约 38 MHz 才能收敛。42 级逻辑远超一个 20 ns 周期通常能容纳的十几级。
结论是这段组合逻辑必须切开。

定位。诊断到这里是对的，但漏了一个更硬的约束：这个加法器当时位于乘累加单元的单周期反馈环里：

```text
   积 --> [ 加法器 ] --> acc
              ^           |
              +-----------+
              每拍读一次 acc

   加法器变成 3 拍，第 k 项读到的 acc 还没被第 k-1 项更新
```

也就是说，"切流水"这个选项当时不存在。

根因与修法。当时整个舍入改动被撤回，退回截断版。两个否决项性质不同："组合逻辑 26 ns"
可以靠切流水解决，"位于单周期反馈环里"不能，后者必须先改反馈环的结构。
反馈环的结构随后被改成能容纳多拍加法器（[第 07 章](07-FP32乘累加反馈环的启动间隔.md)），
三级流水的加法器才真正落地。

原判据为什么没有覆盖到它：功能判据与时序报告都各自正确，但单元级判据看不到调用方的反馈环。

### 4.2 零符号那几行，25 万条随机向量验不出来

第一现场。一次注错实验：把判断同号的信号取反，重跑回归：

```text
==== fp32_add vs IEEE golden ====
loaded/fed = 250000
total      = 250000
exact(0ULP)= 250000  (100%)
off 1 ULP  = 0
off >1 ULP = 0
max ULP    = 0
ALL PASS (250000/250000 逐位相同)
```

解读。故意注错，回归全绿。这条回归对那个信号的鉴别力为零。
原因是那个信号只在一种输入上有可观测效应：两个数异号且绝对值完全相等。
要命中它，需要两个随机的 32 位数除符号位外完全相同，25 万条随机值碰不到。

根因与修法。补三条定向用例，专门打在精确相消上：

```text
    1.0 - 1.0     期望 +0    异号相消得正零
   -0.0 - (+0.0)  期望 -0    实际是 (-0)+(-0)，同号保留符号
   -0.0 - (-0.0)  期望 +0    实际是 (-0)+(+0)，混合情况得正零
```

三条覆盖了那个判断的两个输入组合。后来 3.4 节的窄信号重建做完，同样的注错实验又做了一次：
把重建出来的信号取反，25 万条随机向量仍然全绿，只有这三条定向用例报错。
这三行是整条线上对零符号逻辑鉴别力最强的判据。

原判据为什么没有覆盖到它：判据的覆盖范围要与它声称验证的东西对上。
"25 万条随机向量全过"读起来像是覆盖得很好，但它对精确相消这条路径的覆盖是零。

### 4.3 新增一个寄存器，hold 余量掉到 10 皮秒

第一现场。为修正无穷的符号，在级 2 加了一个选择寄存器。在一个例化 32 份本单元的集成设计中，
实现后的最差 hold 路径终点正是它：

```text
<阵列中的一条 lane>/u_add/s2_spec_sel_reg
WHS = 0.010 ns
```

改动前这个余量是 0.050 ns。

解读。hold 检查的是"同一个时钟沿发出的新数据会不会太早到达下一级"，式子里没有周期：

```text
   hold 余量 = 发射延迟 + 组合逻辑最短路径 - 保持时间 - 偏斜
```

降频对它无效。余量为负时综合与实现照常完成，程序照常运行，症状是输出错误的数，
而不是崩溃。新加的寄存器与上一级之间是零逻辑裸传，最短路径接近纯连线；
32 份副本让布局器把某一份放到不利位置的概率随之增加。

定位。式子里能动的只有两项：往最短路径上加延迟，或者调整时钟相位。
后者会触发全局重新布局，代价大，先试前者。
检查级 1 到级 2 之间的信号，有几条是零逻辑裸传。

根因与修法。把要传的值在级 1 拆成两个更窄的信号寄存，到级 2 用一个异或算回来，即 3.4 节的形态，
使每条级 1 到级 2 的路径至少穿过一级逻辑。

修完之后要证明两件事。一是重建没有被综合器化简掉：

| | 修之前 | 修之后 |
|---|---:|---:|
| WHS | 0.010 ns | 0.028 ns |
| 本单元所在时钟域的最差 hold 路径 | 零逻辑裸传 | 级 2 内的 CARRY4 进位链，1 级逻辑 |

余量数值会随布局波动，不足以证明修法生效；第二行的路径形态才是证据。
如果综合器把重建式化简回裸传，那条路径应该仍是 0 级。

二是数值等价：由 4.2 节那三条定向用例承担。

原判据为什么没有覆盖到它：hold 余量只出现在实现后的时序报告里，功能仿真看不到走线延迟。

### 4.4 余量随布局来回跳动

第一现场。之后几轮改动的实现结果：

| 这一轮改了什么 | 最差 hold 路径所在位置 | 余量 |
|---|---|---:|
| 加乘单元的 FTZ | 阵列中的加法器 | 0.010 ns |
| 窄信号重建 | 集成设计中的另一个模块 | 0.028 ns |
| 删除乘法器左移分支，LUT 减少约一成 | 阵列中的乘法器 | 0.017 ns |
| 再下一轮，两个模块都没有改动 | 集成设计中的另一个模块 | 0.011 ns |

解读。第三行删掉了近一成的逻辑，预期布局更松、余量回升，实际两个余量都下降了，
临界点回到被删逻辑所在的模块。第四轮两个模块一行没改，临界点照样换了位置。
这是满布局设计在布局器手里的固有抖动：大幅改变网表会触发重新布局，余量重新分配，
方向不确定。"删逻辑等于给余量"这个直觉不成立。

根因与修法。原先给新单元定过一条准入门槛：hold 余量回到 35 皮秒以上才允许继续加单元。
四轮实测最高 28 皮秒，并且每次都被下一次布局改写，这条门槛无法满足。
门槛改为两条：全项时序满足，并且最差路径不落在零逻辑裸传上。
后一条检查的是路径形态，不随布局波动。

原判据为什么没有覆盖到它：原门槛检查的是一个随布局波动的数值，它既不能证明改动有效，
也不能证明改动无害。
