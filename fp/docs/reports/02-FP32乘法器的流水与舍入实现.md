# FP32 乘法器的流水与舍入实现

## 一、动机

[第 01 章](01-标量浮点单元的接口与契约.md)定下了单元接口、分发层、延迟常数与数值契约。
这一章往骨架上挂第一个计算单元。

第一个选乘法，理由有两条。一是在浮点密集的负载里，乘法通常是调用次数与单价乘积最大的一项。
二是它最容易：乘法的三个字段几乎各算各的，相互干扰只有两处，理由在下一节展开。
先做它，可以用最少的工作量把"单元接口、延迟常数、金标准对拍、回归入口"整条链路验证一遍。

延迟预算按第 01 章那条准则来定：这个单元的延迟就是一次乘法的价格。
50 MHz 对应 20 ns 周期，24 × 24 位的尾数乘法本身占掉大半个周期，至少要独占一级。
目标定为两级。

## 二、为什么是这五步

### 从表示法推出来

FP32 存三个字段，值为 `(-1)^s × 1.m × 2^(e-127)`。两个这样的数相乘，把定义直接乘开：

```text
    (-1)^sa x 1.ma x 2^(ea-127)
  x (-1)^sb x 1.mb x 2^(eb-127)
  ---------------------------------------------
  = (-1)^(sa^sb) x (1.ma x 1.mb) x 2^(ea+eb-254)
        |               |                |
     只跟符号有关     只跟尾数有关       只跟阶码有关
```

三个字段各自独立。如果到此为止，乘法只需要一步：三条线并排算完，拼回去。

### 两处干扰，生出两步

问题是算完之后，有两条线的结果超出了各自字段能装的范围。

**干扰一：尾数积的范围超了。** 两个尾数都在 `[1, 2)`，积落在 `[1, 4)`。
而格式要求尾数落在 `[1, 2)`，隐藏位固定在同一个位置。积一旦大于等于 2，隐藏位就高了一位：

```text
   尾数积的两种形态（48 位）

   bit  47 46                                              0
       +--+-----------------------------------------------+
   1   | 0| 1 . x x x x x x x x x x x x x x x x x x x x x |   积在 [1,2)
       +--+-----------------------------------------------+
            ^ 隐藏位在 bit46，位置正确

       +--------------------------------------------------+
   2   | 1 . x x x x x x x x x x x x x x x x x x x x x x x|   积在 [2,4)
       +--------------------------------------------------+
         ^ 隐藏位跑到了 bit47，多占一位
```

形态 2 要把整个积右移一位，右移一位等于除以 2，阶码补 +1。这一步是**规格化**，
它处理尾数那条线溢出到阶码那条线上的那一位。

**干扰二：尾数积的位数超了。** 24 位乘 24 位得 48 位，而格式只存 23 位小数，
算出来的一半装不下。扔掉的部分不是零，怎么扔决定结果偏向哪一侧。
这一步是**舍入**，它处理位宽装不下的部分。

### 再加一步：特殊值不走这条通路

上面的推导默认两个操作数都是常规数。NaN、±Inf、±0 的阶码字段被征用，
`1.m` 这个解释不成立，`Inf × 0` 甚至没有数值答案。所以要在最前面把它们筛出来，
走一条独立的短路径。这一步是**特殊值判断**。

### 五步的由来

```text
   拆包            切出三个字段，补回隐藏位          <- 表示法要求
   特殊值判断      把不适用 1.m 解释的输入分流       <- IEEE 特殊值
   主运算          符号异或、阶码相加、尾数相乘      <- 定义乘开的结果
   规格化          修正尾数溢出到阶码的那一位        <- 干扰一
   舍入与组装      处理装不下的位，拼回三个字段      <- 干扰二
```

前三步是照定义翻译，最后两步是全部工作量所在。

## 三、每一步做了什么

### 3.1 拆包

```text
   输入 a   +-+--------+-----------------------+
            |s|  e (8) |        f (23)         |
            +-+--------+-----------------------+
                            |
                            v  在小数部分前面接一个 1
            +-+--------+-+-----------------------+
            |s|  e (8) |1|        f (23)         |
            +-+--------+-+-----------------------+
                        |------ 24 位尾数 -------|
```

补回来的 1 是隐藏位。按 DAZ 规则，指数字段为 0 时尾数整个置零，
零与 denormal 在这一步变成同一种输入。这一步属于常规实现。

### 3.2 特殊值判断

按阶码字段分流：

```text
   e = 0            ->  正负零（DAZ 下包括 denormal）
   e = 1 .. 254     ->  常规数，走主通路
   e = 255, f = 0   ->  正负无穷
   e = 255, f != 0  ->  NaN
```

另加一条组合判断：一边是无穷、另一边是零，结果是 NaN。
DAZ 把 denormal 当成零之后，`Inf × denormal` 同样落进这一条。

判断的结果不在这一级产生 32 位的特殊值，只产生五个一位标志：
是否 NaN、是否 Inf、是否零、是否走特殊通路、特殊结果的符号。
它们随流水走到第 2 级，再由优先级选择重建出 32 位结果。两条通路在硬件里始终并行计算，
选择器放在数据通路末端。只寄存窄标志而不寄存 32 位结果的理由见 4.6 节。

### 3.3 主运算

```text
   符号   sa --+
               (异或) ------------------------------> 结果符号
          sb --+

   阶码   ea --+
               (加) --- 减 127 ---------------+
          eb --+                              v
                                          到规格化
   尾数   1.ma --+                            ^
                 (乘) --- 48 位积 ------------+
          1.mb --+
```

阶码中间量用 10 位带符号数，范围为 `[-512, 511]`，理由见 4.2 节。
24 × 24 位的尾数乘法综合映射为 DSP48，是本单元最长的一条组合路径。

### 3.4 规格化

看积的最高位：

```text
   bit47 = 1   整体右移一位，阶码 +1
               右移时把原积最低位并进新的最低位（理由见 4.3 节）

   bit47 = 0   不动，阶码不变
```

只有这两种情况。DAZ 保证进入主通路的两个操作数都是规格化数，积不可能小于 1，
乘法器永远不需要左移。

### 3.5 舍入

扔掉的那部分携带的信息，只有一件事对结果有影响：它代表的值比"最后一位的一半"大还是小。
所以不必保留全部低位，三个位就能回答：

```text
   bit  46           24  23 | 22   21 .............. 0
       +---------------+---+-----+--------------------+
       |  保留的高位     |LSB| G   |   其余位全部求或 S   |
       +---------------+---+-----+--------------------+
```

判断规则为就近舍入到偶数：

```text
   G = 0                 扔掉的部分小于半个 ULP     -> 不进位
   G = 1，S = 1          扔掉的部分大于半个 ULP     -> 进位
   G = 1，S = 0          正好半个 ULP（平局）       -> LSB 为 1 进位，为 0 不进位
```

写成一行：`round_up = guard_bit & (sticky_bit | mant_lsb)`。

进位本身可能再溢出一次，`1.111...1 + 1 = 10.000...0`，此时尾数归零、阶码再加一，
舍入器比尾数宽一位来接这个进位。

### 3.6 组装与切级

```text
   最终阶码 <= 0     ->  下溢，输出同符号零（FTZ）
   最终阶码 >= 255   ->  上溢，输出同符号无穷
   否则              ->  拼回符号、阶码、尾数
```

两级流水划分：

```text
   +------ 级 1 ------+   +------ 级 2 ------+
   | 拆包、DAZ        |   | 规格化           |
   | 特殊值标志       |-->| 舍入             |--> 结果
   | 尾数乘（最长）   |   | 组装、特殊值重建 |
   | 阶码加           |   |                  |
   +------------------+   +------------------+
```

两级分别是 `fp32_mul_s1` 与 `fp32_mul_s2` 两个模块，`fp32_mul_pipe` 把它们串起来。
级 1 输出未规格化、未舍入的 48 位积与 10 位阶码，乘累加单元直接取这一级的输出，
不经过级 2 的舍入，见第 08 章。

## 四、遇到的问题

### 4.1 截断的误差是单向的

第一现场。第一版的舍入是截断，20 万条随机规格化向量对金标准：

```text
==== fp32_mul vs IEEE golden ====
total      = 200000
exact(0ULP)= 98421  (49%)
off 1 ULP  = 101579
off >1 ULP = 0
DUT<golden = 101579  (偏低占比 50%)
max ULP    = 1
```

`DUT<golden` 一行是后来为了看偏差方向加进测试台的，上面的条数按当时记录的百分比反推，
量级与结论不受影响。

解读。`off >1 ULP = 0` 与 `max ULP = 1`：所有偏差都不超过一个 ULP，
按当时的判据"最大误差不超过 1 ULP"应该判为通过。
关键在最后那个计数：`DUT<golden` 与 `off 1 ULP` 完全相等，所有偏差都落在同一侧。

```text
   舍入噪声                         实测

   偏低  |  偏高                    偏低   |  偏高
    50k  |  50k                    101579 |   0
   ------+------                   -------+------
      对称，累加相消                  单向，累加不相消
```

根因。截断永远朝零取整，绝对值总是变小。单向偏差在累加里随项数线性增长，
对称误差随项数的平方根增长。对逐步递推的模型推理，差别体现在结果质量上。

修法。截断换成 3.5 节的就近舍入到偶数。

原判据为什么没有覆盖到它：判据是幅值上界，对偏差方向不敏感，截断版满足它。
被测的性质落在指标的定义域之外；补一个按方向分开统计的计数器，问题当场可见。

### 4.2 阶码中间量回绕，上溢变成下溢

第一现场。定向用例 `max_float × 2`，期望正无穷：

```text
  FAIL: max*2 -> Inf   got=00000000 exp=7f800000
```

解读。`7f800000` 是正无穷，`00000000` 是正零，两者是浮点数轴上距离最远的两个点。
算错通常得到量级接近、尾数不对的数；得到另一个极端，说明走进了另一条判断分支：
上溢输入走进了下溢出口。

定位。顺着阶码那条线算数值范围：两个阶码各在 `[1, 254]`，相加后减 127，
中间量的真实范围是 `[-125, 381]`。而当时这个中间量存在 8 位无符号数里，只能装 `[0, 255]`：

```text
   真实值   ...  254   255   256   257  ...
   8 位存   ...  254   255    0     1   ...
                              ^
                        这里绕回去了
```

`max_float × 2` 的阶码算出来是 256，存进去变成 0，命中"阶码等于 0"的下溢判据，输出正零。

根因与修法。中间量改为 10 位带符号，上溢与下溢的判断推到最后一级再做。

这次判据覆盖到了。随机向量的指数取在中间地带，碰不到边界；覆盖到它的是定向段的极值用例。
随机段与定向段各管一件事。

### 4.3 右移规格化把原积最低位丢了

第一现场。这一条不是仿真报出来的：20 万条随机向量修复前后都是全绿。
它是逐行读规格化与舍入那一段时发现的，然后按位型反推构造出一对操作数：

```text
   a = 0x3F800C3D
   b = 0x3FFFEB15

   得到     0x400001C6
   正确     0x400001C7
   差       1 ULP
```

解读。两个输入都是普通的正有限数，走最主干的通路。差 1 ULP 意味着舍入方向判错了一次。
把尾数乘出来看：

```text
   24 位尾数   0x800C3D * 0xFFEB15
   完整乘积    0x8001C6800001
   低 25 位    0x00800001
                 bit23 = 1 (Guard)   bit22..1 全 0   bit0 = 1
```

Guard 为 1，Guard 以下只有最低位为 1，被丢弃的部分严格大于半个 ULP，应当进位，而代码没进。

定位。舍入本身没问题，问题在上一步。乘积最高位为 1 时右移一位规格化，
48 位右移一位，最低位就掉出容器了。之后粘滞位只覆盖原积的 `[22:1]`，原积的 bit0 不在其中。
不右移的分支位窗完整，所以缺陷只在右移分支，并且要同时满足 Guard=1、右移后其余位为 0、
保留位最低位为 0、原积 bit0 为 1，位型非常稀疏。

根因与修法。规格化右移与粘滞位汇总被写成了两个独立步骤，右移先丢了一位信息。
修法是右移的同时把它并回去：

```verilog
prod_n[0] = product_r[1] | product_r[0];
```

原判据为什么没有覆盖到它：判据是 20 万条随机向量对金标准，随机采样命中不了这个位型。
判据本身没有错，错在把"样本内 0 ULP"当成了"全输入空间 0 ULP"。
补的是 `tb_fp32_mul_r.v` 里的定向用例；把修复注释掉重跑，随机部分仍然全绿，只有定向用例变红。

### 4.4 DAZ 之后左移分支成了死代码

第一现场。乘法器最初按 IEEE 处理 denormal 输入：尾数没有前导 1，积可能小于 1，
规格化需要左移若干位，由一个独立的 48 位、6 路移位选择器承担。

解读。第 01 章 4.3 节把 DAZ 与 FTZ 定为契约之后，进入主通路的操作数必然是规格化数：

```text
   积的范围        需要的规格化动作
   [1, 2)          不动
   [2, 4)          右移 1 位
   (0, 1)          左移若干位   <-- DAZ 之后不可能发生
```

那个左移模块永远走不到。

根因与修法。删除左移模块。同时修改衍生的特殊值规则：DAZ 把 denormal 当成零，
`Inf × denormal` 必须与 `Inf × 0` 一样输出 NaN，否则同一个操作数在乘法器的两个判断点上
一边算零、一边不算零。`tb_fp_ftz.v` 与 `tb_fp32_denorm.v` 覆盖这两条规则，
后者的 173 条乘法定向用例全部通过。

原判据为什么没有覆盖到它：死代码不会让任何判据报错。它是在按契约推导"哪些分支还可达"时发现的。

### 4.5 "冲零"没有唯一规定下溢判定的时点

第一现场。一份独立审计报来一个反例：`0x00800000 × 0x3F7FFFFF`，
精确积是 `2^-126 − 2^-150`，恰好在最小规格化数下面一点点。硬件输出 `+0`，审计认为应输出 `0x00800000`。

解读。双方对数值事实没有分歧，分歧在"冲零"的定义。IEEE 754 允许两种下溢判定时点，
而审计采用的是第三种：

| 定义 | 做法 | 本例结果 |
|---|---|---|
| 舍入后判定 | 在无界指数下舍入到 24 位有效位，再判是否小于最小规格化数 | 该值正好是 24 位精确值，无需舍入，判为下溢，输出 `+0` |
| 舍入前判定 | 直接看无限精度中间值 | 判为下溢，输出 `+0` |
| 舍入到含 denormal 的格点再冲零 | 在 `2^-149` 间隔上舍入，中点取偶后不再是 denormal | `0x00800000` |

定位。硬件精确实现的是第一种：尾数在 24 位格点上舍入，阶码是 10 位带符号的无界值，
然后判 `exp <= 0` 冲零。这与 x86 的做法一致，第二种是 ARM 的做法，两者在这个例子上都输出 `+0`。
第三种要按阶码做可变位置的舍入，那正是 FTZ 要省掉的整条通路。

根因与修法。实现无缺陷，契约有缺口：说明书从来没有写取哪一种时点。
补上"下溢在舍入之后判定"这一条，这个例子从此可以由使用者自己推理出来。不改 RTL。

原判据为什么没有覆盖到它：契约里没有这一条，判据自然也无从检查。
一条说不清楚的规则本身就是缺陷，哪怕每一次计算都是对的。

### 4.6 特殊值寄存 32 位，最短路径几乎为零

第一现场。乘法器最初在级 1 把 32 位特殊值结果算好寄存下来，级 2 只过一级选择器输出。
在一个多份例化本单元的集成设计中，最差 hold 路径多次落在这一段附近，余量只有几十皮秒。

解读。hold 检查的是同一个时钟沿发出的新数据会不会太早冲到下一级。
32 位特殊值从级 1 寄存器出发，只经一级选择器就到达输出寄存器，最短路径接近纯连线。
多份例化之后，布局器把其中某一份放到不利位置的概率随之增加。

根因与修法。级 1 只寄存五个一位标志，级 2 用三级优先级选择重建 32 位特殊值，即 3.2 节的形态。
级 1 到级 2 的路径至少穿过一级逻辑，最短延迟随之增大；每份例化还少寄存约 29 个触发器。
功能逐位不变，20 万条随机向量与定向用例的结果与改动前相同。

原判据为什么没有覆盖到它：hold 余量只出现在实现后的时序报告里，功能仿真看不到走线延迟。

### 4.7 一条被推翻的诊断：重新切级解决不了 hold

第一现场。在同一个集成设计里，最差 hold 路径后来落在乘法器内部：

```text
源    <某条 lane>/u_mul/product_r_reg[28]/C
终    <某条 lane>/u_mul/p_reg[5]/D
逻辑  2 级（LUT3 规格化选择 + CARRY4 舍入进位）
数据  0.388 ns
偏斜  0.266 ns
```

当时的判断是"级深不均衡"：级 1 里有 24 × 24 乘法器很深，级 2 只有规格化与舍入很浅，
应该重新切一下级。

解读。最后两行是关键。这条路径的数据延迟 0.388 ns，其中 0.266 ns 被时钟偏斜吃掉，
目的端的时钟比源端晚到。偏斜来自多份例化与满布局，与逻辑写法无关。
逻辑 2 级已经是这个功能的最小深度。

定位。重新切级改变的是路径的平均长度与最长长度，影响的是 setup；
hold 看的是最短路径。把级 1 的工作挪到级 2，低位那条"积的某一位经选择器与进位到结果某一位"
的路径仍然是 2 级，一点不变。

根因与修法。重排级深不解决 hold。可用的手段只有两类：在最短路径上插入延迟，或者调整时钟相位。
两者都会触发全局重新布局，而大改网表可能更差（第 03 章 4.4 节），这一条没有改动。

原判据为什么没有覆盖到它：这是一次诊断失误，按"级深不均衡"修下去不会让任何判据变红，
只是修不好。避免它的办法是先查报告里的偏斜与逻辑级数，再决定修法。

## 五、结果

| 判据 | 结果 |
|---|---|
| `tb_fp32_mul.v` | 20 万条随机向量，0 ULP，100% |
| `tb_fp32_mul_r.v` | 右移分支粘滞位定向用例 9 组，0 FAIL |
| `tb_fp_ftz.v` | FTZ 定向用例与加乘各 20 万随机向量，25 条判定全部通过 |
