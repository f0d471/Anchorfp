# FP32 倒数的查表与牛顿迭代实现

## 一、动机

### 剩下的最贵一项

加、减、乘、比较与转换都有了硬件单元之后，软件浮点里剩下的算术原语只有除法。
在无浮点单元的 32 位软核上，一次 FP32 除法约 260 个周期，是所有原语里最贵的。

### 为什么不替换除号

IEEE 754 把运算分成两类：

```text
   必须正确舍入                        不要求
   +  -  x  /  sqrt  fma               exp  log  sin  cos  pow
   整数与浮点的转换、比较               标准只在推荐章节给建议

   正确舍入：结果必须等于无限精度算完再舍入一次，一位不差
```

除法在第一类里。用近似倒数替换除号，等于把除法从 0 ULP 变成近似，
已经编译好的程序会悄悄改变结果。

业界处理同一件事的方式是把近似倒数做成一条独立的显式指令：x86 的 `RCPSS`、
ARM 的 `VRECPE`、RISC-V 向量扩展的 `vfrec7`。编译器默认不拿它们替换除号，
只有显式允许放宽数学语义时才会用。

所以这一章的目标是两条：提供一个显式的近似倒数单元，由调用方自行决定在哪里使用、
承担多少误差；不替换除法，除号保持正确舍入。

### 延迟预算

这个单元比前面几个都深：查表要一拍存储器读延迟，牛顿迭代要两个定点乘法，各占一级。
最后落在 5 级，是这条通路上延迟最长的单元。

## 二、为什么是这五步

### 除法为什么在硬件上贵

加减乘都能一遍并行算完。除法不行，商的每一位都依赖前一位算出的余数：

```text
   商的第 1 位  <- 由被除数决定
   商的第 2 位  <- 由第 1 位算完的余数决定
   商的第 3 位  <- 由第 2 位算完的余数决定
   ...
   24 位商 = 24 步串行
```

### 第一次绕开：把除法换成乘法

`a / b = a × (1/b)`。问题变成求 `1/b`，然后做一次乘法。
但 `1/b` 本身还是除法，只是被除数固定为 1，只剩一个操作数。

### 第二次绕开：不去算倒数，改成猜了再验

判断一个数 `r` 是不是 `1/m`，只要算 `m × r` 看是否等于 1，一次乘法，没有除法。
求倒数要除法，检验倒数只要乘法。检验便宜，就可以把"算"换成"猜一个、验一下、不对就改"。
剩下两个问题：按什么规则改，以及从哪儿开始猜。

### 改的规则：牛顿法

把 `m × r = 1` 写成求根问题 `f(r) = 0`，牛顿法的迭代是
`r(n+1) = r(n) - f(r(n)) / f'(r(n))`。关键在于 `f` 不止一种写法，选哪种决定迭代式里有没有除法：

```text
   写法一   f(r) = m*r - 1        f'(r) = m
            r(n+1) = r(n) - (m*r(n) - 1) / m          要除以 m，回到除法

   写法二   f(r) = 1/r - m        f'(r) = -1/r^2
            r(n+1) = r(n) - (1/r(n) - m) / (-1/r(n)^2)
                   = r(n) * (2 - m*r(n))              只有乘法和减法
```

`1/r` 在求导之后与分母上的 `1/r^2` 约掉，这是写法二能用的原因。迭代式为：

```text
   r1 = r0 x (2 - m x r0)
```

### 一轮就够：误差每轮平方

定义相对误差 `e = 1 - m*r`。令 `m*r0 = 1 - e0`，代入：

```text
   m*r1 = (1 - e0) * (2 - (1 - e0)) = (1 - e0) * (1 + e0) = 1 - e0^2
   => e1 = e0^2
```

这一行给出两个结论。其一，误差每轮平方：`e0 = 2^-11` 时 `e1 = 2^-22`，
FP32 尾数 23 位，一轮就够。其二，`e1 = e0^2` 恒大于等于零，所以 `r1` 恒小于等于 `1/m`，
迭代永远从下方逼近真值，除非 `e0` 本来就是零。第二个结论后面会逼出第四步。

### 从哪儿开始猜：查表

要 `e1 <= 2^-22`，就要 `e0 <= 2^-11`。靠公式凑一个这么准的初值不现实，办法是查表：
把输入区间切成若干段，每段的初值预先算好。一张 1024 项的表正好能给到 `2^-11`，账在 3.2 节。

### 指数不参与逼近

```text
   a = 正负 2^(e-127) x m,     m 属于 [1, 2)
   1/a = 正负 2^(126-e) x (2/m)
```

指数部分是一个减法，只有尾数需要逼近，表也只需要覆盖 `[1, 2)` 这个固定区间。

### 五步的由来

```text
   一  拆掉指数      1/a 化成阶码取反与尾数求倒数       <- 指数可以直接算
   二  查表          给 1/m 一个 2^-11 的初值           <- 逼近要初值
   三  牛顿迭代      一轮把误差平方到 2^-22             <- 逼近要迭代
   四  特判 2 的幂   迭代从下方逼近，到不了精确值       <- e1 = e0^2 >= 0
   五  规格化组装    定点结果转回 FP32                  <- 内部定点，接口浮点
```

## 三、每一步做了什么

### 3.1 拆掉指数

```text
   输入 a   +-+--------+-----------------------+
            |s|   e    |          f            |
            +-+--------+-----------------------+
             |    |                 |
             |    |                 +--> m = 1.f，送去求倒数
             |    +--> 253 - e，一个减法就是结果的阶码
             +--> 符号原样带过去
```

253 的来历：`1/m` 落在 `(0.5, 1]`，不是合法的规格化尾数，
把 2 挪一下得 `1/a = 2^(126-e) × (2/m)`，`2/m` 属于 `[1, 2)`；
结果的偏置阶码为 `(126 - e) + 127 = 253 - e`。逼近算出的是 `1/m`，结果尾数是 `2/m`，
两者只差一位移位，在第五步兑现。

### 3.2 查表

把 `[1, 2)` 按尾数高 10 位切成 1024 段，第 i 段覆盖 `[1 + i/1024, 1 + (i+1)/1024)`，
每段存一个倒数初值。表地址就是尾数的高 10 位，一段裸切片，不经过任何逻辑。

表由生成器 `gen_recip_lut.c` 用 binary64 计算后写成 `recip_lut.mem`，综合时由 `$readmemh` 读成 ROM 初值：

```text
   m_mid = 1 + (i + 0.5) / 1024          区间中点
   r0    = round( 1/m_mid * 2^17 )       Q0.17 定点

   i=0     m_mid=1.000488281   1/m_mid=0.999511957   ->  0x1ffc0
   i=512   m_mid=1.500488281   1/m_mid=0.666449723   ->  0x15539
   i=1023  m_mid=1.999511719   1/m_mid=0.500122100   ->  0x10010
```

这里用了一个特定手段：**表里存区间中点的倒数，不存左端点的**。

```text
   存左端点                              存中点

   m_left           m_right              m_left      m_mid     m_right
     |-----------------|                   |-----------|-----------|
     ^ 表项对准这里                                    ^ 表项对准这里
     最远差一整段 2^-10                          最远差半段 2^-11
```

`e0 = 1 - m/m0 = (m0 - m)/m0`。左端点下 `|e0| < 2^-10`，中点下 `|e0| <= 2^-11`，
逐段扫描两个上界都精确取到。再套 `e1 = e0^2`：

```text
                初值误差 e0     牛顿一轮后 e1      换算成 ULP
   左端点        2^-10          2^-20             8 到 16
   中点          2^-11          2^-22             2 到 4
```

结果尾数落在 `[1, 2)`，1 个 ULP 的相对大小在 `2^-24` 到 `2^-23` 之间，
同一个相对误差换算成 ULP 有一倍的区间。改一次表白得一位初值精度，牛顿把它放大成两位结果精度，
代价只是重新运行一次生成器；多加一轮牛顿则要多两个乘法器，其中一个是 42 位的。

`r0` 落在 `(0.5, 1]`，18 位无符号定点刚好装下，`1.0` 对应 `0x20000`。
量化误差 `2^-18` 远小于区间误差 `2^-11`，不占精度预算。

回归入口在每次运行时重新编译生成器，要求输出与 `recip_lut.mem` 逐字节相同。

### 3.3 牛顿迭代在定点上怎么算

记号 `Qa.b` 表示整数 a 位、小数 b 位。一轮迭代拆成两个乘法，各占一级：

```text
   m     24 位   小数点在第 23 位   值属于 [1, 2)
   r0    18 位   小数点在第 17 位   值属于 (0.5, 1]

   t  = m x r0        24 x 18 -> 42 位，小数点在第 40 位，值 = 1 - e0
   d  = 2 - t         42 位，常数 2 在这个格式下是 0x200_0000_0000
   r1 = r0 x d        18 x 42 -> 60 位，小数点在第 57 位，值为 1/m 的估计
```

小数点位置相加：`23 + 17 = 40`，`17 + 40 = 57`，位宽由此确定。

### 3.4 特判 2 的幂

迭代永远从下方逼近，取不到等号。对大多数输入，差的那一点在容差里；
但 2 的整数次幂的倒数是精确可表示的，调用方期望它们精确：

```text
   1/2.0    真值 0.25       若不特判得到 0.24999998
   1/4.0    真值 0.125      若不特判得到 0.12499999
```

判据：尾数小数部分全为零，即 `m` 恰好等于 1.0，一个 23 位或非门。
此时 `2/m = 2.0`，正好是"尾数进位到 2.0"这一种情况，而这条通路第五步本来就有，
所以特判不另建支路，把进位信号强制置 1 即可。x86 的 `RCPSS` 一类指令同样保证这类输入精确。

### 3.5 规格化与组装

`r1` 是 60 位定点数，值为 `1/m`；结果尾数是 `2/m`，把小数点右移一位来读：

```text
   bit  59 58 57 56 55 ................ 33 32 31 ................ 0
         0  0  ?  1  <----- 23 位 ----->  G  <------ 32 位 ------->
               ^  ^                       ^         ^
               |  |                       |         +-- 全部求或 = sticky
               |  |                       +------------ guard
               |  +--- 结果尾数的隐藏位
               +------ 只有 r1 恰好等于 1 时才是 1
```

取位窗读出尾数、guard 与 sticky，就近舍入到偶数，与前几章的乘法器、加法器相同，属于常规做法。
取 25 位而不是 24 位，多的一位接进位：进位到 2.0 时小数清零、阶码加一，3.4 节的特判就走这一行。

阶码封顶：`exp = (253 - e) + 进位`，`exp <= 0` 按 FTZ 输出同符号零，`exp >= 255` 输出同符号无穷。

特殊值按固定优先级覆盖常规通路：NaN 原值透传；正负 Inf 输出同符号零；
正负 0 输出同符号 Inf；denormal 按 DAZ 当作零，同样输出同符号 Inf。

### 3.6 流水划分

```text
   级 1   拆包、分类；同一拍表读在途
   级 2   收表项
   级 3   第一个乘法    m x r0
   级 4   第二个乘法    r0 x (2 - t)
   级 5   规格化、舍入、组装
```

表地址是输入尾数的一段裸切片，直接接到存储器地址口，存储器在时钟沿锁存它。
级 1 寄存尾数与旗标的同时，表读已经在途，级 2 直接收表，这一拍读延迟不需要单独一级去消化。

## 四、遇到的问题

### 4.1 定向用例挑的全是自己能过的点

第一现场。补牛顿迭代之前的版本只查表、不迭代，测试台输出：

```text
-- special (bit-exact) --
  PASS: 1/+0 -> +Inf
  PASS: 1/-0 -> -Inf
  ...
-- powers of two (bit-exact) --
  PASS: 1/1.0 = 1.0
  PASS: 1/2.0 = 0.5
  PASS: 1/4.0 = 0.25
  ...（18 条定向全 PASS）
  random golden: loaded=20021 compared=20021 over-tol=19770 max_ulp=16011
  FAIL: 19770/20021 超容差
```

解读。定向段 18 条全过，随机段 98.7% 超容差。实现若正确，两段应当同时通过；
若错误，两段应当同时暴露。只有定向通过、随机不通过，说明定向段选的点有系统性。

`max_ulp=16011` 给出了错误的量级。当时的表存左端点，只查表的相对误差是 `2^-10`，
按 3.2 节的换算对应 8192 到 16384 个 ULP，实测 16011 正落在上端。差的是整整一轮迭代。

定位。那 18 条用的是 1.0、2.0、3.0、4.0、0.5、最小规格化数，这些数的尾数低 13 位全是 0，
而表地址取尾数高 10 位，这些数正好落在表的格点上，查表结果就是精确值，
迭代做不做都一样。定向段的鉴别力是零。

根因与修法。补上牛顿迭代与中点表；定向段补三条落在格点之间的用例：
`1/1.7`、`1/π`、`1/√2`，使定向段能独立暴露"缺少迭代"。

原判据为什么没有覆盖到它：定向用例挑了好记的整数值，而好记的数往往也是特殊的数。
定向用例里必须至少有一个"实现若偷懒就会出错"的点。

### 4.2 修了两个真缺陷，一个数都没变

第一现场。同一轮还查出两处结构错误：

```text
   错误一   表是同步读，而第一版在下一拍就去收数据，早采了一拍
   错误二   valid 链是 5 级而数据链是 4 级，错位一拍
```

两处都改对之后重跑随机对拍：

```text
  random golden: loaded=20021 compared=20021 over-tol=19770 max_ulp=16011
  FAIL: 19770/20021 超容差
```

与改之前逐字相同。

解读。改对了两处真错误而指标零变化，说明这两处错误在当前激励下没有任何可观测效应。

定位。测试台的激励把输入一直保持不变：同一个值一直挂着，每拍重载同一个地址，
每拍读出同一个表项。早采一拍读到的"上一笔表项"与这一笔相同，错位一拍读到的还是同一笔数据，
流水自己就对上了。

根因与修法。两处错误本身已经修正。测试台改为逐条发起、不保持输入，
这类与时序相关的缺陷才有机会暴露。

原判据为什么没有覆盖到它：保持型激励掩盖了与时序相关的缺陷。

### 4.3 表文件放错目录，综合出一块空表

第一现场。某次集成构建的综合日志里有一行：

```text
CRITICAL WARNING: [Synth 8-4445] cannot open file recip_lut.mem
```

构建照常完成，时序照常满足，而倒数运算在硬件上返回无意义的结果。

解读。这条警告的级别是 CRITICAL，但不让综合失败。读表文件失败的后果不是读到错误的表项，
而是数组保持初值，综合器把整条读通路优化成常量：

```text
   期望的电路                        实际综合出的电路
   地址 --> [ ROM 1024 项 ] --> 数据     地址 --> (常量) --> 数据
```

所以硬件上不是表里的数不对，而是根本没有表。

定位。`$readmemh` 的裸文件名在综合时按发起读取的源文件所在目录查找。
表文件放在了使用结果的模块旁边，而读取它的是表结构模块，两者不在同一目录。
这件事同时解释了两个一直没有解释的数：补两个定点乘法按预算应增加上千个 LUT，实测只增加两百多；
加一张表按预算应多一块 BRAM，实测一块没多。两条都指向"这部分电路没有被综合出来"。

根因与修法。表文件与表结构模块放在一起，并把位置要求写进模块头注释；
离线综合脚本 `ooc_units.tcl` 显式登记表文件，并在综合后检查 ROM 带有初值，
找不到 ROM 或初值为零即报错。

原判据为什么没有覆盖到它：功能判据在仿真里运行，仿真器按工作目录找到了表；
而综合一侧没有任何检查把这条警告升级为错误。

### 4.4 表地址被寄存了两次，多花一级流水

第一现场。没有仿真报错，结果一直是对的。这一条是逐行读源码时发现的：

```verilog
   s1_addr <= s0_frac[22:13];                          // 本模块寄存一次

   bram_lut_1024x32 ... .addr(s1_addr)
        always @(posedge clk) dout <= mem[addr];       // 存储器内部又锁存一次
```

解读。同步读存储器自己会在时钟沿锁存地址。在它外面再寄存一次，地址就走了两级触发器，
而数据只需要一级读延迟。多出来的一拍必须有人消化，于是有了一个只搬运旗标、不做任何计算的级。

定位。判断依据是"这一级做了什么"：它的时序块里没有算术，只是把上一级的旗标原样搬到下一级。
一个不改变任何值的流水级，存在的唯一理由只能是等待某样东西，这里等的是表读，
而表读的等待存储器自己那一级已经提供了。

根因与修法。表地址直接接到存储器的地址口，即 3.6 节的形态，单元延迟从 6 拍降到 5 拍，
组合深度不变。数值等价用新旧两个版本并排例化、喂同一批输入、按输出顺序逐位比较来证明：
20 万条随机输入加 8 个定向边界（1.0、2.0、正负零、Inf、NaN、denormal、最大规格化数），失配 0。
`FP32_RECIP_LAT` 同步改为 5。

原判据为什么没有覆盖到它：多花一拍不是错误。所有判据问的都是结果对不对、延迟是否等于声明值，
而两条当时都成立。这一类问题只能通过读代码问另一个问题来发现：这一级存在的理由是什么。
