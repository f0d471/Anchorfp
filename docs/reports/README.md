# fp 系列

给一颗没有浮点单元的 CPU 增加浮点硬件的开发记录。

平台为 Artix-7 xc7a200t，系统时钟 50 MHz，处理器是龙芯 LA32R 的一个精简实现。
该处理器没有浮点单元，C 代码中的浮点运算由 libgcc 用整数指令模拟，一次乘法 131 个周期。

## 关于契约

第一章开头那一节「这套库是给谁用的」与「契约分三档」，
是在第十二章做完之后回头补的，然后按它把整个目录过了一遍。
补出来的账没有单开一章，各自记在它该在的地方：

| 补出来的问题 | 记在哪 |
|---|---|
| 两个回归脚本的退出码恒为绿 | 01 章 4.4 |
| 「冲零」没规定下溢判定时点 | 04 章 4.3 |
| 进位保存档声称逐位等价，实为假绿 | 10 章 4.4 |
| 项数上限的断言误报，且没有编译期判据 | 10 章 4.6 |
| 误差界的推导用了不成立的前提 | 11 章 3.1 |
| 灾难性损失被稀释在一个宽泛信号里 | 11 章第六节 |
| 两层参考模型共用输入侧代码 | 11 章 8.1 |
| 向量侧的最大值归约在正规数上算错 | 向量引擎，不在本仓 |
| 平方根倒数的 denormal 处理与目录规则不一致 | 超越函数单元，不在本仓 |

最后两条列在这里是因为它们是同一次审计查出来的，落点在宿主 SoC 仓的另外两个模块。
本仓不含那两个模块，但第二条的结果本仓看得见：整机 LUT 那一列少掉的 268 个就来自它。

**顺序颠倒的代价是真金白银的返工。** 契约该在第一章就定下来，
而不是走到第十二章再回头补——这也是为什么它现在放在第一章，
而不是单独占一章挂在最后。

第 01 章的接口为共用接口，exp / sin / cos / rsqrt 四个超越函数挂在同一层，其系列另立。

指令单价，用紧循环探针测量，已减去空循环基线。

| `__mulsf3` | 131.45 拍 | 4.99 |
| `__addsf3` | 81.52 拍 | 5.99 |
| `__subsf3` | 88.96 拍 | 5.99 |
| `__ltsf2` | 31.56 拍 | 5.99 |
| `__floatsisf` | 55.76 拍 | 3.99 |
| `__fixsfsi` | 27.93 拍 | 3.99 |
| `__divsf3` | 261.64 拍 | 261.64（[未替换](07-FP32倒数的查表与牛顿迭代实现.md)）|

屏幕上的椭圆，全部为浮点运算。逐工作点实测：

```
  纯软件     乘法    加减     FTZ     比较     转换    硬件 rsqrt
                                                      累计 −89.3%
```

第 10 章那一列里，WNS 变好的那条路那一步一行没碰（在向量引擎的地址生成器上），
是布局重来的结果，不能记在它头上；WHS 变差的那条才是它带来的。

最后一列是按契约把整个目录过一遍那一轮（各条的去向见上面「关于契约」那张表）。
LUT 少掉的 268 个主要来自平方根倒数单元（不在本仓）：非规格化输入通路对齐到
本目录统一的 DAZ 之后，那条 23 路优先编码与移位器整个删掉。
乘累加这一侧只多了 32 个：每条 lane 一个 `mac_prec` 粘滞触发器加一个 LUT
（11 章第六节）。

WHS 从 0.024 变到 0.019 要说清楚：最差 hold 路径两次都是同一对寄存器
（`PE_LANE[17].u_mac` 的 `term_q_reg[73]` 到 `acc_r_reg[73]`，累加环内），
路径形状一行没动，差的是布局。**这一轮不能声称「没有代价」，
只能说代价不在那条路径的逻辑上。** 余量仍是正的，时序全 MET，产出了 bitstream。

## 这条线的收尾条件

标量浮点在此封顶，依据三条：

1. 协处理器为阻塞式，EX 级发出请求后停到应答，上限是每条指令若干拍，做不到每拍一个结果。提高吞吐需要向量引擎。
2. 除法不再加速。IEEE 要求除号正确舍入，近似倒数不能替换；实现一个正确舍入的迭代除法器，代价超过收益。
3. 转换完成后重新拆账，循环控制、寻址、访存、整数分支合计占 47%，为最大单项（乘法 18.5%）的 2.5 倍，而乘法的 4.99 拍已是硬件价。继续增加标量 FP 指令的边际收益不足。
