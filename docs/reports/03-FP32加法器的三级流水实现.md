# FP32 加法器的三级流水实现

## 一、动机

乘法做完之后，剩下的最大单项是加减。

做法上它比乘法难，难的原因在下一节能直接推出来：
乘法的三个字段各算各的，加法的三个字段从一开始就纠缠在一起。

除了延迟约束之外，这个模块还有一个当时没意识到的约束。
它不只给协处理器用，矩阵加速器的 32 路乘累加也用它，而乘累加是一个反馈环。
第一版做出来的时候那个环是单周期的，加法器一旦变成多拍，累加就错。
这个约束比"延迟要短"更硬，它直接否决了"切流水"这个选项。经过在第四节 4.1。

## 二、为什么是这三步

### 加法的三个字段是纠缠的

还是从表示法出发。两个数：

```
   a = (-1)^sa x 1.ma x 2^(ea-127)
   b = (-1)^sb x 1.mb x 2^(eb-127)
```

乘法能把三个字段拆开各算各的，因为乘法对指数是相加、对尾数是相乘，
两者互不干涉。加法不行。加法要求两个数的小数点在同一个位置，
而小数点的位置正是由阶码决定的：

```
   ea = 5      1 . m m m m m m m .................
                 ^
                 小数点在这里

   eb = 2                 1 . m m m m m m m .......
                            ^
                            小数点在这里，差 3 位

   两排位对不齐，不能逐位相加
```

所以加法的第一件事不是相加，是把两个数改写成同一个指数。

### 改写只能往一个方向，于是生出第一步

要改写成同一指数，有两种方向：抬高小的那个，或者压低大的那个。

```
   抬高小的：  1.mb x 2^2   =   0.001mb x 2^5      尾数右移 3 位
   压低大的：  1.ma x 2^5   =   1000.ma x 2^2      尾数左移 3 位
```

压低大的会让尾数往高位长出去，而尾数字段宽度固定，
左移出去的是最高有效位，丢了就是数量级错。
抬高小的让尾数右移，移出去的是最低有效位，丢了只是精度损失。

两害相权，只能抬高小的。这一步是**对阶**。

它同时决定了对阶必然丢位，所以要给"丢掉的部分"留位置，
这就是后面那三个保护位的来历。

### 加减之后范围失控，于是生出第二步

对齐之后是一次定点加减。结果的范围跟乘法那里完全不同：

```
   同号相加   1.xxx + 1.xxx   结果落在 [1, 4)    可能大于 2，要右移 1 位
                               +----------------+
                               | 1 0 . x x x x  |   多出一位
                               +----------------+

   异号相减   1.xxx - 1.0xxx  结果落在 (0, 2)    可能远小于 1，要左移
                               +----------------+
                               | 0 0 0 0 1 . x  |   前面一大片零
                               +----------------+
```

乘法只有"右移一位或者不动"两种可能，因为积的范围只有 `[1, 4)`。
加法多出了整个左移方向，而且左移多少位取决于抵消掉了多少高位，是一个变量。

要左移就得先知道移几位，也就是要数出前面有多少个零。
这一步是**规格化**，它比乘法的规格化重得多：
数前导零是一个 26 路的优先级判断，是整个模块最长的一条组合路径。

### 位数装不下，于是生出第三步

跟乘法一样，算完之后的位数多于格式能存的，要扔掉一部分。
这一步是**舍入与组装**，做法跟乘法完全相同。

### 三步的由来

```
   拆包与对阶     两个数的小数点必须对齐，只能右移小的     <- 加法的定义要求
                  右移必然丢位，所以要留保护位

   加减与规格化   结果范围是 (0, 4)，两个方向都要修        <- 加减的值域
                  左移量是变的，要数前导零

   舍入与组装     位数装不下                             <- 跟乘法同一个原因
```

三步各占一级流水。为什么正好这么切，在 3.4 节。

## 三、每一步做了什么

### 3.1 拆包与对阶

拆包跟乘法器一样。对阶这一步做了两件事。

**先比大小，再重新贴标签。**

对阶要右移小的那个，所以先得知道谁小。比出来之后，
控制逻辑直接把两路数据交换到固定位置，无需继续保存“a 或 b”的来源标记：

```
                a          b
                |          |
                +----+-----+
                     |
                  比绝对值
                     |
        +------------+------------+
        |                         |
       big                       sml
   （不动的那个）           （要右移的那个）

   从这里往下，数据通路里只有 big 和 sml，没有 a 和 b
```

代价是几个多路选择器，换来的是后面几十行没有分支。
它还顺带保证了两个隐含前提：阶码差恒为非负，后面那个减法恒不借位。

**右移，并且把移出去的位归约成一位。**

小尾数右移之前，先在它后面接三个空位：

```
   移位前
   +-------------------------+---+---+---+
   |      24 位尾数           | 0 | 0 | 0 |
   +-------------------------+---+---+---+
                               G   R   S     <- 预留的三个保护位

   右移 5 位之后
   +-----+-------------------------+---+---+
   | 0 0 |      24 位尾数           |...|   |
   +-----+-------------------------+---+---+
     补零                            |   |
                                     |   +-- 掉出去的位
                                     +------ 落进保护位的部分

   掉出去的那些位全部或在一起，结果并进最低那一位（S 位）
```

阶码差如果大于等于 27，小的那个数整个落在窗口之外，
这时候只要它非零就把 S 置 1。

三个保护位够用有严格理由，分两种情况：

```
   阶码差大   右移很多位，丢掉很多信息
              但这时候大的那个主导结果，小的只影响最后一位的舍入
              而舍入只需要"比半个最后一位多还是少"
              => 丢了很多，但不需要那些位

   阶码差小   只有 0 或 1，右移最多 1 位
              而预留的三个位本来就是零，右移 1 位掉出去的还是零
              => 需要精度，但一位真实数据都没丢
```

中间的情况不存在：阶码差大于等于 2 的时候，
小的那个不到大的一半，相减以后至少还剩大的一半，最多左移一位，
不会发生大量抵消。

截断版在这里的最大误差是 128 ULP，集中在两个数异号、大小接近、
相减以后高位大量抵消的场景。那正好是 transformer 的残差连接和 rmsnorm
大量在做的事。

### 3.2 加减与规格化

加减用比尾数宽一位的宽度做，多出来的那一位接进位。
因为 big 恒大于等于 sml，减法永远不借位，不用处理补码符号。

规格化分三种情况，看结果的最高位落在哪儿：

```
   情况 1    +---+---+------------------+
             | 1 | x |  ...             |    进位了，值 >= 2
             +---+---+------------------+
                      整体右移 1 位，阶码 +1
                      被挤掉的最低位并进新的最低位

   情况 2    +---+---+------------------+
             | 0 | 1 |  ...             |    正好规格化，不动
             +---+---+------------------+

   情况 3    +---+---+---+---+---+------+
             | 0 | 0 | 0 | 0 | 1 |  ... |    有前导零，值 < 1
             +---+---+---+---+---+------+
                       |
                       v  数出前面有几个零，整体左移那么多位
             +---+---+------------------+
             | 0 | 1 |  ...             |    阶码减掉同样的数
             +---+---+------------------+
```

情况 3 里那个"数出前面有几个零"是 26 路并列判断，
最高的那个为 1 的位胜出。这是整个模块里最长的一条路径，
也是它必须独占一级的原因。

阶码在这三条路上分别是 +1、不变、减去前导零数。
减法可能减出负数，加法可能加到 256，所以中间量用 10 位带符号，
两头都留足，跟乘法器同一个理由（[第二章](02-FP32乘法器的流水与舍入实现.md) 4.2）。

### 3.3 舍入与组装

舍入跟乘法器完全一样，GRS 三位判进位（[第二章](02-FP32乘法器的流水与舍入实现.md) 3.5）。

组装的时候多了一条乘法器没有的规定：结果是零的时候，符号取什么。

零在这里有两个来源，规则不同：

```
   来源 A   尾数减出来正好是零（两个数精确相消）

            同号     (-0) + (-0)  ->  -0     保留符号
                     (+0) + (+0)  ->  +0

            异号      1.0 - 1.0   ->  +0     IEEE 754 规定
                     (-0) + (+0)  ->  +0     就近舍入模式下恒为正零

   来源 B   尾数非零，但阶码太小被冲成零（下溢）

            保留原符号，一个很小的负数下溢应该得 -0
```

来源 A 的异号那一条是 IEEE 754-2008 §6.3 明文规定的，不是自然推论：
两个非零的数相消，结果的符号在数学上没有定义，标准挑了正零。

这几行的验证问题在第四节 4.2。

### 3.4 为什么正好切三级

第一版是单周期的，撤回的经过在 4.1。现在按三步各占一级：

```
   +----- 级 1 -----+  +------ 级 2 ------+  +---- 级 3 ----+
   | 比大小         |  | 定点加减         |  | GRS 判进位   |
   | 变长右移       |->| 26 路前导零判断  |->| 上下溢判断   |-> 输出寄存
   | 掩码归约 S     |  | 变长左移         |  | 拼三段       |
   | （中等长度）   |  | （最长）         |  | （中等）     |
   +----------------+  +------------------+  +--------------+
```

级 2 最长，它决定这个模块的频率。再切细可以，
但按[第一章](01-标量浮点协处理器接口设计.md)那条约束，
多一级就是每次浮点加法多付一拍，不划算。

### 3.5 减法不单独做

减法就是把第二个操作数的符号位翻过来再做加法：

```
   a - b  =  a + (-b)

   b   +-+--------+----------+      -b   +-+--------+----------+
       |0|   e    |    f     |  ->       |1|   e    |    f     |
       +-+--------+----------+           +-+--------+----------+
        ^ 只翻这一位，零成本
```

FADD 和 FSUB 共用同一个加法器，分发层多一个选择器，省下一整套减法器。

## 四、遇到的问题

### 4.1 单周期版本整个撤回

**第一现场。** 最早的版本是单周期的，对阶、加减、规格化、舍入全在一个组合云里。
功能是对的，25 万条向量 0 ULP。综合报告给出的是：

```
Path delay:      26.0 ns
Logic levels:    42
Requirement:     20.0 ns
Slack (setup):   -6.365 ns   VIOLATED
```

**解读。** 三个数指向同一件事。

`Requirement 20.0 ns` 是 50 MHz 的周期。`Path delay 26.0 ns` 是这条路径实际要的时间。
两者之差就是那个负余量。跑不完，要把频率降到 38 MHz 左右才能收敛。

```
   一个周期 20 ns
   |<----------------------------------->|
   |                                     |
   |  这条路径实际需要 26 ns              |
   |<------------------------------------------>|
                                         |<---->|
                                          超出 6.365 ns
```

`Logic levels 42` 是这条路径上串了 42 级逻辑。
一个 20 ns 的周期通常能容纳十几级，42 级远超范围。

结论是这坨组合逻辑必须切开。

**定位。** 到这里为止的诊断是对的，但漏了一个更硬的约束。
这个加法器当时待在乘累加单元的单周期反馈环里：

```
   积 --> [ 加法器 ] --> acc
              ^           |
              +-----------+
              每拍读一次 acc

   加法器如果变成 3 拍，第 k 项读到的 acc 还没被第 k-1 项更新
```

也就是说"切流水"这个选项当时根本不存在。

**结果。** 整个舍入改动撤回，退回截断版。

**教训。** 两个否决项的性质不同。
"组合云 26 ns"可以靠切流水解决，"它在一个单周期反馈环里"不能，
后者必须先改反馈环的结构。当时的判断把两件事混在一起看了。

后来先改了乘累加的结构（[第八章](08-FP32乘累加反馈环的启动间隔.md)），
让它能容纳多拍加法器，这个加法器才真正上去。

### 4.2 零符号那几行，25 万条随机向量验不出来

**第一现场。** 做过一次注入实验：把判断同号的那个信号取反，重跑回归。
`tb_fp32_add` 的汇总是：

```
==== fp32_add vs IEEE golden ====
loaded/fed = 250000
total      = 250000
exact(0ULP)= 250000  (100%)
off 1 ULP  = 0
off >1 ULP = 0
max ULP    = 0
ALL PASS (250000/250000 逐位相同)
```

**解读。** 故意注错，回归全绿，一条都没红。
这个输出的含义是这条回归对那个信号的鉴别力为零。

原因是那个信号只在一种输入上有可观测效应：

```
   全部输入空间
   +--------------------------------------------------+
   |                                                  |
   |    25 万条随机向量落在这一大片                     |
   |                                                  |
   |                                        +---+     |
   |                                        | * |     |  <- 两数异号
   |                                        +---+     |     且绝对值完全相等
   +--------------------------------------------------+
                                              ^
                                   零符号那几行唯一起作用的地方
```

要命中那个点，需要两个随机的 32 位数除符号位外完全相同。
25 万条随机值碰不到。

**修法。** 补三条定向用例，专门打在精确相消上：

```
    1.0 - 1.0     期望 +0    验异号相消得正零
   -0.0 - (+0.0)  期望 -0    FSUB 把 +0 翻成 -0，实际是 (-0)+(-0)，验同号保留符号
   -0.0 - (-0.0)  期望 +0    实际是 (-0)+(+0)，验混合情况得正零
```

三条把那个判断的两个输入组合都覆盖到了。

**为什么判据没覆盖到。** 判据的覆盖范围要跟它声称验证的东西对上。
"25 万条随机向量全过"读起来像是覆盖得很好，
但它对"精确相消"这条路径的覆盖是零。

这三行后来成了整条线上鉴别力最强的判据，
理由和完整现场在[第九章](09-FP32数据通路的hold时序修复.md)。

## 五、结果

| | 软件 libgcc | 硬件 |
|---|---:|---:|
| `__addsf3` | 81.52 拍 | 5.99 拍 |
| `__subsf3` | 88.96 拍 | 5.99 拍 |

加法和减法在软件版里差 7 拍，因为 libgcc 的 `__subsf3` 要先取反
再跳进 `__addsf3`；硬件版两者完全一样，因为分发层只是一个选择器。

geometry 那一级从 4,976 ms 降到 2,621 ms，比上一个工作点又少 47.3%。
