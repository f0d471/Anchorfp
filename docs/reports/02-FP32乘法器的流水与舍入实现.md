# FP32 乘法器的流水与舍入实现

[上一章](01-标量浮点协处理器接口设计.md)接好了协处理器骨架。这一章往上挂第一条指令。

## 一、动机

### 为什么第一条是乘法

拿三维渲染那个负载拆过账。它最费时的一级叫 geometry，
把空间里的高斯点投影成屏幕上的椭圆，全是浮点。
按调用次数乘单价折算，浮点开销里乘法占了将近一半，是最贵的单项。

它同时是最容易的一项，理由在下一节展开：乘法的三个字段几乎各算各的，
相互干扰只有两处。先做它，可以在最短时间内验证整条链路
（编译器发 `bl` → 链接期替换 → 协处理器握手 → 运算单元 → C 的返回值）是通的。

### 延迟预算

上一章那条约束在这里第一次落地：这个单元的延迟就是 FMUL 的单价。
50 MHz 意味着 20 ns 的周期。24×24 的乘法器用查找表搭，在 Artix-7 上
本身就占掉大半个周期，所以它至少要独占一级。
目标定成两级，多一级就多付一拍。

## 二、为什么是这五步

### 从表示法推出来

FP32 存的是三个字段，值等于 `(-1)^s × 1.m × 2^(e-127)`。
两个这样的数相乘，把定义直接乘开：

```
    (-1)^sa x 1.ma x 2^(ea-127)
  x (-1)^sb x 1.mb x 2^(eb-127)
  ---------------------------------------------
  = (-1)^(sa^sb) x (1.ma x 1.mb) x 2^(ea+eb-254)
        |               |                |
     只跟符号有关     只跟尾数有关       只跟阶码有关
```

三个字段各自独立，互不牵扯。如果就这样结束，乘法只需要一步：
三条线并排算完，拼回去。

### 两处干扰，生出两步

问题是算完之后，有两条线的结果超出了各自字段能装的范围。

**干扰一：尾数积的范围超了。**
两个尾数都在 `[1, 2)`，积落在 `[1, 4)`。而格式规定尾数落在 `[1, 2)`，
隐藏位固定在同一个位置。积一旦大于等于 2，隐藏位就跑高了一位：

```
   尾数积的两种形态（48 位）

   bit  47 46                                              0
       +--+-----------------------------------------------+
   1   | 0| 1 . x x x x x x x x x x x x x x x x x x x x x |   积在 [1,2)
       +--+-----------------------------------------------+
            ^ 隐藏位在 bit46，位置正确

       +--------------------------------------------------+
   2   | 1 . x x x x x x x x x x x x x x x x x x x x x x x|   积在 [2,4)
       +--------------------------------------------------+
         ^ 隐藏位跑到了 bit47，多占一位
```

形态 2 要把整个积右移一位挪回去。右移一位等于除以 2，
所以阶码要补一个 +1。这一步是**规格化**，
它处理的是尾数那条线溢出到阶码那条线上的那一位。

**干扰二：尾数积的位数超了。**
24 位乘 24 位得 48 位，而格式只存 23 位。算出来的一半装不下：

```
   bit  46                     23 22                        0
       |------ 要保留的 24 位 --|------ 要扔掉的 23 位 ------|
       | 1 . f f f f f f f f f  | x x x x x x x x x x x x x |
       +-----------------------+---------------------------+
                                 ^
                          从这里开始的信息全部丢失
```

扔掉的部分不是零，怎么扔决定结果偏向哪一侧。
这一步是**舍入**，它处理的是位宽装不下的部分。

### 再加一步：特殊值不走这条通路

上面的推导默认两个操作数都是常规数。IEEE 754 里还有 NaN、±Inf、±0 三类取值，
它们的阶码字段被征用，`1.m` 这个解释不成立。
`Inf × 0` 这种组合甚至没有数值答案。

所以要在最前面把它们筛出来，走一条独立的短路径。这一步是**特殊值判断**。

### 五步的由来

```
   拆包            把三个字段切出来，补回隐藏位      <- 表示法要求
   特殊值判断      把不适用 1.m 解释的输入分流       <- IEEE 特殊值
   主运算          符号异或 / 阶码相加 / 尾数相乘    <- 定义乘开的结果
   规格化          修正尾数溢出到阶码的那一位        <- 干扰一
   舍入与组装      处理装不下的 24 位，拼回三字段    <- 干扰二
```

难度分布很不均匀。前三步是照定义翻译，最后两步是全部工作量所在。

## 三、每一步做了什么

### 3.1 拆包

对输入做的事是切开加补一位：

```
   输入 a   +-+--------+-----------------------+
            |s|  e (8) |        f (23)         |
            +-+--------+-----------------------+
                            |
                            v  在小数部分前面接一个 1
            +-+--------+-+-----------------------+
            |s|  e (8) |1|        f (23)         |
            +-+--------+-+-----------------------+
                        |------ 24 位尾数 -------|
```

补回来的那个 1 是隐藏位，格式里不存但参与运算。这一步没有技巧。

### 3.2 特殊值判断

按阶码字段分流：

```
   e = 0            ->  正负零（FTZ 契约下也包括 denormal，见第四章）
   e = 1 .. 254     ->  常规数，走主通路
   e = 255, f = 0   ->  正负无穷
   e = 255, f != 0  ->  NaN
```

再加一条组合判断：只要一边是无穷、另一边是零，结果是 NaN。
`Inf × 0` 在数学上没有定义。这一条在 FTZ 那一章还要扩一次，
因为 denormal 被当成零之后，`Inf × denormal` 也落进这条。

判断的结果不直接产生数值，而是产生四个一位标志
（是 NaN / 是 Inf / 是零 / 要不要走特殊通路），跟着流水线走到最后一级：

```
   常规通路 ----------------+
                           |
                           +--> 选一路 --> 输出
                           |
   特殊值通路 ---------------+
                           ^
                      四个标志
```

选择器放在数据通路末端。硬件中的两条通路始终并行计算，
没有"因为是 NaN 所以跳过尾数乘法"这回事。

### 3.3 主运算

三条线并排：

```
   符号   sa --+
               (异或) ------------------------------> 结果符号
          sb --+

   阶码   ea --+
               (加) --- 减 127 ---------------+
          eb --+                              |
               两个阶码各含一份偏置，            |
               相加以后多了一份，减掉            v
                                          到规格化
											  ^
   尾数   1.ma --+                             |
                 (乘) --- 48 位积 -------------+
          1.mb --+
```

尾数乘是一个 24×24 的整数乘法，用查找表搭。
这条是整个单元里最长的一条组合路径。

### 3.4 规格化

看积的最高位，决定要不要挪：

```
   bit47 = 1   +-------------------------------+
               | 1 . x x x x ... x x x x x x x |
               +-------------------------------+
                         |  整体右移一位
                         v
               +-------------------------------+
               | 0 1 . x x x x ... x x x x x x |    阶码 += 1
               +-------------------------------+

   bit47 = 0   不动，阶码不变
```

只有这两种情况。乘法器永远不需要左移，因为两个规格化数的积不可能小于 1。
这个性质在[第四章](04-FP32加乘单元的FTZ语义实现.md)兑现成一次删模块的机会。

### 3.5 舍入

这是整条指令唯一需要想清楚的一步。

要扔掉的那 23 位携带的信息，只有一件事对结果有影响：
它代表的值，比"最后一位的一半"大还是小。
所以不必保留全部 23 位，三个位就能回答：

```
   bit  46           24  23 | 22   21   20 .............. 0
       +---------------+---+-----+----+------------------+
       |  保留的高位     |LSB| G   | R  |   剩下的 21 位    |
       +---------------+---+-----+----+------------------+
                        |    |     |          |
                        |    |     |          +- 全部或在一起，得 S
                        |    |     +------------ R
                        |    +------------------ G，权重恰好是半个最后一位
                        +----------------------- 保留部分的最低位
```

判断规则：

```
   G = 0                   扔掉的部分 < 半个        -> 不进位
   G = 1，R 或 S 非零       扔掉的部分 > 半个        -> 进位
   G = 1，R 和 S 都是 0     扔掉的部分 = 半个（平局） -> 看 LSB
                                                       LSB 是 1 -> 进位
                                                       LSB 是 0 -> 不进位
```

平局采用取偶规则；一律进位会产生第四节 4.1 所示的实测偏差。

进位本身还会再溢出一次：

```
      1.1111111 ... 1
   +               1
   --------------------
     10.0000000 ... 0     <- 多出一位
```

这时候结果正好是 2 的整数次幂，尾数归零、阶码再加一。
所以舍入器要比尾数宽一位来接这个进位。

### 3.6 组装与切级

组装时先判范围，再拼三段：

```
   最终阶码 <= 0     ->  下溢，输出正负零（FTZ，见第四章）
   最终阶码 >= 255   ->  上溢，输出正负无穷
   否则              ->  +-+--------+--------------+
                         |s|   e    |      f       |
                         +-+--------+--------------+
```

流水切两级：

```
   +------ 级 0 ------+   +------ 级 1 ------+   +- 输出 -+
   | 拆包             |   | 规格化           |   |        |
   | 特殊值判断       |-->| 舍入             |-->| 寄存   |--> 对外 2 拍
   | 尾数乘（最长）   |   | 组装             |   |        |
   | 阶码加           |   |                  |   |        |
   +------------------+   +------------------+   +--------+
```

切在这里，是因为 24×24 的全查找表乘法器占掉大半个周期，
不能再跟舍入的进位链串在同一级。这是延迟预算允许的最小级数。

## 四、遇到的问题

### 4.1 截断的误差是单向的

**第一现场。** 截断版跑 20 万条随机规格化向量对金标准，
`tb_fp32_mul` 的汇总是这样：

```
==== fp32_mul vs IEEE golden ====
total      = 200000
exact(0ULP)= 98421  (49%)
off 1 ULP  = 101579
off >1 ULP = 0
DUT<golden = 101579  (偏低占比 50%)
max ULP    = 1
```

（`DUT<golden` 这一行是为了看偏差方向后来加进 TB 的。
上面的条数按当时记录的百分比反推，量级和结论不受影响。）

**解读。** 逐行看。

`off >1 ULP = 0` 和 `max ULP = 1`：所有偏差都不超过一个最后一位。
单看这两行，"误差小于 1 ULP"是成立的，
按当时的判据（最大误差 ≤ 1 ULP）应该判通过。

`off 1 ULP = 101579`：一半的向量偏了一位。

关键在最后那个计数器。`DUT<golden` 统计的是硬件结果小于金标准的条数，
它跟 `off 1 ULP` 完全相等。也就是所有偏差都落在同一侧，没有一条偏高。

```
   如果是舍入噪声                     实测

   偏低  |  偏高                    偏低   |  偏高
    50k  |  50k                    101579 |   0
   ------+------                   -------+------
      对称，累加相消                  单向，累加不相消
```

**根因。** 截断永远朝零取整。对正数它偏小，对负数它偏大，绝对值总是变小。
这种单向偏差在累加里按 N 线性增长，而对称误差按根号 N 增长。
对 llama2 这种一个 token 接一个 token 往下推的模型，差别体现在生成质量上。

**修法。** 把截断换成 3.5 节那个就近舍入、平局取偶。

**为什么判据没覆盖到。** 判据是"最大误差 ≤ 1 ULP"，
这是一个幅值上界，对偏差的方向不敏感，截断版满足它。

指标选错的形状是：被测的性质（方向性）落在指标的定义域之外。
补一个按符号分开统计的计数器，问题当场可见。

### 4.2 阶码中间量回绕，上溢变成了下溢

**第一现场。** 定向用例喂 `max_float × 2`，期望正无穷：

```
  FAIL: max*2 -> Inf   got=00000000 exp=7f800000
```

**解读。** `7f800000` 是正无穷，`00000000` 是正零。
这两个值是浮点数轴上距离最远的两个点：

```
   -Inf ...... -max ... -0  +0 ... +max ...... +Inf
                            ^                    ^
                          拿到的               期望的
```

一个实现如果只是算错了，拿到的通常是量级接近、尾数不对的数。
拿到完全相反的另一个极端，说明它走的是另一条判断分支，
这可以排除同一条计算通路内部的算术错误。上溢输入实际走进了下溢出口。

所以要查的是"上溢和下溢是怎么判的"。

**定位。** 顺着阶码那条线算数值范围：

```
   ea 属于 [1, 254]           eb 属于 [1, 254]
        +-------- 相加 ----------+
                  |
             [2, 508]
                  |  减 127
                  v
             [-125, 381]        <- 中间量的真实范围
```

而当时这个中间量存在一个 8 位无符号量里，只能装 `[0, 255]`：

```
   真实值   ...  253   254   255   256   257  ...
   8 位存   ...  253   254   255    0     1   ...
                                    ^
                              这里绕回去了
```

`max_float × 2` 的阶码算出来是 256，存进去变成 0。
而下溢的判据是"阶码等于 0"，于是命中，输出写正零。

**修法。** 中间量改成 10 位带符号，两头都留足，
上溢下溢的判断推到最后一级再做：

```
   10 位带符号能装 [-512, 511]

   -125 -------------- 0 ---------- 255 ------ 381
     |                 |             |          |
     +-- 下溢，写零 ---+    常规      +-- 上溢，写无穷
```

同一个模式后来在加法器和倒数单元里各出现一次，都是 10 位带符号。

**这次判据覆盖到了。** 随机向量的指数域取的是 `[110, 145]`，中间地带，
碰不到边界。覆盖到它的是定向段里的极值用例。
随机段和定向段各管一件事，缺一不可。

### 4.3 右移规格化把原积最低位丢了

**第一现场。** 这一个不是仿真报出来的。20 万条随机向量当时全绿，
修之前和修之后也都全绿 —— 它是逐行读规格化与舍入那一段时看出来的，
然后照着位型反推，构造出一对操作数：

```
   a = 0x3F800C3D
   b = 0x3FFFEB15

   得到     0x400001C6
   正确 RNE 0x400001C7
   差       1 ULP
```

**解读。** 两个输入都是正的普通有限数，不碰 NaN、Inf、零、denormal，
走的是最主干的那条乘法通路。差 1 ULP 意味着舍入方向判错了一次。

把尾数乘出来看：

```
   24 位尾数   0x800C3D * 0xFFEB15
   完整乘积    0x8001C6800001
   低 25 位    0x00800001
                 ^bit23=1(Guard)  bit22..1 全 0  bit0=1
```

Guard 是 1，Guard 以下除了最低位全是 0。**被丢弃的部分严格大于半个 ULP**，
RNE 必须进位。而代码没进。

**定位。** 舍入本身没问题，问题在它上一步。乘积最高位是 1 时要右移一位规格化：

```
   prod_n = product_r >> 1
```

48 位右移一位，最低位就掉出容器了。之后 sticky 是这样算的：

```
   sticky = |prod_n[21:0]      而 prod_n[21:0] = product_r[22:1]
```

原积的 bit0 不在里面。正确的 sticky 要覆盖 `product_r[22:0]`，
代码只覆盖了 `[22:1]`。

不右移的那条分支没有这个问题，`prod_n` 就是 `product_r`，位窗完整。
所以缺陷只在右移分支，也就是乘积落在 `[2,4)` 的那一半输入上，
而且还要同时满足 Guard=1、右移后 sticky=0、保留位 LSB=0、原 bit0=1。
四个条件叠起来，位型非常稀疏。

**根因和修法。** 规格化右移与 sticky 汇总被写成了两个独立步骤，
右移那一步先丢了一位信息，汇总时已经找不回来。修法是在右移的同时把它并回去：

```verilog
   prod_n[0] = product_r[1] | product_r[0];
```

`prod_n[0]` 本来就是 sticky 的一部分，两位或起来不损失任何信息。
同一份代码里 `fp32_add` 的规格化早就是这么写的（`norm[0] = raw[1] | raw[0]`），
乘法器这边漏了。

**原来的判据为什么没覆盖到它。** 判据是 20 万条随机向量对 IEEE 金标准，
0 ULP。它没抓到，是因为随机采样命中不了这个位型 —— 修之前跑，
20 万条依然是 100% 精确。

这条判据本身没有错，错在把"样本内 0 ULP"当成了"全输入空间 0 ULP"。
补的是一条定向用例，直接打这一对操作数，放在 `tb_fp32_mul_r.v` 里。
把修复注释掉重跑，随机部分仍然全绿，只有定向那条变红 —— 这就是它存在的理由。

## 五、结果

`softfp_prof` 是单价探针，跑紧循环量每个原语的净成本，减掉空循环基线：

| | 软件 libgcc | 硬件 |
|---|---:|---:|
| `__mulsf3` | 131.45 拍 | 4.99 拍 |

那 4.99 拍的构成：2 拍是乘法器本身，1 拍是协处理器的输出寄存器，
剩下的是 `bl` 跳进 wrapper 再跳回来的开销。

geometry 那一级从 10,559 ms 降到 4,976 ms，少了 52.9%。

这一章报出来的 4.99 是拿掉 wrapper 里那段 denormal 判断之后的数。
第一版的 wrapper 前面还有十几条整数指令在做那个判断，
当时实测的 wrapper 总开销是 10.99 拍，那部分要到
[第四章](04-FP32加乘单元的FTZ语义实现.md)才归零。
