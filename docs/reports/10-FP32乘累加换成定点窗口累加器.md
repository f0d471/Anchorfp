# FP32 乘累加换成定点窗口累加器

## 一、动机

[第八章](08-FP32乘累加反馈环的启动间隔.md)把一个三级流水的加法器接成了反馈环，
量出相邻两笔之间必须隔 4 拍，否则第二笔读到的是还没写回的旧值。
那一章给出的办法是交错：摆 4 个累加器，第 k 项进第 `k mod 4` 个，
喂完再用同一个加法器做两两归约，把间隔压回每拍一个。

办法有效，但它绕过了问题而不是解决问题。绕过去要付的钱是一整条链：

```
   反馈环 3 拍
     -> 单累加器的喂积间隔是 4
     -> 摆 4 个累加器交错，把间隔压回 1
     -> 于是需要一棵归约树
     -> 于是需要归约控制，每条 lane 各一份，一共 32 份
     -> 于是累加器成了数组，多路选择器进了环内
     -> 于是求和次序变成累加器个数的函数，金标准得复刻这个次序
     -> 而且每一项乘积各自舍入一次，误差随项数累积
```

这一章去掉链的源头：让反馈环只有一拍。链上其余七条随之消失。

## 二、为什么是这五步

### 三拍花在哪里

`fp32_add` 的三级分别是对阶移位、加减与前导零规格化、舍入组装。
放进反馈环，这三件事就都在环里：

```
   acc ---> 对阶 ---> 加减+规格化 ---> 舍入 ---> acc
            (1 拍)      (1 拍)        (1 拍)
```

逐件看，只有中间那个加是累加真正需要的：

- 对阶在环里，是因为累加器的阶码是动态的。每加一次都可能变，
  下一项要移多少位，得等这一次的结果出来才知道。
- 规格化与舍入在环里，是因为累加器保持着 IEEE 的规格化形式。
  但中间结果没人看，它只在最后一项之后才需要变回 IEEE。

也就是说，环里三件事有两件是为了让累加器长得像一个 FP32 而付的，
不是为了算加法。

### 把小数点钉死，两件事就都能搬到环外

如果整组要相加的数先对齐到一个共同的阶码基准，它们就成了同一把尺子上的定点整数。
定点整数相加不用对阶、不用规格化、不用舍入：

```
   项 --->[对阶]--->+---> [ 定点加 ] ---> [ acc ]
         (环外)     |          ^             |
                    |          +-------------+
                    |            环长 1 拍
   末项之后 --------+---> [规格化+舍入] ---> FP32 结果
                          (环外，一个 tile 只做一次)
```

对阶能搬到环外，是因为它的移位量是"基准减这一项的阶码"，
只跟这一项自己有关，跟累加器当前的值无关。

### 基准不能是常量

尺子有了，还得决定它钉在哪。最直觉的做法是拿第一项定基准。
第四节 4.1 会给出这个做法当场垮掉的现场：一个点积内乘积的阶码可以跨几十位，
第一项没有理由是最大的那一项。所以基准得会动，而且动的那一步不能把环拉长。

### 项从哪里来

窗口要的是 48 位定点积。而乘法器的第 2 级做的正是"把 48 位积规格化、舍入成 24 位尾数"。
在这条通路上那一级是多余的：它先扔掉 24 位，窗口再把 24 位零扩展回 48 位。
所以乘法器也要跟着改。

### 五步的由来

```
   统一刻度       乘积与 psum 换算成同一个二元组          <- 定点相加的前提

   动态基准       基准跟着运行最大值走，量子化上调        <- 全指数域不能饱和
                  上调那一拍累加器同步右移

   窗口定宽       上方裕度、量子、下方余量、求和增长      <- 决定能容忍多少抵消

   特殊值旁路     NaN 与 Inf 装不进定点窗口               <- 加法器撤掉后那条通路断了

   乘法器拆级     融合通路只取级 1 的未舍入积             <- 省掉一次多余的舍入
```

## 三、每一步做了什么

### 3.1 统一刻度

乘积与 psum 都换算成二元组 `(mant48, E)`，约定它代表的值恒为：

```
   值 = mant48 x 2^(E - 173)
```

173 不是魔数，是三处对齐凑出来的：

```
   FP32     a = ma x 2^(ea-127-23)，ma = {1,frac} 落在 [2^23, 2^24)
   两个相乘 a x b = (ma x mb) x 2^(ea+eb-254-46)
   令 E = ea + eb - 127，则 a x b = (ma x mb) x 2^(E-173)
```

于是乘积的 `mant48` 就是 `ma x mb`、`E` 就是 `ea + eb - 127`，
这两个量乘法器第 1 级已经算好，直接引出来即可。
单个 FP32 数换算到同一把尺子取 `mant48 = mx << 24`、`E = ex - 1`。

### 3.2 动态基准

维持一条不变式：进窗口的每一项都满足 `B >= 这一项的阶码 + WinUp`。
来了一项不够高就把基准往上抬，抬多少位，累加器就在同一拍算术右移多少位：

```
   新项的阶码比基准的容量还高
        |
        v
   基准 += delta      累加器 >>= delta      本项按新基准对齐
   (delta 是 WinG 的整数倍)
```

抬的代价是累加器最低的 delta 位被移出。既有测试集上未因此观察到单 tile 的 ULP 偏差，
但这不足以证明任意后续抵消下都不影响最终舍入；丢位和换基误差另有精度闭环 TODO。

关键在于这一步没有把环拉长。`delta` 量子化成 16 位的整数倍，一共只有七档
（0/16/32 一直到 80，外加整体移空一档），所以环里加的是一个 8 选 1 多路器，
在 7 系列上每位一个 LUT6，再串一条 88 位的 CARRY4 进位链：

```
   acc ---> [8 选 1 移位] ---> [ 加法器 ] ---> acc
              1 级 LUT          进位链
```

`delta` 跟着项一起走流水，判断在环外做，环里只有选择和加。

跨 tile 的部分和是以 IEEE FP32 回灌进来的，它也要进窗口。
只要 psum 非零就让它先定基准，于是 psum 自己的移位量恒等于 `WinUp`，
是一个编译期常量，直接接线，不占那个桶形移位器；
第一个乘积在下一拍才用移位器，两者不冲突。psum 为零时基准由第一个非零乘积定。

### 3.3 窗口定宽

```
   TW   = 48 + WinUp + WinG + WinFrac = 80    对齐后一项占的位宽
   AccW = TW + 8                      = 88    累加器位宽
```

- 48 是乘积尾数的位宽，24 乘 24。
- `WinUp = 8` 是不变式要求的最小上方裕度。
- `WinG = 16` 是基准上调的量子。量子化之后最大的那一项落在 `WinUp` 到 `WinUp+WinG`
  之间，所以这一段也得算进窗口。
- `WinFrac = 8` 是最大项 LSB 之下还留的位数，决定能容忍多少位的灾难性抵消。
- 末尾 8 位里，7 位给求和增长（64 项加 psum 最多让和大 7 位），1 位给符号。

合起来，最大的那一项之下还有 `48 + WinFrac` 位有效位，而结果只保留 24 位尾数，
也就是允许约 32 位的抵消而结果仍与无限精度一致。
旧形态是每一项都舍入到 24 位，两者不在一个量级上。

### 3.4 特殊值旁路

定点窗口里没有 NaN 和 Inf 的位置。旧形态靠 `fp32_add` 的特殊值通路处理它们，
加法器一撤，那条通路就断了。

改成三个 sticky 标志：见过 NaN、见过 +Inf、见过 -Inf。末项组装时优先出，
NaN 或者正负 Inf 都见过就出 qNaN，单向 Inf 出对应符号的 Inf，否则才走定点结果。
判定所需的分类位在乘法器第 1 级已经算好，直接引出来，不用另写一套。

还有一个容易漏的角落：结果精确得零时符号是什么。IEEE 的规矩是全部参与项都是负零
才出 -0，其余一律 +0，所以还要一个零项符号的与，和一个有没有非零项参与过的标志。

### 3.5 乘法器拆级

把 `fp32_mul_pipe` 拆成两个模块：第 1 级出未舍入的原始积，第 2 级做规格化与舍入。
标量 FPU 的乘法指令仍走两级，融合乘加通路只取第 1 级。

拆模块而不是给乘法器加一组旁路输出端口，是因为后者会在全仓 16 处例化上
各留 7 个未连端口，凭空多出上百条 lint 告警。

这一步单独测得的收益在 5.2 节。

### 3.6 两个移位器合成一个

对阶要一个 88 位右移器，规格化要一个 88 位左移器。两者是同一件东西的两个方向，
而且从不同拍使用：对阶在累加期，规格化在末项落定之后三拍。
所以共用一个桶形右移器，左移由输入输出两侧的位序翻转实现，是纯连线：

```
   对齐期    尾数放进 TW 位域顶端，右移 (B - E)
   规格化期  累加值绝对值位序翻转后右移 lz，再翻回来，等价于左移 lz
```

不做这一步面积还要再多一截。这是本模块面积上的主要杠杆。

## 四、遇到的问题

### 4.1 第一版的固定基准，300 组里垮掉 95 组

**第一现场。** 第一版拿第一项定基准：`B = 第一项的阶码 + 24 位上方裕度`，
后面的项按 `B - 自己的阶码` 右移进窗口，比第一项大得多的项装不下就饱和并置标志。
用本仓的随机点积激励跑，300 组里 95 组置了那个饱和标志。

**解读。** 饱和之后结果不是不够精确，是错的。95/300 这个比例也说明它不是边角情形
而是常态：随机向量里第一项恰好是最大项的概率本来就只有 1/K。

**根因。** 一个点积内乘积的阶码跨度可以有几十位，以第一项为锚的窗口，
窗口之上的部分整个丢掉。这不是裕度取 24 位还是 32 位的问题：
FP32 的阶码域有 254 个档，要覆盖全域得把窗口做到 Kulisch 那么宽，
约 280 位，每条 lane 一个对齐移位器，摆不下。

**修法。** 基准改成跟着运行最大值走，就是 3.2 节那套不变式。

**方法。** 定点窗口的宽度要按输入的动态范围定，不能按直觉的"够用"定。
判断一个窗口够不够宽，量的是撑破的比例，不是最大误差。

### 4.2 第一版切少了，WNS 掉到 -3.83

**第一现场。** 第一版把基准推导、移位量、桶形移位、取二补数放在一拍里，
取模与前导零检测放在一拍里，规格化移位、舍入、组装放在一拍里，总延迟 5 拍。
仿真全绿，实现出来 WNS = -3.83 ns、TNS = -5271 ns，不产 bitstream。

**定位。** 离线综合报出来的关键路径，单条 lane，20 ns 约束：

```
   exp_r --> need --> raise/dq --> base_nxt --> sh_s --> sh_big/sh_al
         `--> 88 位桶形右移器（4 级 LUT6）--> 取反 --> term_q

   36 级逻辑，24.07 ns（逻辑 10.5 ns，布线 13.5 ns）
```

**根因。** 四个 12 位加减器串在一起，后面再挂一个 88 位的桶形移位器，一拍装不下。

**修法。** 按下面切开之后，同一条锥子降到 18 级、12.1 ns：

| 级 | 内容 |
|---|---|
| A | 项源选择、基准推导、上调量、移位量 |
| B | 桶形移位、取二补数 |
| ACC | 累加，8 选 1 移位加 88 位加法 |
| Na | 取模、前导零检测 |
| Nb | 规格化移位，复用同一个移位器 |
| Nc | RNE 舍入、组装 |

**方法。** 一条锥子的级数不能按"里面有几个运算"估，要按实现报出来的逻辑级数算。
四个串起来的 12 位加减器看着不起眼，它们后面挂什么才决定这一拍装不装得下。

### 4.3 切级之后，acc_load 那一拍算出一次假的上调

**第一现场。** 切级顺带踩了一个坑，判据当场抓到：300 组里 75 组的 `win_rescale`
与金标准不符，2 组结果差 1 ULP。

**根因。** `acc_load` 那一拍基准是重新锚定的，而 `base_r` 里还是上一个 tile 的值。
切级之前那一拍不会走到基准推导；切级之后 psum 与乘积走了同一条路，
于是那一拍会拿旧基准算出一次上调，`win_rescale` 被误置，psum 也移错位。

**修法。** 引一个信号，在 `acc_load` 那一拍把"基准已落定"当成假。

**方法。** 把两条通路合并成一条，要连它们的初始状态一起合并。
这一条能被抓住，是因为 `win_rescale` 这个精度提示进了判据：
它在产线上没有消费者，但它是这个 bug 唯一的可观测点。
结果只差 1 ULP 的那 2 组，单看结果很容易当成容差放过。

### 4.4 进位保存累加器，实测判死

环里那个加法器还可以再快：把累加器存成和向量加进位向量，
环里换成 3:2 压缩器不做进位传播，末项之后再走一次进位传播加法。
这是脉动阵列 PE 的常规结构，在 ASIC 上换的是关键路径。

在 7 系列上它是净亏的。单条 lane 离线综合，Vivado 2025.2：

| 累加器实现 | LUT | FF |
|---|---:|---:|
| 行波进位 | 1408 | 386 |
| 进位保存 | 1751（+24.4%） | 471（+22%） |

原因是资源形状不对：N 位行波进位加法器映射成 N 个 LUT6 加 N/4 个 CARRY4，
进位链走专用布线；而 N 位 3:2 压缩器没有专用资源可用，和位一个 LUT6、
进位位一个 LUT6，还要多一组 N 位寄存器，末项之后仍要一次 N 位 CPA。
换来的时序余量在 20 ns 的周期下用不上。

默认取行波进位。

#### 判死的理由后来换了一条，而换掉的那条是本章最值得记的一次假绿

本节原来还有一句：**"两档的结果逐位相同，用的是同一份金标准跑两遍，
所以这是一次干净的等价改动，只是不启用。"**

这句话是错的，而且当时有判据、判据是绿的。

两档并不逐位等价。基准上调时，进位保存档的和向量与进位向量**各自**算术右移，
分别截断再相加——这不等于先相加再截断。差别只在被截掉的那一位上，
所以只有在低位重新成为主角的时候才看得见，也就是抵消。
换上 cancel 激励，64 组里 10 组不一样。

**判据没错。** 它老老实实比对了它拿到的那份激励——常规激励，走不到抵消路径。
错的是**没人规定过"两档逐位相同"这句话该用什么激励去验**。
"同一批向量在两档下结果相同"这条判据，只有在这批向量走热了差异路径时才有证伪力；
否则它量的是"两条路都没被走到"。

这一条后来直接催生了第一章那把尺子：一条声称是承诺的话，得先说清楚
"拿什么去验它"，否则它就只是一句没人负责的话。

**处置。** 这一档撤出支持集合，例化期检查直接挡住 `UseCarrySave != 0`
（做法见 4.6），那一档回归随之删除。上面那组面积数仍然有效，
判死的理由从"净亏且等价"改成**"净亏且不等价"**。

### 4.5 WHS 变薄 0.032 ns，记在这一步头上

最差 hold 路径换了位置。基线在老病灶上，现在是
`PE_LANE[20].u_mac/mac_out_reg[6]` 到 `u_pe_array/result_reg_reg[358]`，
就是新 MAC 的输出寄存器到阵列结果寄存器那一跳。

0.018 ns 仍为正、时序 MET，但它比基线薄，而 hold 违例的症状是上板乱码不是跑不起来，
见[第九章](09-FP32数据通路的hold时序修复.md)。本工作点不上板，
这一条作为已知风险如实记在这里，不当成验过了。

### 4.6 项数上限只有仿真判据，而那条判据自己会误报

一个 tile 内进窗口的项数不能超过 255（求和增长位 8 位给的**已认证上限**）。
措辞要准：超了不是立刻绕回——实算下来真实绕回点在万数量级——
而是进入没有论证过的区域。

这条限制原来只有一道防线，就是仿真期的 C5 断言。它有两个毛病。

**第一，它数错了。** C5 数的是复位以来的**累计**项数，不是当前 tile 的。
于是一个完全合法的满额分块，只要前面已经跑够了量，就会被误报。
一条会对合法输入报警的断言，用不了几次就会被当成噪声忽略掉，
那它就等于不存在了。
修法是改成数当前 tile：`acc_load` 那一拍重置，psum 也算一项。
判据加了两档——255 项满额必须为 0、256 项必须报；撤销修复则满额那档当场红。

**第二，它来得太晚。** 分块深度是一个例化参数，写死在调用方的常量里，
综合之前就完全确定。让它一路跑到仿真才发现，属于**能在编译期查却没查**，
按第一章的 A 档这是缺陷，而且零面积可修。

修法是给模块加一个 `MaxTerms` 参数，调用方声明自己每 tile 最多喂多少项，
超过已认证上限就在例化期报错，用的还是本仓那个"例化一个不存在的模块"的手法
（第 3 节那几条检查同款）。矩阵阵列传的是 `KAccumDepth + 1`，psum 也算一项。

这里踩到一个判据设计的小坑，值得记：原本打算的判据是"去掉 `MaxTerms != 0`
这个短路条件后，不传参的例化必须报错"。**这条不成立**——不传参时 `MaxTerms`
是 0，去掉短路之后判的是 `0 > 255`，仍然为假。短路条件在这里不是判据的对象，
它只是让"不声明"的调用方保持现有行为。换成三点边界才量得准：
`MaxTerms` 取 0（不声明）与 255（认证上限）必须编译通过，取 256 必须报错。

两条防线各管一段：**例化期的 `MaxTerms` 管"调用方要不要得起"，
仿真期的 C5 管"跑起来之后有没有真的超"**。

## 五、结果

### 5.1 精度

判据分两层。第一层是逐位判据：用 Python 大整数精确复刻硬件的窗口累加，
硬件必须与它逐位相同。第二层是证据：用分数精确求和后一次正确舍入，
检查第一层的窗口在所测样本中是否够宽，不构成全输入域证明。两层都在 `sim/mac_win_model.py`。

四种激励各 300 组点积，K = 64，与无限精度参考的最大 ULP：

| 激励 | 抬基准的比例 | 定点窗口 | 旧形态（同序 IEEE） |
|---|---:|---:|---:|
| 常规，阶码跨度到 80 位 | 259/300 | 0 | 1168 |
| 极小，1/4 元素落在 denormal 区 | 246/300 | 0 | 164 |
| 宽跨度，乘积阶码跨 210 位 | 300/300 | 0 | 79 |
| 特殊值，NaN / ±Inf / ±0 / Inf×0 | — | 逐位相符 | — |

窗口形态在这三档上全部拿到正确舍入的结果，也就是与无限精度求和后再舍入完全一致。

跨 tile 一档，K = 256 分 4 块、块间经 FP32 回灌，100 组：

| 形状 | 定点窗口 | 旧形态 |
|---|---:|---:|
| 256×256 | 68 | 377 |

这一档不是 0，因为那几次 FP32 回灌是架构决定的，不属于窗口的账。

### 5.2 融合那一步单独的收益

同一批向量、同一把参考尺子，只把乘积侧的舍入开关拨一下：

| 乘积侧 | 与无限精度的最大 ULP |
|---|---:|
| 舍入一次再进窗口 | 1027 |
| 不舍入，48 位直接进窗口 | 0 |

也就是说，上表"常规"那一档剩下的全部误差，都是乘积侧那一次舍入造成的。

### 5.3 延迟与吞吐

末项 `prod_valid` 到 `out_valid`：

| 构型 | 拍数 | 组成 |
|---|---:|---|
| 融合 | 7 | 乘法级 1（1）+ 对阶（2）+ 累加（1）+ 规格化舍入（3） |
| 不融合 | 8 | 乘法两级（2）+ 对阶（2）+ 累加（1）+ 规格化舍入（3） |

喂积间隔从 4 变 1，旧形态靠 4 个累加器交错才做到 1。
总延迟变长了而吞吐没变：一个 tile 有 64 项，这几拍只落在尾巴上。

### 5.4 面积与时序

| 数 | 基线 | 本工作点之后 | 变化 |
|---|---:|---:|---|
| WNS | 0.053 ns | 0.460 ns | 变好，但不是这一步的功劳，见下 |
| WHS | 0.050 ns | 0.018 ns | 变差 0.032 ns，见 4.5 |
| LUT | 64890（48.21%） | 81729（60.72%） | +16839（+25.9%） |
| FF | 37536（13.94%） | 43540（16.17%） | +6004 |
| BRAM | 192（52.60%） | 192 | 不变 |
| DSP | 137 | 137 | 不变 |

分层，`report_utilization -hierarchical`：

| 层 | 基线 LUT / FF | 本次 LUT / FF |
|---|---:|---:|
| 每条 lane `fp32_mac_unit` | 742 / 360 | 1262 / 552 |
| `gemm_pe_array`，32 条 lane | 23850 / 13587 | 39781 / 19595 |
| `gemm_top` | 26013 / 16139 | 43043 / 22145 |

WNS 变好的那 0.407 ns 不能记在这一步头上。最差 setup 路径两次都是同一条：
`u_vse/u_streamer/g_addrgen[0].u_ag/idx_reg[0][4]` 到 `s_addr_reg[1][31]`，
在向量引擎的地址生成器里，好几个工作点之前就在那儿，本工作点一行没碰它。它变好纯粹是面积涨了之后布局重来的结果。
这正是"删逻辑不等于给余量"的反向：加逻辑也不等于吃余量，
两个方向上时序都不能靠改了什么去推，只能靠量。

面积是这一步的主要代价：每条 lane 多 520 个 LUT，也就是七成。
省下来的是每条 lane 一个三级 IEEE 加法器、3 个多余的累加器和一份归约控制，
但抵不过新增的 88 位桶形移位器与 88 位累加器。

### 5.5 调用契约

模块对调用方有三条要求，网表里不检查，仿真时有断言接住：

1. 相邻 `prod_valid` 的间隔不小于 `FP32_MAC_PACE`，现在是 1，恒成立。
2. `last` 与末项 `prod_valid` 同拍。
3. 末项之后到 `out_valid` 之前不许再喂积。

第三条的区间容易写窄。它从末项就开始，不是从模块内部某个忙标志置起才开始：
那之后流水线里还有在飞的项，此时一个带 `acc_load` 的新首项会先清空累加器，
再被在飞的项污染，而模块内部没有任何忙标志是高的。
只盯内部忙标志的断言抓不到这一段，所以 `tb_fp_lat` 对这个区间的两端各注了一次错。

还有一条不是给调用方的，是给参数的：一个 tile 内进窗口的项数不能超过
**已认证的上限**，8 位求和增长位对应 255 项。超了不是立刻绕回，
是进入没有论证过的区域。这一条有两道防线，例化期一道、仿真期一道，
两道都返过工，见 4.6。

### 5.7 还欠什么

- `win_rescale` 报的是本 tile 发生过换基，不精确统计非零丢位或量化误差。它是精度提示不是错误，
  假阳性率很高，产线上没有消费者，在 `gemm_pe_array` 里显式空连，
  单元级判据在 `tb_mac_win.v` 里量它。
  **后来从它里面单独引出了一位 `mac_prec`**，只报灾难性的那一类（旧和被整个丢弃），
  那一位有消费者，见[第十一章](11-定点窗口累加器的误差边界.md)第六节。
- 第八章的 `FP32_MAC_PACE = FP32_ADD_LAT + 1` 与交错累加器已经作废，
  那一章保留为历史记录。
- 旧交错归约次序不再需要复刻，`gemm_defs.vh` 的 `GEMM_MAC_ACC` 宏随之删除；
  窗口截断及跨 tile FP32 回灌仍可能受输入次序影响，不能泛化为任意重排等价。
- 反馈环 TODO仅保留面积增幅接受结论与提交仓同步；
  本工作点明确不上板，4.5 的 hold 风险不冒充板上验收。
- 窗口精度闭环保留五类误差边界的独立工作，
  本章随机样本的 0 ULP 不作为该项已经完成的证据。

  **2026-09-06 补记：那件工作做完了，见[第十一章](11-定点窗口累加器的误差边界.md)。**
  结论是本章那句"最大 ULP 为 0"需要限定：它在本章这批激励上成立，
  但窗口在一种确定的构造下会稳定地差 1 个 ULP（被挤出窗口的位里含着决定进位的信息）。
  三类误差有可算的界、够不着结果的最低位；一类是结构的固有代价；
  跨 tile 那一类不属于累加器。面积那一侧的收尾见[第十二章](12-不改结构的面积回收.md)。
