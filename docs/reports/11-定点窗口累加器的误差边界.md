# 定点窗口累加器的误差边界

## 一、动机

[第十章](10-FP32乘累加换成定点窗口累加器.md)把累加器换成了一把定点尺子，
一个 tile 内只在末项舍入一次。那一章的验收写着一句话：

> 现有随机与定向用例相对无限精度参考的最大 ULP 为 0。

这句话是真的，但它回答的问题比它看起来小。它说的是「这批激励没测出误差」，
不是「这个结构不会有误差」。两者的差别在于：随机激励打得到的地方，
和一个结构能出错的地方，往往不是同一片区域。

尺子是有限长的。把一个数移到尺子外面，它就没了。所以问题不该问「误差多大」，
该问「什么东西会被移出去，移出去之后还看不看得见」。

这一章把「被移出去」这件事拆成五条路，一条一条量。量完之后结论是：
其中三条在数学上就摸不着，一条会稳定地差一个最低位，还有一条根本不是尺子的错。

## 二、五条路

一项要进尺子，得先右移到共同的刻度上。丢信息的机会有这么几处：

```
   进来一项 ---> 右移对齐 ---> 加进累加器
                    |
                    +--(1) 移出去的低位没了

   来了个更大的项 ---> 抬基准 ---> 整个累加器右移
                                        |
                                        +--(2) 累加器的低位没了
                                        +--(3) 累加器是负数时，截断方向与正数相反

   来的项大得离谱 ---> 基准重锚 ---> 累加器清空
                                        |
                                        +--(4) 旧的和整个没了

   一个 tile 算完 ---> 结果转回 FP32 ---> 当下一个 tile 的初值
                                             |
                                             +--(5) 每个 tile 边界舍一次
```

这五条的量级差着几十个二进制位。只报一个总的 ULP，等于把五件事搅成一团，
既不知道该修哪一条，也不知道修完了没有。所以逐位金标准里给每条挂了一个计数器，
跑一遍就知道这一批激励把哪几条走热了、每条走了多少次。

## 三、前三条为什么摸不着

先看尺子的刻度是怎么排的。当前的尺子是 88 位，一项的尾数占 48 位，
最大的那一项被放在靠上的位置，它下面留出来的就是保护区：

```
   位序  87                                                      0
         |  求和位  |      最大项的尾数 48 位      |    保护区     |
                    ^                            ^
                    最大项右移 sh 位之后落在这里     保护区宽 32 - sh 位
```

一项要丢位，它得低到整个滑出这块区域，也就是它自己的移位量超过 `TW - 48 = 32`。

关键的一步是估被丢掉的那些位有多重。不必知道它们落在第几位，
只要知道**它们全都在窗口最低位以下**，而窗口最低位的实数权重是固定的一个量。
记当前基准为 `B`，那个权重是

```
   λ = 2^(B - 205)
```

基准的不变式给出 `B` 与最大项 `M` 的关系，代进去得 `λ ≤ 2^-55 · M`。
每一项对齐丢位、每一次换基，各引入不超过一个 `λ`。`N` 项合计：

```
   |Z − S| < 2N·λ ≤ 2^-46 · M ≤ 2^-46 · A
```

`Z` 是末项舍入之前的窗口累加值，`S = Σ tᵢ` 是精确和，`A = Σ |tᵢ|` 是输入的绝对和。
契约要求的是 `2^-32 · A`，这条界比它还有 14 位余量——**所以不必为了
「刚好够 32 位」去缩窄窗口。**

这条界是可以验的。构造 254 个同号、尾数全一、指数刚跨过丢位门槛的小项，
让丢位量尽可能大，跑四百组，最大 ULP 是零。换基那两条（第 2、3 条）同理：
让累加器在正负之间反复换基两百多次，误差同样是零。
更硬的一次验证是用一个独立的大整数模型逐前缀检查：2352 组，含 5093 次换基与
1221 次清空，`|Z−S| · 2^32 / A` 实测最大 `3.36e-07`。

### 3.1 第一版的推导是错的，虽然结论没变

上面这条界是第二版。第一版是这样推的：最大项的移位量恒为 `WinUp = 8`，
所以它的尾数固定落在第 71 到 24 位，下面固定有 24 位保护位；结果的最低有效位
就在第 48 位；一个 tile 最多 255 项，于是累计丢失量小于 `255 / 2^48`，
约 `2^-40` 个 ULP。

**结论方向没错，前提是假的。** 基准不是精确锚在 `Emax + WinUp` 上，
它按 `WinG = 16` 位的量子往上抬，所以最大项的移位量在 8 到 23 之间取值，
保护位最少只剩 9 位。上面那个独立模型实测到的最大移位量正是 23。
第二条毛病更隐蔽：它默认结果的最低有效位落在第 48 位，
而这在发生抵消时根本不成立——抵消之后结果变小，它的最低有效位往下走。

**为什么这值得单独写一段。** 一个错误的推导配一个正确的结论，比一个错误的结论
更难发现，而且危害不小：使用者不会照抄结论，他会照着推导去算自己的数据。
「保护位固定 24 位」这句话一旦被用来估自己那批数据的余量，
就会在窗口抬过基准之后偏出 14 位。

换掉的第二版不依赖任何「固定位置」：它只用基准的不变式，
所以窗口怎么抬、结果怎么抵消，那条不等式都还在。这一点第五节还会再用一次。

第 3 条还多一个问题要回答。二补码的算术右移对负数是向下取整，对正数相当于
向零截断，两个方向不一样，会不会积出系统性偏差？验法是把整组向量取反再跑一遍，
看两边的结果是不是严格互为相反数。六十四对，一对不差。

更硬的一个证据来自反面：把金标准里的算术右移改成对称的向零截断，
再和硬件比 —— 一位都不变。**一条路径改坏了都看不出来，说明它本来就不影响输出。**

## 四、真会差一个最低位的那一个

上面说的是「丢掉的量太小」。但有一种情形，丢掉的量确实小，
丢掉的**信息**却不小：当被丢掉的那一点点，恰好是决定进位方向的那一点点。

舍入到最近偶数有一条规则：正好卡在两个可表示数中间时，往偶数那边靠。
判断「是不是正好在中间」靠一个粘滞位，它记的是「中间点之下还有没有非零的东西」。

现在构造这样一个点积：

```
   第一项   M                 一个尾数末位是偶数的数
   第二项   M 的半个最低位     正好落在两个可表示数的中点上
   第三项   一个极小的数       小到整项被移出尺子
```

精确的和严格大于中点，正确答案是进位。但硬件把第三项整个丢了，
它看到的和正好是中点，于是按规则往偶数靠，也就是不进位。差一个最低位。

这一族六十四条里有五十六条稳定地差一个 ULP。而此前所有的随机激励，
一次都没有打到过它。

要不要修？修法是让移位器额外报出「移出去的位里有没有非零的」，并进粘滞位。
这个修法有两个问题。

一是它不是无条件正确的。一个布尔量恢复不了被丢掉那部分的符号，
正负项抵消的时候，它可能把结果推向错误的方向。

二是这个单元承诺的本来就不是「正确舍入」，而是「一个 tile 内只舍入一次」。
截断发生在舍入之前，是尺子长度决定的，不是舍入方式决定的。
真要正确舍入，正解是把尺子加长到覆盖整个指数范围，让加法完全精确，
而不是给有限长的尺子打补丁。

所以这一条的处置是：写进契约，标明边界，不修。

## 五、抵消：把免责声明换成一条仍然成立的界

第 4 条是这样一个序列：

```
   先累加出一个不为零的小和   s
   然后来一个巨大的项         X       旧的和相对它可以忽略，被清掉
   再来一个                  -X       两个大项精确抵消
```

正确答案是 s，硬件给零。这不是差几个最低位，是整个结果没了。

这一条不需要「清空」那一档才成立。把差距调小一点，走普通的抬基准，
s 被右移到尺子外面，结局一样。

要说清楚的是，**这是结构的固有代价，不是缺陷**。任何「基准跟着最大值走、
尺子长度有限」的累加器都有这一条。消除它的办法学界早有：把尺子加长到
覆盖 FP32 的整个指数范围，任何加法都不丢位，代价是尺子长好几倍。
那是另一个设计点，不是这个设计的 bug。

所以这一条也是写进契约。但**怎么写**有讲究，第一版写法后来被换掉了，
这件事比这条损失本身更值得记。

第一版写的是「灾难性抵消场景不在本单元的误差契约内」。这是一句**免责声明**：
它把一整类输入从承诺里摘出去，使用者拿它做不了任何事——他没法判断自己的数据
算不算「灾难性」，只能自己去试。

第二版换成第三节那条不等式，抵消场景不再需要豁免：

```
   对有限项 S = Σ tᵢ、A = Σ |tᵢ|，恒有 |Z − S| ≤ 2^-32 · A
```

`S` 变小的时候 `A` 不变小，所以**抵消得再厉害，这条不等式照样成立**。
上面那个 `[s, X, -X]` 的例子代进去就明白了：`S` 接近零，`A` 是 `2|X| + s`，
误差被 `A` 罩着，一点也没超。使用者拿到的是一个恒成立的界，
而不是一句「这种情况我们不管」。

代价是验收方式要跟着改：**按绝对误差与输入尺度检查，不能要求接近零的 `S`
仍保持固定的相对误差**。那种要求任何有限窗口的累加器都做不到。

这里可以提炼成一条通用的判断：**免责声明不如一个仍然成立的界。**
一条偏离能不能接受，不看误差大小，看它有没有规则——能用一句不带「通常」
「大多数」的话说清楚、使用者据此能判断自己是否受影响，就是取舍；
说不清楚就是缺陷，哪怕每一次计算都是对的。

## 六、把灾难性的那一类单独引出来

上一节说的是「写清楚」。但契约写得再清楚，也只能让使用者**读文档自己判断**。
第 4 类还能再往前走一步：让硬件在运行时告诉他踩没踩上。

原来的窗口累加器只有一个「基准移动过」的信号，它把两件性质完全不同的事或在一起：

- **普通抬基准。** 移出去的多半全是零，无损。假阳性率高到这个信号几乎恒为真。
- **基准重锚。** 新来的项比当前基准高出整个累加器的宽度，**旧的累加和被整个丢弃**，
  正是第 4 类，是灾难性损失确定发生过的一次。

两者混在一起的后果是：硬件确切知道「这个分块的结果可能整个是错的」，却没告诉任何人
——那条线在阵列里根本是悬空的。一个信号如果假阳性率高到永远为真，它就没有信息量；
把高假阳性的那部分滤掉，剩下的才能当告警用。

所以把重锚事件单独引出一个端口 `mac_prec`，逐分块 sticky，
在阵列里或成一位、汇进状态寄存器，写控制寄存器清除。

**代价出乎意料地小。** 单 lane 离线综合 1277 到 1278 个 LUT、495 到 496 个 FF，
各多一个；进位链、逻辑级数与最长路径的起终点都不变。
因为「要不要重锚」这个条件本来就已经算出来供清空用了，多的只是一个粘滞触发器。

**边界必须写死：这一位只覆盖「旧和被整个清掉」，不覆盖普通对齐右移丢掉的非零低位。**
后者要挂变量掩码，是另一笔账（见第十二章第 4.5 节，实测判死）。
所以文档里只能叫它「基准重锚事件」，不能写成「精度损失检测」。

### 6.1 这条线的判据，反面才是核心

**核心判据不是「构造重锚能让它置位」，而是它的反面：普通抬基准时它必须不置位。**
没有这一条，它就退化成第二个「基准移动过」，白加一个端口。

集成级同理，而且两个方向都要有。七种分块形状下这一位恒为 0，
只能说明它没有假阳性；再加一档极端阶码差的构型让它置位，
才能证明这条线真的连到了寄存器上。只验前者的话，
**一条断线看起来和恒 0 一模一样。**

### 6.2 写清除这一条抓到一个真 bug

第一版把状态位挂在电平上。而阵列那一路要到下一个分块起头才自清，
于是软件清掉的下一拍又被置起，清不掉。改挂上升沿。

值得记的是：同一份代码里，搬运层的错误位早就因为完全一样的理由挂了边沿，
注释还写着原因。**知道这个坑的人和写这一行的人是同一个，仍然踩了进去。**

## 七、第五条不是尺子的错

跨 tile 那一条要单独说，因为它经常被读反。

一个 tile 算完，结果转回 FP32 再当下一个 tile 的初值。转一次舍一次。
K 越长，tile 越多，舍的次数越多。测出来是这样：

| K | tile 数 | 窗口累加器 | 逐项舍入的旧形态 |
|---|---|---|---|
| 64 | 1 | 0 | 339 |
| 128 | 2 | 8 | 85 |
| 256 | 4 | 16 | 108 |
| 512 | 8 | 97 | 546 |

左边那一列自己看，像是「K 大了就不准」。加上右边一列才是完整的：
同样的输入，同样的 K，窗口形态比旧形态好五到十倍。
增长的那部分是分块这件事本身的代价，是部分和走 FP32 这个接口决定的，
换成什么累加器都一样。

还有一件事值得写下来：**不要给这张表配一个「按块数算」的上界。**
分块求和的误差正比于条件数，也就是各项绝对值之和除以总和的绝对值。
抵消得越厉害，条件数越大，误差越大，而条件数是没有上界的。
所以任何形如「n 个 tile 最多 n 个 ULP」的说法都是错的。
真要设闸门，只能拿实测值加余量当回归基线，并且在注释里写明它是基线不是定理。

## 八、判据自己也要被验一次

上面每一条结论背后都有一条判据。那么判据本身对不对？

办法是把金标准改坏，看判据红不红。准备了五个改法：给移出位补粘滞、
把换基改成对称截断、清空那一档改成不清、末项舍入改成截断、把尺子加长八位。
每一个都是对某条路径的真实改动，硬件一字未动，所以「硬件与金标准逐位相同」
这条判据必须当场红。

第一次跑，五个里有四个没红。

四个都不是判据坏了，是配错了激励：

- 对称截断配到了「反复换基」那组上。可那组的丢位量在结果最低位之下四十位，
  换个截断方向照样看不见。得让换基之后发生抵消，被丢掉的低位重新成为主角，
  才看得见。
- 「清空那一档改成不清」的第一版写法，是把旧的和右移到尺子最底下再留着 ——
  移完就是零，和清掉是同一个结果。改成原地不动才是有效的改坏。
- 「舍入改成截断」配到了中点那组上。那组每一条都精确卡在中点、尾数取偶，
  往偶数靠和直接截断都是不进位，两种舍入给同一个答案。
- 「尺子加长八位」配到了长串小项那组上。那组丢的位本来就看不见，加长也白加。

这里还有一层更隐蔽的：换基那条改坏之后一开始怎么都红不了，
追下去发现是激励构造的问题——单精度数换算到定点尺子上时，低二十四位是零填充，
所以只有初值、没有真乘积的累加器，右移多少位都一位不丢。
必须先垫两个真正的二十四位乘二十四位的乘积，累加器的低位才有东西可丢。

调整之后五个全红。

这一轮的收获不止是「判据现在有效了」。它同时是第三节那个结论的独立证据：
**有三条路径，改坏了都看不出来。** 这比「测下来是零」更强。

### 8.1 两层参考共用一份代码，等于只有一层

金标准是两层：第一层逐位复刻硬件，第二层用分数精确求和后一次正确舍入。
两层比对是这一章大部分数字的来源。

但这两层原来共用同一份「位型解释」与「乘积构造」代码——同一个拆包函数，
同一个把 `a × b` 变成 `(mant48, E)` 的函数。共用的后果很直接：
**那份代码本身若有错，两层会一起错，「两层都过」永远发现不了它。**
一个参考模型的价值全在独立性上，共用输入侧就等于只有一层。

修法是把第二层的位型解释、乘积构造与特殊值分类各写一份，不再调用第一层的函数。
拆分前后所有归因数字逐个不变（说明拆的时候没引进新错），
然后把第一层的乘积阶码改坏一位——两层对拍从 maxULP 0 变成 139809444。
这个数字才是「两层现在真的独立了」的证据。

### 8.2 注错见红，只在被注入的那条路径可观测时才成立

验上面那件事的时候先失败了一次。第一次改坏的是 48 位积的**最低位**，
期待对拍变红，结果不红。

原因就是第三节：那一位在结果有效位之下 40 位，本来就观测不到。
改成阶码差 1，立刻红。

这和本节开头那次「五个里四个没红」是同一件事的两面，
可以合成一条能带走的判断：**判据的输入必须覆盖它声称覆盖的边界。**
一次注错不红，有两种可能——判据烂了，或者那条路径在当前激励下不可达。
不区分这两种，就会把第二种误当成第一种，去修一个没坏的判据。

### 8.3 一个环境层面的坑

Python 的字节码缓存按**秒级**时间戳判断源文件变没变。
注错、跑、恢复、再跑这一串动作如果发生在同一秒内，第二次跑的仍是注错版本，
现象是「恢复之后还是红的」。这不是判据的问题，但足以让人误判成判据坏了，
然后去改一个本来是对的判据。

## 九、最后

这一章只加了一个粘滞触发器，其余没改一行硬件。它做的是把一个「测下来是零」
的结论，换成一组带边界、带反例、带反证的说明：

- 三条路径在数学上够不着结果的最低位，有可算的界，改坏了也看不出来。
- 一条会稳定地差一个最低位，构造是确定的，处置是写进契约而不是打补丁。
- 一条是结构的固有代价，学界早有更贵的解法，不在这个设计点上。
  它从「免责声明」换成了一条在抵消时仍然成立的不等式，
  并且额外引出一位运行时信号，让使用者不必读文档就知道自己踩没踩上。
- 一条根本不属于累加器，是分块接口的账，而且同样条件下仍比旧形态好一个数量级。

对一个准备开源的单元来说，这组说明比那句「最大 ULP 为 0」有用得多。
后者会被读成「精确」，然后有人在灾难性抵消的场景里踩上去。

还有一条是关于这一章自己的。第一版的界结论对、推导错（第 3.1 节），
两层参考共用输入侧代码（第 8.1 节），五个注错里四个配错了激励（第八节）——
**这些都不是硬件的问题，是「拿什么判断硬件对不对」的问题。**
它们一条也不会让回归变红，却会让所有的绿失去意义。

复现全部数字：`bash sim/run_mac_audit.sh`。
