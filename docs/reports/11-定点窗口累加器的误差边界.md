# 定点窗口累加器的误差边界

## 一、动机

[第十章](10-FP32乘累加换成定点窗口累加器.md)把累加器换成了一把定点尺子，
一个 tile 内只在末项舍入一次。那一章的验收写着一句话：

> 现有随机与定向用例相对无限精度参考的最大 ULP 为 0。

这句话是真的，但它回答的问题比它看起来小。它说的是「这批激励没测出误差」，
不是「这个结构不会有误差」。两者的差别在于：随机激励打得到的地方，
和一个结构能出错的地方，往往不是同一片区域。

尺子是有限长的。把一个数移到尺子外面，它就没了。所以问题不该问「误差多大」，
该问「什么东西会被移出去，移出去之后还看不看得见」。

这一章把「被移出去」这件事拆成五条路，一条一条量。量完之后结论是：
其中三条在数学上就摸不着，一条会稳定地差一个最低位，还有一条根本不是尺子的错。

## 二、五条路

一项要进尺子，得先右移到共同的刻度上。丢信息的机会有这么几处：

```
   进来一项 ---> 右移对齐 ---> 加进累加器
                    |
                    +--(1) 移出去的低位没了

   来了个更大的项 ---> 抬基准 ---> 整个累加器右移
                                        |
                                        +--(2) 累加器的低位没了
                                        +--(3) 累加器是负数时，截断方向与正数相反

   来的项大得离谱 ---> 基准重锚 ---> 累加器清空
                                        |
                                        +--(4) 旧的和整个没了

   一个 tile 算完 ---> 结果转回 FP32 ---> 当下一个 tile 的初值
                                             |
                                             +--(5) 每个 tile 边界舍一次
```

这五条的量级差着几十个二进制位。只报一个总的 ULP，等于把五件事搅成一团，
既不知道该修哪一条，也不知道修完了没有。所以逐位金标准里给每条挂了一个计数器，
跑一遍就知道这一批激励把哪几条走热了、每条走了多少次。

## 三、前三条为什么摸不着

先看尺子的刻度是怎么排的。当前的尺子是 88 位，一项的尾数占 48 位。
最大的那一项右移的位数是固定的，于是：

```
   位序  87        79                    32                     0
         |  求和位  |      最大项的尾数      |     保护位          |
                    |<------- 48 位 ------->|<---- 24 位 ------->|
                                      结果的最低有效位在这里 ^
                                      （第 48 位）
```

两件事从这张图直接读出来：

第一，一项要丢位，它得比最大项小 24 位以上，不然它整个落在保护区里面。

第二，也是关键的一条：**丢掉的位全部在第 0 位附近，而结果的最低有效位在第 48 位。**
一项最多丢掉不足一个最低刻度的量。一个 tile 最多累加 255 项（这是求和位宽给的上限，
模块内有断言守着），所以丢掉的总量小于 255 个最低刻度。

把这两个数放一起：

```
   累计丢失量  <  255 / 2^48  个 ULP  ≈  2^-40 个 ULP
```

也就是说，就算每一项都在丢位、丢的还都朝同一个方向，加起来也够不着结果的
最低位的一万亿分之一。

这条界是可以验的。构造 254 个同号、尾数全一、指数刚跨过丢位门槛的小项，
让丢位量尽可能大，跑四百组，最大 ULP 是零。换基那两条（第 2、3 条）同理：
让累加器在正负之间反复换基两百多次，误差同样是零。

第 3 条还多一个问题要回答。二补码的算术右移对负数是向下取整，对正数相当于
向零截断，两个方向不一样，会不会积出系统性偏差？验法是把整组向量取反再跑一遍，
看两边的结果是不是严格互为相反数。六十四对，一对不差。

更硬的一个证据来自反面：把金标准里的算术右移改成对称的向零截断，
再和硬件比 —— 一位都不变。**一条路径改坏了都看不出来，说明它本来就不影响输出。**

## 四、真会差一个最低位的那一个

上面说的是「丢掉的量太小」。但有一种情形，丢掉的量确实小，
丢掉的**信息**却不小：当被丢掉的那一点点，恰好是决定进位方向的那一点点。

舍入到最近偶数有一条规则：正好卡在两个可表示数中间时，往偶数那边靠。
判断「是不是正好在中间」靠一个粘滞位，它记的是「中间点之下还有没有非零的东西」。

现在构造这样一个点积：

```
   第一项   M                 一个尾数末位是偶数的数
   第二项   M 的半个最低位     正好落在两个可表示数的中点上
   第三项   一个极小的数       小到整项被移出尺子
```

精确的和严格大于中点，正确答案是进位。但硬件把第三项整个丢了，
它看到的和正好是中点，于是按规则往偶数靠，也就是不进位。差一个最低位。

这一族六十四条里有五十六条稳定地差一个 ULP。而此前所有的随机激励，
一次都没有打到过它。

要不要修？修法是让移位器额外报出「移出去的位里有没有非零的」，并进粘滞位。
这个修法有两个问题。

一是它不是无条件正确的。一个布尔量恢复不了被丢掉那部分的符号，
正负项抵消的时候，它可能把结果推向错误的方向。

二是这个单元承诺的本来就不是「正确舍入」，而是「一个 tile 内只舍入一次」。
截断发生在舍入之前，是尺子长度决定的，不是舍入方式决定的。
真要正确舍入，正解是把尺子加长到覆盖整个指数范围，让加法完全精确，
而不是给有限长的尺子打补丁。

所以这一条的处置是：写进契约，标明边界，不修。

## 五、抵消：不在契约内

第 4 条是这样一个序列：

```
   先累加出一个不为零的小和   s
   然后来一个巨大的项         X       旧的和相对它可以忽略，被清掉
   再来一个                  -X       两个大项精确抵消
```

正确答案是 s，硬件给零。这不是差几个最低位，是整个结果没了。

这一条不需要「清空」那一档才成立。把差距调小一点，走普通的抬基准，
s 被右移到尺子外面，结局一样。

要说清楚的是，**这是结构的固有代价，不是缺陷**。任何「基准跟着最大值走、
尺子长度有限」的累加器都有这一条。消除它的办法学界早有：把尺子加长到
覆盖 FP32 的整个指数范围，任何加法都不丢位，代价是尺子长好几倍。
那是另一个设计点，不是这个设计的 bug。

所以这一条也是写进契约：灾难性抵消不在这个单元的误差承诺范围内。
写清楚比修掉更重要 —— 一个用户如果不知道这条边界，会在自己的算法里踩上去；
知道了，他可以自己决定要不要换个求和顺序。

## 六、第五条不是尺子的错

跨 tile 那一条要单独说，因为它经常被读反。

一个 tile 算完，结果转回 FP32 再当下一个 tile 的初值。转一次舍一次。
K 越长，tile 越多，舍的次数越多。测出来是这样：

| K | tile 数 | 窗口累加器 | 逐项舍入的旧形态 |
|---|---|---|---|
| 64 | 1 | 0 | 339 |
| 128 | 2 | 8 | 85 |
| 256 | 4 | 16 | 108 |
| 512 | 8 | 97 | 546 |

左边那一列自己看，像是「K 大了就不准」。加上右边一列才是完整的：
同样的输入，同样的 K，窗口形态比旧形态好五到十倍。
增长的那部分是分块这件事本身的代价，是部分和走 FP32 这个接口决定的，
换成什么累加器都一样。

还有一件事值得写下来：**不要给这张表配一个「按块数算」的上界。**
分块求和的误差正比于条件数，也就是各项绝对值之和除以总和的绝对值。
抵消得越厉害，条件数越大，误差越大，而条件数是没有上界的。
所以任何形如「n 个 tile 最多 n 个 ULP」的说法都是错的。
真要设闸门，只能拿实测值加余量当回归基线，并且在注释里写明它是基线不是定理。

## 七、判据自己也要被验一次

上面每一条结论背后都有一条判据。那么判据本身对不对？

办法是把金标准改坏，看判据红不红。准备了五个改法：给移出位补粘滞、
把换基改成对称截断、清空那一档改成不清、末项舍入改成截断、把尺子加长八位。
每一个都是对某条路径的真实改动，硬件一字未动，所以「硬件与金标准逐位相同」
这条判据必须当场红。

第一次跑，五个里有四个没红。

四个都不是判据坏了，是配错了激励：

- 对称截断配到了「反复换基」那组上。可那组的丢位量在结果最低位之下四十位，
  换个截断方向照样看不见。得让换基之后发生抵消，被丢掉的低位重新成为主角，
  才看得见。
- 「清空那一档改成不清」的第一版写法，是把旧的和右移到尺子最底下再留着 ——
  移完就是零，和清掉是同一个结果。改成原地不动才是有效的改坏。
- 「舍入改成截断」配到了中点那组上。那组每一条都精确卡在中点、尾数取偶，
  往偶数靠和直接截断都是不进位，两种舍入给同一个答案。
- 「尺子加长八位」配到了长串小项那组上。那组丢的位本来就看不见，加长也白加。

这里还有一层更隐蔽的：换基那条改坏之后一开始怎么都红不了，
追下去发现是激励构造的问题——单精度数换算到定点尺子上时，低二十四位是零填充，
所以只有初值、没有真乘积的累加器，右移多少位都一位不丢。
必须先垫两个真正的二十四位乘二十四位的乘积，累加器的低位才有东西可丢。

调整之后五个全红。

这一轮的收获不止是「判据现在有效了」。它同时是第三节那个结论的独立证据：
**有三条路径，改坏了都看不出来。** 这比「测下来是零」更强。

## 八、最后

这一章没有改一行硬件。它做的是把一个「测下来是零」的结论，
换成一组带边界、带反例、带反证的说明：

- 三条路径在数学上够不着结果的最低位，有可算的界，改坏了也看不出来。
- 一条会稳定地差一个最低位，构造是确定的，处置是写进契约而不是打补丁。
- 一条是结构的固有代价，学界早有更贵的解法，不在这个设计点上。
- 一条根本不属于累加器，是分块接口的账，而且同样条件下仍比旧形态好一个数量级。

对一个准备开源的单元来说，这组说明比那句「最大 ULP 为 0」有用得多。
后者会被读成「精确」，然后有人在灾难性抵消的场景里踩上去。
