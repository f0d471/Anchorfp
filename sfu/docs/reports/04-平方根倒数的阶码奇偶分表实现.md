# 平方根倒数的阶码奇偶分表实现

## 一、动机

四个函数里，平方根倒数的软件实现最便宜：它可以用位运算取初值再做牛顿迭代，
不需要多项式。在一颗无浮点单元的 32 位软核上，单次调用约 600 个周期，
另外三个函数都在三千周期上下。

它仍然需要硬件，理由有两条。第一条是调用位置：均方根归一化每层都要算一次
`1/sqrt(平方和)`，法向量与协方差的归一化同样如此，这些计算位于串行路径上，
不能与其他计算重叠。第二条是它的分解方式：前两章的指数要做定点化与常数乘法，
正弦余弦要做相位乘法，而平方根倒数的压缩、查表、还原三步全部是位操作与整数加法，
一次乘法都不需要。

## 二、为什么是这几步

浮点数写成 `x = m · 2^e`，其中 `m ∈ [1, 2)`。分解为：

```text
1/sqrt(m · 2^e) = 1/sqrt(m) · 2^(-e/2)
```

`1/sqrt(m)` 的定义域只有 `[1, 2)`，值域 `(0.707, 1.0]`，制表；
`2^(-e/2)` 是 2 的幂，加进阶码字段。而 `m` 与 `e` 在 FP32 编码里本来就分开存放，
压缩这一步只是取字段。

问题出在 `e/2`：`e` 是整数，除以 2 不一定是整数。`e` 为奇数时余下半个二次幂，
即一个 `sqrt(2)` 因子。阶码字段只能存整数次幂，这个因子只能折进尾数那一半，
办法是另做一张表，把因子预先乘进表项。

于是步骤是：

1. **分类。** 拆字段，区分 NaN、正无穷、负数与零，零包括 denormal。
2. **奇偶与偏移。** 判 `e` 的奇偶，算出整数偏移 `k`。
3. **两张表并行读。** 以尾数高 10 位为地址，同时读偶数表与奇数表。
4. **还原。** 按奇偶选表项，把 `k` 加进表项的阶码字段。
5. **特殊值与流水划分。** 按分类选择特殊结果，BRAM 的读延迟由一级并行寄存器对齐。

代价是多一块 BRAM，收益是不需要开方、除法或乘法。

## 三、每一步做了什么

### 3.1 分类与 DAZ

p1 寄存五个分类旗标：NaN、`+Inf`、负数（指数字段非零且符号为负，含 `-Inf`）、
负零、正零。零的判定是指数字段为 0，所以 denormal 与零同类：
输入采用 DAZ，指数字段为 0 的位图一律按同符号零解释，正 denormal 出 `+Inf`，
负 denormal 出 `-Inf`。

DAZ 之后不存在需要规格化的输入，模块内没有前导零计数、规格化移位或 denormal 阶码修正。
这是一条库级数值约定：FP32 算术单元的输入侧按 FTZ 语义把 denormal 当作零，
本单元对同一个位图给出同样的解释。

### 3.2 奇偶与偏移

```text
e 为偶数：k = -(e/2)
e 为奇数：k = -((e-1)/2)
```

判奇偶看去偏置之后阶码的最低位，除以二是算术右移一位。奇数那一路先减 1 再除，
得到的商比 `e/2` 小半个，少掉的那半个二次幂由奇数表补上。

奇数路取 `(e-1)/2` 还是 `(e+1)/2` 是一个选择：前者要求奇数表存 `1/sqrt(2m)`，
后者要求存 `1/sqrt(m/2)`。方向选定，表的内容就固定了，换方向必须重新制表。

### 3.3 两张表并行读

```text
rsqrt_even_lut[i] = 1 / sqrt(1 + i/1024)
rsqrt_odd_lut[i]  = 1 / sqrt(2 · (1 + i/1024))
```

两张表用同一个地址，即尾数高 10 位，按区间左端点取样。
两张表同时读，返回后再按奇偶位选择。块 RAM 的读延迟固定一拍，
等奇偶判断出结果再发地址就要多花一拍；两张一起读多用一块表，省下一拍延迟。

表地址是 p1 寄存器的位直连 BRAM 地址口，不经逻辑，也不另行寄存。
BRAM 自带一级地址锁存，再寄存一次只会多付一拍。

### 3.4 阶码基准取自表项

出口的偏置阶码是 `表项阶码字段 + k`，不是 `127 + k`。
`1/sqrt(m)` 对 `m ∈ [1, 2)` 落在 `(0.707, 1.0]`，除首项 1.0 外，
这个区间的数阶码字段是 126，用 127 会让结果大一倍。

直接读表项的阶码字段，代码里就不必再记一遍"表的值域是多少"，表自己说了算。
改表的值域时，这一行不用跟着改。

`表项阶码字段 + k` 小于等于 0 时输出 `+0`，大于等于 255 时输出 `+Inf`，
其余保留表项尾数。

### 3.5 特殊值与流水划分

特殊值按以下优先级覆盖常规结果：NaN 出规范 qNaN `0x7FC00000`，`+Inf` 出 `+0`，
负数出 qNaN，负零出 `-Inf`，正零出 `+Inf`，然后是常规下溢、上溢与查表结果。

| 级 | 内容 |
|---|---|
| p1 | 分类旗标、阶码与尾数入寄存器 |
| p2 | 奇偶位、`k` 与旗标入寄存器，与 BRAM 地址采样同拍 |
| p3 | 按奇偶位选择表输出并收表 |
| out | 偏置阶码 = 表项阶码字段 + `k`，选择特殊值 |

```text
时钟沿          T    T+1  T+2  T+3  T+4
输入             A
p1 分类          -     A
p2 奇偶/BRAM     -     -    A
p3 收表          -     -    -    A
出口             -     -    -    -    A
```

单元延迟 4 拍，每拍可以发起一条。p1 到 p2 的组合路径是一次 9 位减法、
一次常量移位和一次取负。

## 四、遇到的问题

### 4.1 第一版丢掉了表项的阶码字段

第一现场。以下为按当时的问题记录还原的对比结果，原始日志未保留：

```text
区间 [1e-3, 1e3] 内与 libm 逐点对比
  相对误差超过 5% 的点：49.9%
  2 的幂：全部正确
  偶数阶码的整个八度：结果恰好大一倍
```

解读。一半的点误差超过 5%，而误差的形状极有规律：偶数阶码的输入整体大一倍，
奇数阶码的输入正确。一个恒定的 2 倍说明阶码差 1，与查表精度无关。

定位。出口装配只取了表项的尾数字段，丢掉了表项的阶码字段，统一套上 127。
偶数表项落在 `(0.707, 1.0]`，阶码字段是 126，套上 127 就大一倍；
奇数表项落在 `(0.5, 0.707]`，与 127 的假设同处一个二进制区间，恰好对上。

当时的角点测试只测了尾数为零的点，也就是 2 的幂。而 2 的幂恰好是这个缺陷的不动点，
测试选取的样本点系统性地避开了缺陷。

根因与修法。出口阶码改为 `表项阶码字段 + k`，即 3.4 节的形态。
修复后在 30016 个规格化数向量上与 libm 对比全部通过，而第一版在同一批向量上 49.9% 失败。

原判据为什么没有覆盖到它：期望值由同一套算法的复制品生成；
随机激励只取正区间，没有区分阶码奇偶；定向用例只取 2 的幂。

### 4.2 连续发起时 256 个结果全错

第一现场。单元接入一个每拍发起一条的调用方后，一组 256 个输入的结果全部错误。
其中一个输出为 `0x3F09427A`，这个值逐位等于奇数表第 757 项的原文，未经任何还原。

解读。输出等于表项原文，说明还原那一步用的阶码偏移是 0，
也就是阶码通路取到的数据与查表通路不属于同一条运算：
索引来自某一条输入，选表与阶码来自另一条。

定位。当时有两处数据寄存器由 valid 门控，各自隐含一条从未写下来的约定：
一处要求调用方把输入保持两拍，另一处要求同时只有一条运算在流水线里。
阻塞式调用方恰好满足这两条：它保持请求寄存器，并且一次只发一条。
每拍发起一条的调用方两条都不满足。

测试台复现：用 `x[i] = 1.0 + 0.37·i` 这组输入每拍发起一条，修复前第 1 个输出
逐位等于 `0x3F09427A`，与现场一致。

根因与修法。所有数据寄存器改为无条件推进，BRAM 的读延迟用一级真寄存器对齐，即 p2。
同时发现表地址先被寄存一次、BRAM 内部又锁存一次，地址被寄存了两次；
改成地址由寄存器位直连 BRAM 之后，延迟从 6 拍降到 5 拍，组合深度没有变化。

原判据为什么没有覆盖到它：测试台每次只发一条，并且把输入保持到结果出来，
驱动比真实调用方弱。现在 `tb_rsqrt_stream.v` 用 hold、pulse、每拍一条三种驱动跑同一组输入，
要求逐位相同（R2、R3），并按冻结参考比较 hold 结果（R7）。

### 4.3 早期 denormal 数值通路的阶码差 1

第一现场。早期实现曾为本单元单独计算 denormal 输入的真值：先做 23 路前导零计数，
把尾数规格化，再修正阶码。用一批覆盖整个 denormal 区间的激励验证：

```text
输入        x              硬件           libm           hw/libm
00000001   1.4013e-45     inf            2.6714e+22     —
00000002   2.8026e-45     inf            1.8889e+22     —
00000004   5.6052e-45     9.4447e+21     1.3357e+22     0.7071
00000008   1.1210e-44     6.6784e+21     9.4447e+21     0.7071
...（中间 19 行同为 0.7071）
00400000   5.8775e-39     9.2234e+18     1.3044e+19     0.7071
00800000   1.1755e-38     9.2234e+18     9.2234e+18     1.0000
00ffffff   2.3510e-38     6.5235e+18     6.5219e+18     1.0002
```

解读。最后两行是规格化数，比值为 1，正确。它们上面的每一行都是 denormal，
比值恒为 0.7071，即 `1/sqrt(2)`。恒定比值说明存在确定的常数因子，
排除了查表精度的随机散布。相对误差 29.3%，比预算大近三个数量级。
最小的两个 denormal 返回正无穷，走的是前导零过多时的饱和分支，与本条无关。

定位。`sqrt(2)` 这个因子直接指向阶码奇偶：两张表相差的正是这个因子，
阶码算错一位就会选错表。顺着规格化那一步推导：

```text
denormal 的真值 = 尾数 · 2^-149
设前导零个数为 L，则 尾数 = 2^(22-L) · (1.f)
真值 = (1.f) · 2^(-127-L)
```

规格化后应满足 `阶码 - 127 = -127 - L`，即 `阶码 = -L`，而代码写的是 `1 - L`，大了 1。
补偿只做了一半：起点取了 denormal 的名义阶码 1，而规格化左移了 `L + 1` 位，
两处各算了一次。

根因与修法。当时把起点从 1 改为 0，denormal 全域 46 个代表点与 libm 的相对误差全部回到
1e-3 以内。这条通路随后在 4.4 节被整体删除。

原判据为什么没有覆盖到它：测试台的判据全部是发起形态，没有一条比对数值；
30016 个随机向量取自规格化数区间，不含 denormal。

### 4.4 denormal 的解释与其余单元相反

第一现场。4.3 节的数值通路修正之后，同一个位图在不同单元里有两种解释：
FTZ 语义的 FP32 加法器把 `0x00000001` 当作零，本单元把它当作一个很小的正数并算出有限结果。
随后在同一批改动里又出现了一次相反的要求：单元测试台已经按 DAZ 改写，输出为

```text
PASS  R10a rsqrt(0x00000001) == +Inf (DAZ)
PASS  R10b rsqrt(negative denormal) == -Inf (DAZ)
```

而上层的集成测试对同一批输入仍要求输出有限值、相对误差小于 1e-3。

解读。两处判据各自自洽，合起来要求相反。问题不在某一处写错，
而在没有一份契约表把所有消费者要求的语义并排列出来。

定位。为 denormal 保留数值通路的局部理由是：`1/sqrt(x)` 在 `x` 趋于零时趋于无穷，
把很小的正数按零处理会把有限结果变成无穷。但使用者无法从统一规则推导本单元的行为，
必须逐单元记住例外。

根因与修法。输入统一采用 DAZ，即 3.1 节的形态：指数字段为 0 的位图按同符号零解释，
整条前导零计数、规格化移位与阶码修正随之删除。`tb_rsqrt_stream.v` 用 R9（24 个正负
denormal 代表点）、R10a 与 R10b 断言同符号无穷。契约表列出所有消费者，
改契约时须同时修改契约表、独立参考 `verify_sfu.py` 的特殊值检查与上层测试。

原判据为什么没有覆盖到它：单元测试与上层测试各自只检查自己那一侧，
没有任何一条判据比较两侧对同一输入的要求。

### 4.5 DAZ 之后多出一级空流水

第一现场。删除 denormal 通路之后，原先承载规格化的那一级只剩下：

```verilog
wire [7:0]  exp_work  = p1_exp_e;     // 纯连线
wire [22:0] mant_work = p1_mant_e;    // 纯连线
```

解读。这一级把分类旗标、阶码、尾数原样搬一拍，不切分任何组合路径，只增加一拍延迟。

根因与修法。合并这一级，表地址改由 p1 的尾数位直出，仍是寄存器位直连、不经逻辑，
BRAM 的对齐关系不变。单元延迟 5 拍降到 4 拍，`RSQRT_FUNC_LAT` 改为 4。
`tb_rsqrt_stream.v` 的 R6 与 R9 按宏断言实测延迟，冻结参考 R7 与 9500 条固定激励逐位不变。

### 4.6 精度数字的适用范围被写宽

第一现场。模块头注释写着"对 libm 实测最大相对误差 4.9e-4"。这个数来自 30016 个
规格化数随机采样。另一份速查手册把倒数与平方根倒数合写成一条"容差 4 ULP"，
按契约审计时找到反例：输入 `0x3F801FFF` 输出 `0x3F800000`，与双精度参考相差 8185 ULP。

解读。两处是同一个形状：一个在窄条件下测出的数字被写成了宽条件下的承诺。
第一处把"规格化数的随机采样"写成了全域上界，第二处把倒数单元的容差套到了另一个函数上。
倒数单元是查表加一轮牛顿迭代，4 ULP 对得上；平方根倒数只有查表，
真实量级是 5e-4 左右的相对误差。

根因与修法。规定相对误差预算为 5e-4，写进契约；`tb_rsqrt_stream.v` 的 R11 扫满两张表的
2048 个表项，尾数低 13 位取满，每个采样点落在表项区间误差最大的一端，
所以 R11 给出的是区间上界，而不是随机采样碰到的最大值。
随机采样给出的 4.9e-4 与扫满给出的 4.881e-4 数值相近，但只有后者能当作上界使用。

预算是规格的一部分。将来某次改动达不到预算时，应当修改算子，而不是放宽预算。
