# 正弦余弦共用一条流水

## 一、动机

第 03 章把正弦与余弦做成两个函数单元，各自例化一份相位归约模块，相位偏移作为参数传入：
正弦为 0，余弦为 1024。

两份归约模块吃同一种输入、算同一个乘积，差别只在乘法之后那个 12 位加法：

```verilog
wire [72:0] p_mag    = x_mag * Inv2piQ032;                        // 41x32，4 个 DSP48
wire [54:0] uf_field = sign ? (~p_mag[54:0] + 55'd1) : p_mag[54:0];
wire [11:0] uf12     = uf_field[54:43] + PhaseOffset;              // 两份只差这一行
```

偏移加在乘法之后，所以 41 × 32 位的相位乘法被做了两遍。
一个调用方若同时需要两个函数，就要为它们各付一份乘法、一份流水寄存器与一个表端口。
第 03 章的离线综合量到，输入相互独立的两个单元合计 537 个 LUT、8 个 DSP48。

## 二、为什么是这几步

两个函数只有两处不同：相位偏移，作用在乘法之后；零点出口，作用在出口级。
其余的定点化、乘法、取补、象限映射、表与流水骨架完全相同。
所以合并只需要把这两处差别从编译期常量变成逐拍信号：

1. **偏移由参数改为端口。** 输入 `is_cos` 在发起当拍选择偏移。
2. **函数标签随 valid 链传递。** 出口级需要知道当前这一条是正弦还是余弦。
3. **出口按标签分类。** 零点出口只对正弦生效。
4. **只用一块表。** 调用方只例化一块正弦表。
5. **保留固定函数的包装。** 只需要其中一个函数的调用方仍可直接使用 `sin_func` 或 `cos_func`。
6. **等价性验证。** 合并前后的每一位结果必须相同，判据要独立于合并后的电路。

合并有一个前提：正弦与余弦不在同一拍发起。合并后的模块只有一个 `in_valid`，
这个前提由接口本身保证。每拍发起一条的性质不受影响，因为每一级都是寄存器，
没有跨拍占用的共享资源。同一个输入在同一拍需要两个结果时，例化两份即可。

## 三、每一步做了什么

### 3.1 偏移由参数改为端口

```verilog
wire [11:0] uf12 = uf_field[54:43] + (is_cos ? 12'd1024 : 12'd0);
```

`trig_phase_reduce` 的参数 `PhaseOffset` 改为输入端口 `is_cos`。
这一路选择落在乘法之后的 12 位加法上，不在最差路径的起点一侧。

### 3.2 函数标签随 valid 链传递

`is_cos` 与其余分类旗标在同一个过程块里寄存进 s0：

```verilog
always @(posedge clk) begin
    s0_is_cos  <= is_cos;
    s0_nan      <= c_nan;
    ...
end
```

标签与数据在同一级寄存，天然同拍，不需要额外对齐。出口寄存器把它送到 `out_is_cos`，
与 `out_data` 同拍有效。调用方若在同一条流水里交错发起两个函数，可以用它区分结果。

### 3.3 出口按标签分类

```verilog
if (s0_nan | s0_inf | s0_domain)
    out_data <= 32'h7FC0_0000;
else if (!s0_is_cos && s0_zero)
    out_data <= {s0_sign, 31'b0};
else
    out_data <= {s0_res_sign, bram_dout[30:0]};
```

第二条分支是整个模块唯一区分两个函数的地方。余弦在零点由正常通路读表末项 1.0，
正弦在零点走这条出口保号，理由见第 03 章 3.5 节。

### 3.4 只用一块表

表地址由归约组合逻辑直接驱动，在发起当拍被 BRAM 采样。交错发起时，
相邻两条运算占用的是相邻两拍的地址口：

```text
时钟沿        T     T+1    T+2    T+3    T+4
发起          S0    C1     S2
地址口采样    S0    C1     S2
s0 与表输出   -     S0     C1     S2
出口          -     -      S0     C1     S2
```

任意一拍地址口上只有一条运算的地址，所以一块表足够。

### 3.5 固定函数包装

`sin_func` 与 `cos_func` 各只含一次 `sincos_func` 例化，把 `is_cos` 固定为 0 或 1，
端口与合并前的函数单元相同。它们有两个用途：只需要一个函数的调用方直接使用；
合并前写好的测试台不用修改，继续驱动同名模块。

### 3.6 等价性验证

合并前后的 9500 条固定激励逐位比较。冻结参考 `golden_ref.txt` 由合并前的电路产生，
与合并后的电路无关；测试台经由固定包装驱动合并后的电路，结果与冻结参考逐位相同。

新增 `tb_sincos_shared.v`，每拍交错发起正弦与余弦，输入与标签都不保持，
检查三件事：每一条都按顺序返回，标签与结果逐位正确，`flush` 之后不出现有效输出。
定向向量包括 `sin(+0)`、`cos(+0)`、`sin(±1)`、`cos(±1)`、`sin(+Inf)`、sNaN、
极小负正规数与支持域边界 `2^17`。

## 四、遇到的问题

### 4.1 流水式调用方需要两块表的论证

第一现场。一个每拍发起一条的调用方里有一条注释，解释为什么正弦与余弦必须各接一块表：

```text
两者在本模块的流水线上会同时在飞，共用一块会撞地址。
```

解读。这条论证把"同时在飞"与"同拍占用地址口"当成了一件事。
两条运算同时在流水线里，并不意味着它们在同一拍使用地址口。

定位。表地址由组合逻辑直连 BRAM，在发起当拍就被采样；
该调用方的执行级只有一个操作寄存器，正弦与余弦不可能在同一拍发起。
两条在飞的运算占的是相邻两拍的地址口，见 3.4 节的时间轴。
另一个阻塞式调用方里，正弦与余弦本来就共用一块表，靠一路地址选择，一直工作正常。

根因与修法。一块表对两种调用方都成立。合并之后调用方只需例化一块正弦表。

原判据为什么没有覆盖到它：这是一条写在注释里的技术断言，没有任何判据检查它；
而两块表在功能上同样正确，逐位对拍无法区分两种接法。

### 4.2 等价对拍的两侧是同一个模块

第一现场。复核合并时，另写了一个对拍测试台，把 `sincos_func` 与 `sin_func`、`cos_func`
并排跑 9500 条激励，报告 0 条失配。按规矩向合并后的电路注入一处错误，
把出口的 `!s0_is_cos && s0_zero` 改为 `s0_is_cos && s0_zero`。
直接探测确认注入生效：`cos(+0)` 返回 0，`sin(-0)` 丢掉符号。而那个对拍仍然报告 0 条失配。

解读。注入确实改变了电路行为，判据却没有报错，说明判据本身是空的。

定位。`sin_func` 与 `cos_func` 只是 `sincos_func` 的包装，对拍的两侧跑的是同一份电路，
注入同时改变了两侧，比较结果永远相同。

根因与修法。删掉这个对拍，等价性由 3.6 节的冻结参考承担，它由合并前的电路产生，
不受注入影响。同一处注入下，`tb_sincos_shared.v` 的结果为：

```text
  FAIL  item 1 op=COS x=00000000 got(tag=1,data=00000000) expected=3f800000
  FAIL  item 7 op=SIN x=80800000 got(tag=0,data=00000000) expected=80000000
  FAIL  T2 alternating tags and bit-exact results match
```

两个定向向量分别指出了注入造成的两处错误：`cos(+0)` 返回 0，极小负正规数的正弦丢掉符号。

原判据为什么没有覆盖到它：判据的参考值来自被测电路自身。注错不报错有两种可能：
判据无效，或注入的那一行在当前激励下不可达。这一次是前一种。

### 4.3 合并表没有省下 BRAM

第一现场。合并立项时写的验收目标之一是"少用一块 RAMB36"。离线综合的结果：

| 形态 | RAMB36 |
|---|---:|
| 两个单元，各接一块表，输入相互独立 | 1 |
| 一条共用流水，一块表 | 1 |

解读。两个单元明明例化了两块表，综合结果却只有一块 RAMB36。

定位。两块表的初值完全相同，综合器把它们映射到了同一块 RAMB36 的两个端口上，
最差路径的终点 `u_sin_tab/dout_reg/ADDRBWRADDR` 就是那块 RAMB36 的 B 端口地址。
合并之前就只占一块 RAMB36，"少用一块"这个目标从一开始就不存在。

根因与修法。合并表的收益是删掉重复的例化与那条错误的注释，BRAM 用量不变。
合并之后的实际收益在乘法与流水寄存器上，见 4.4 节与第五节。

原判据为什么没有覆盖到它：验收目标按"例化了几块表"估算，没有按综合后的网表单元计数核对。

### 4.4 同一路输入时综合器已经合并了乘法

第一现场。在输入是否独立这一点上做对照，离线综合三种形态：

| 形态 | LUT | FF | DSP48 |
|---|---:|---:|---:|
| 两个单元，输入相互独立 | 537 | 74 | 8 |
| 两个单元，共用同一路输入 | 302 | 71 | 4 |
| 一条共用流水 | 285 | 40 | 4 |

解读。两个单元共用同一路输入时，DSP48 只有 4 个，与共用流水相同。
两份相位乘法的输入是同一组线网、常数也相同，综合器识别出这是同一个乘积并只保留一份。
两路输入独立时，两份乘法无法合并，DSP48 为 8 个。

定位。合并的收益取决于调用方怎样连接输入。输入来自同一组寄存器时，
综合器已经共享了乘法，结构合并只再省下重复的流水寄存器与出口逻辑（17 个 LUT、31 个 FF）；
输入来自不同来源时，结构合并省下一整份乘法（252 个 LUT、4 个 DSP48）。

根因与修法。结构上共用一条流水，使这项收益不依赖综合器是否能识别出相同的乘积，
也不依赖调用方把两个函数的输入接到同一组寄存器上。

原判据为什么没有覆盖到它：单独对比"两个单元"与"一个单元"时，若只综合了共用输入的形态，
会得出"合并不省 DSP"的结论；必须把输入独立的形态也量一次，才能看清收益的条件。

## 五、结果

资源与时序：`ooc_sfu.tcl` 离线综合，Vivado 2025.2，`xc7a200tfbg676-1`，时钟约束 20 ns，
数的是网表单元。

| 形态 | LUT | FF | CARRY4 | DSP48 | RAMB36 | 20 ns 下 WNS | 逻辑级数 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 两个单元，输入相互独立 | 537 | 74 | 49 | 8 | 1 | 1.864 ns | 22 |
| 两个单元，共用同一路输入 | 302 | 71 | 25 | 4 | 1 | 1.846 ns | 22 |
| 一条共用流水 | 285 | 40 | 25 | 4 | 1 | 1.864 ns | 22 |

与输入独立的两个单元相比，共用流水少用 252 个 LUT（47%）、34 个 FF、4 个 DSP48。
三种形态的最差路径都是输入端口经相位乘法到 BRAM 地址口，逻辑级数与 WNS 基本相同，
合并没有加长关键路径。

功能：9500 条固定激励与冻结参考逐位相同；`tb_sincos_shared.v` 3 条判据通过；
`tb_sfu_stream.v` 经固定包装驱动合并后的电路，22 条判据通过，实测延迟仍为 2 拍。
