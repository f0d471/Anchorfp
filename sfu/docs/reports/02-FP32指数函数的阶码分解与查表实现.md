# FP32 指数函数的阶码分解与查表实现

## 一、动机

第 01 章确定了四个函数共用的骨架：把输入压缩到有界区间，查一张 1024 × 32 的表，
再把压缩时保存的信息还原到结果上；每个单元是定长流水，valid 链是 `flush` 的唯一落点，
延迟由 `sfu_lat.vh` 记录并由测试台断言。

指数是第一个按这个骨架落地的单元，也是级数最多的一个。

`exp(x)` 的输入没有自然的周期或对称性可以利用，输出又横跨 FP32 的整个指数范围：
`x` 约大于 88.7 时上溢，约小于 -87.3 时结果低于最小正规数。
直接给 `x` 制表是做不到的，必须先找到一个分解，让其中一部分落在有界区间上，
另一部分能用整数运算还原。

## 二、为什么是这几步

分解建立在以 2 为底的幅值拆分上：

```text
a = |x| · log2(e) = n + f
n = floor(a),  f = a - n,  0 <= f < 1

x >= 0:  exp(x) = 2^n · 2^f
x <  0:  exp(x) = 2^(-a) = 2^(-n-1) · 2^(1-f)
```

`n` 是乘积 `a` 的整数部分，不是输入 `x`；`f` 是 `a` 的小数部分，不是常数 `log2(e)`。

这个分解划算的原因在 FP32 的格式上。阶码字段存的正是 2 的幂次，
给表项的阶码字段加上 `n` 就等于乘以 `2^n`，只是一次整数加法。
`2^f` 的定义域是 `[0, 1)`，正好制表。

从分解往下推，需要的步骤依次是：

1. **定点化。** 要乘 `log2(e)`，先要把 FP32 输入变成定点数。浮点数的尾数与阶码分开存放，
   定点化是一次由阶码决定方向与位数的移位。
2. **常数乘法与切位。** 乘完之后，整数部分 `n` 与小数部分的高位在同一串位里，
   切开只是位选。
3. **负数映射。** 数据通路只算正幅值 `a`。`x < 0` 时要把 `-(n+f)` 改写成
   `(-n-1) + (1-f)`，表索引随之镜像。
4. **上下溢判定。** 结果可能超出 FP32 的表示范围，判断依据是 `n` 的大小，在阶码域完成。
5. **查表与对齐。** 同步读 BRAM 有一拍读延迟，控制字段要与表数据同拍到达出口。
6. **还原与特殊值。** 把 `n` 加进表项阶码，按分类旗标选择 NaN、无穷、零等特殊结果。

少了定点化，常数乘法无法对齐；少了负数映射，负输入要么另建一张表，
要么在表后再做一次倒数；上下溢若不在阶码域提前判定，还原时的阶码加法会回绕。

## 三、每一步做了什么

### 3.1 定点化：Q8.20，双向移位

目标格式是 Q8.20，整数 8 位、小数 20 位，共 28 位。
8 位整数覆盖到 128，包住了上溢点 88.7 与下溢点 -87.3；
20 位小数给表索引 10 位，另留 10 位截断余量。

FP32 规格化数的值是 `mant24 · 2^(real_exp - 23)`，其中 `mant24 = {1, frac}`。
要得到 `|x| · 2^20`，尾数需要移动 `real_exp - 3` 位，方向可正可负：

```text
real_exp >= 7       |x| >= 128，饱和，后级必然判为上溢或下溢
3 <= real_exp <= 6  左移 real_exp - 3 位
real_exp < 3        右移 3 - real_exp 位，超过 27 位时结果为 0
```

这一段属于常规实现：一个双向桶形移位器加一路选择。需要点明的是左移量只有 4 位，
它只在阶码落在 3 到 6 时被使用，取值 0 到 3。这个位宽的安全性来自上一路已经把
`real_exp >= 7` 截走，而不是移位量自身能表示足够大的数。

### 3.2 常数乘法与切位

`log2(e) = 1.4427`，乘以 `2^20` 取整存成 21 位常数，格式 Q1.20：

```text
Log2eQ120 = round(log2(e) · 2^20) = 0x171547
```

Q8.20 乘 Q1.20 得到 Q9.40，共 49 位。取高 29 位得到 Q9.20，丢掉的 20 位小数是截断误差，
量级 `2^-20`，比下游用到的分辨率 `2^-10` 小三个数量级。

```text
product[48:20] = y_raw，Q9.20
  y_raw[27:20] = n        整数部分
  y_raw[19:10] = idx      小数高 10 位，表索引
```

把 `[0, 1)` 均匀切成 1024 份并判断落在第几份，在定点表示下就是取高 10 位，不需要乘除。

这是一次 28 × 21 位的常数乘法，综合映射到 DSP48。乘法之后只剩位选、8 位或 10 位加减
与阈值比较，所以乘法与切位放在同一级。这一段属于常规实现。

### 3.3 表的取样与负数映射

索引是纯截断，同一个表项覆盖的真实 `f` 落在 `[idx/1024, (idx+1)/1024)` 内，
误差是单边的。表若按区间左端点取样，误差区间是 `[-1/1024, 0]`；
按区间中点取样，误差区间被搬到 `[-0.5/1024, +0.5/1024]`，最大值对半。

表按中点取样：

```text
exp_lut[i] = 2^((i + 0.5) / 1024)
```

负输入需要的是 `2^(1-f)`。`1-f` 落在 `((1023-idx)/1024, (1024-idx)/1024]`，
这个区间的中点是 `((1023-idx) + 0.5) / 1024`，恰好是表的第 `1023-idx` 项。于是负数映射为：

```text
(n, idx) → (-n-1, 1023-idx)
```

这是一个特定手段，取样点与镜像常数必须成对选择。它带来的代价是：
极小正规数输入的 `a` 近似为 0，结果落在表的首项或末项上，即 `2^(±0.5/1024)`，
编码为 `0x3F800B18` 与 `0x3F7FE9D3`，而不是精确的 1.0。相对误差 3.4e-4，在预算之内。

中点取样的理论最大相对误差为 `ln2 / 2048 = 3.39e-4`。

### 3.4 上下溢判定

在阶码域判定，不等到还原之后：

```text
x >= 0, n >= 128:  2^n · 2^f >= 2^128，上溢出 +Inf
x <  0, n >= 126:  2^(-n-1) · 2^(1-f) < 2^-126，低于最小正规数，出 +0
```

负方向的 `2^(1-f)` 落在 `(1, 2]`，所以阈值取 126 而不是 127。

### 3.5 查表与对齐

BRAM 是同步读：地址在第 k 拍被采样，数据在第 k+1 拍出现。
表索引在 s1 给出，与表读并行增加一级寄存器 s1d，把分类旗标、`n` 与原输入推到与表数据
同一拍；s2 同时收下表数据与 s1d 的控制字段。

| 级 | 内容 |
|---|---|
| p0 | 拆包、分类、Q8.20 定点化 |
| s1 | 常数乘法，切出 `n` 与 `idx`，负数映射，上下溢判定 |
| s1d | 与 BRAM 读并行，控制字段推后一拍 |
| s2 | 收表 |
| out | 把 `n` 加进表项阶码，选择特殊值 |

连续发起 A、B、C 三条时的时间轴：

```text
时钟沿          T    T+1  T+2  T+3  T+4  T+5  T+6  T+7
输入             A     B    C
p0               -     A    B    C
s1               -     -    A    B    C
BRAM/s1d         -     -    -    A    B    C
s2               -     -    -    -    A    B    C
out              -     -    -    -    -    A    B    C
```

单元延迟 5 拍，每拍可以发起一条。`sfu_lat.vh` 的 `EXP_FUNC_LAT` 记为 5。

### 3.6 还原与特殊值

表项存的是 `2^f` 的完整 FP32 编码。乘以 `2^n` 只改阶码，尾数原样搬运：

```text
n >= 0:  new_exp = lut_exp + n，用 9 位中间量接住进位，超过 254 钳到 255
n <  0:  new_exp = lut_exp - |n|，减到 0 以下钳到 0
```

结果符号恒为 0。特殊值按以下优先级覆盖常规结果：
NaN 出规范 qNaN `0x7FC00000`，`+Inf` 出 `+Inf`，零与 denormal 出 1.0，
`-Inf` 出 `+0`，然后是下溢与上溢。

## 四、遇到的问题

### 4.1 第一版只实现了右移

第一现场。第一版指数单元在 `[-40, 40]` 上与 libm 对比，输出如下：

```text
range[-40,40]: max rel err = 2.354e+17  at x=-40,  spikes(>1e-2) = 160001 / ~266k 采样
x=-0.01 → hw=0.990568  libm=0.990050     (0 附近 OK，~7e-4)
x=-40   → 真值 exp≈4.2e-18，硬件返回 ≈ O(1) 垃圾
下溢探针：[-10,-90] 步进 0.5 内 hw exp 从不正确返回 0
```

解读。第一行的最大相对误差 2.354e+17 说明某些输入下输出与正确答案无关，
误差比真值大十七个数量级。二十六万个采样点里有十六万个相对误差超过 1%，
六成的定义域是错的。第二、三行给出错误的形状：零点附近正常，误差 7e-4，
与设计目标一致；到 `x = -40` 就完全失效，正确答案是 4.2e-18，硬件给出 1 附近的数。
第四行说明大负输入下这个函数从来不会正确返回 0。

把这个形状放回负载看：softmax 计算的是 `exp(score - max)`，输入恒为负，
序列越长负得越多。一个本该下溢到 0 的项返回 1 附近的数，softmax 的分母被污染，
整行权重失真，并逐层放大。

定位。先排除"移植时译错"：直接运行生成那一版表与期望值的脚本，用同样的输入，
脚本给出的结果与硬件一致，错误在设计本身。接着定位到定点化：
第一版整数部分只留了约 4 位，`|x|` 超过 7 就饱和；移位量用 6 位无符号数表示且只实现了右移，
阶码大于 3 时 `3 - 阶码` 下溢回绕成一个很大的数，移位结果为零，
`|x| >= 16` 的输入全部被当成 0 处理。

根因与修法。定点格式改为 Q8.20，移位改为双向，饱和分支先于窄位宽的左移量，
即 3.1 节的形态。

原判据为什么没有覆盖到它：期望值由一个 Python 脚本生成，而这个脚本是同一套硬件算法的
逐位复制品；随机激励又只取 `[-10, 10]`，恰好落在第一版正确的那条窄带里。
期望值改由 libm 生成、激励覆盖全定义域之后，第一版在同一套测试上 81% 失败。

### 4.2 第一级占满了时钟周期

第一现场。实现后的时序报告中，时钟周期 20 ns，最差建立时间路径如下
（起点属于集成方的上游寄存器，实例名略去）：

```text
<上游寄存器>/x_r_reg[25] → …24 级… → exp_func/s1_idx_reg[6]/R
19.001 ns / 20 ns，逻辑 6.957 (36.6%) + 布线 12.044 (63.4%)，CARRY4×11 + LUT×13
```

解读。这条路径用掉 19.001 ns，是全设计最差的一条。终点是本单元第一级的索引寄存器，
中间 24 级逻辑，其中 11 个进位链单元，说明路径上有加法或乘法。
逻辑 6.957 ns 已占三分之一个周期，布线占六成则说明路径跨越的物理距离也长。

当时第一级里放了四件事：拆包、桶形移位定点化、28 × 21 位乘法、切位与符号修正与上下溢比较，
全是组合逻辑，最后才寄存。那一版实现限定乘法不使用 DSP，乘法由 LUT 与进位链搭成。

定位。先考虑缩短乘法本身：在不用 DSP 的前提下，部分积压缩树的深度与进位链长度固定，
没有可压缩的余地。再考虑缩小位宽：20 位小数是精度下界，8 位整数是覆盖范围下界，都不能减。
长进位链消不掉，能改的只有切级。

根因与修法。把原来的第一级按每级只做一件事拆成三级：p0 定点化，p1 乘法独占一级，
s1 切位、符号修正与上下溢判定。单元延迟从 4 拍变为 6 拍。
切级之后，这条路径不再出现在最差路径之列。

原判据为什么没有覆盖到它：功能测试不检查时序，这条路径只出现在实现后的时序报告里。

### 4.3 连续发起时阶码取自下一条输入

第一现场。单元改为每拍发起一条之后，结果的尾数正确、阶码错误。
仿真复现后，错误的阶码逐位等于下一条输入应有的阶码。

解读。尾数走查表通路，阶码走控制字段通路，两条通路取到了不同运算的数据。
尾数属于本条，阶码属于下一条，说明控制字段通路比查表通路快了一拍。

定位。表索引在 s1 给出，BRAM 下一拍才出数据。当时收表级的写法是"晚一拍去读 s1 的寄存器"：
单条运算在流水线里时，s1 没有被覆盖，晚一拍读到的仍是它自己；
连续发起时 s1 每拍都被下一条刷新，晚一拍读到的就是下一条。

根因与修法。用一级真寄存器代替时序上的巧合，即 3.5 节的 s1d：与 BRAM 读并行，
把控制字段推到与表数据同一拍。这一级与读操作占用同一拍，不增加延迟。
修复后连续发起与逐条隔离发起的结果逐位相同。

原判据为什么没有覆盖到它：当时的测试台每次只发一条，等结果落地再发下一条，
这种发起形态下缺陷不成立。现在 `tb_sfu_stream.v` 用 hold、pulse、每拍一条、隔拍四种驱动
跑同一组输入，要求结果逐位相同（X1、X2、X8）。

### 4.4 乘法映射到 DSP 之后多出一级寄存

第一现场。允许乘法使用 DSP 之后，4.2 节拆出的流水为：

```text
p0 定点化 → p1 乘积寄存 → s1 切位/修正/比较 → BRAM+s1d → s2 → out     共 6 拍
```

解读。乘积由 DSP48 算出后，p1 到 s1 之间只剩位选、8 位或 10 位加减和阈值比较，
组合深度很浅；p1 这一级寄存边界已经不再切分任何长路径。

根因与修法。把乘积寄存级与切位级合并，乘法输出直接进入切位与修正逻辑，
s1 在同一沿锁存最终字段，valid 链由 `v0` 到 `v4` 收为 `v0` 到 `v3`，
`EXP_FUNC_LAT` 由 6 改为 5，即 3.5 节的形态。

修改前后 9500 条固定激励的指数结果变化数为 0，`tb_sfu_stream.v` 的 X4 实测延迟为 5。
这一步不改变数值，只减少一拍延迟。依据本单元延迟搭建对齐流水的调用方须同步更新，
这正是延迟常数必须引用宏的原因。

### 4.5 常数比注释写的数学值高 14

第一现场。代码与注释：

```verilog
localparam [20:0] Log2eQ120 = 21'h17_1555;    // round(log2(e) * 2^20)，Q1.20
```

`log2(e) · 2^20 = 1512775.395`，四舍五入是 `0x171547`，与代码里的值相差 14。

解读。表面上是一个笔误，改回注释写的值似乎就行。但这个常数直接决定每一条结果的误差分布，
改之前需要先知道改了之后误差怎样变化。

定位。先把 `exp_func` 逐级复刻成一个位精确的模型，在 9500 条冻结激励上与 RTL 零失配，
再用它在稠密输入上量不同形态的误差：

| 形态 | 最大相对误差 | 平均绝对相对误差 |
|---|---|---|
| 左端点表 + `0x171555` + 镜像 `1024-idx`（原样） | 6.72e-4 | 2.18e-4 |
| 左端点表 + `0x171547` + 镜像 `1024-idx` | 6.95e-4 | 3.48e-4 |
| 中点表 + `0x171547` + 镜像 `1024-idx` | 1.03e-3 | 4.28e-4 |
| 中点表 + `0x171547` + 镜像 `1023-idx`（现形态） | 3.56e-4 | 1.69e-4 |

第二行是只把常数改回数学值的结果，平均误差反而增加 60%。

原因在截断。左端点表下，索引截断让误差单边落在 `[-1/1024, 0]`。
常数相对上偏 `eps` 之后，误差区间平移成 `[eps·a - 1/1024, eps·a]`。
这里 `eps = 9.255e-6`，解得在 `a = 52.8`，即 `|x| = 36.6` 处误差区间正好居中，
而 36.6 落在定点化支持范围 `|x| < 128` 的中段。扫描常数取值，平均误差最小点在 `0x171553`。
所以 `0x171555` 是一个居中偏置，几乎就在最优点上。它的问题在于注释把它写成了数学常数，
读代码的人无法从注释复算出代码里的值，也就无法判断它是否正确。

第三行说明只换表也不行。换成中点表后，负输入需要的中点落在 `1023-idx`，
沿用左端点表下的 `1024-idx` 会把误差推到一整格之外。
左端点表下的 `idx == 0` 退化分支（映射为 `(-n, 0)`）在中点表下也不再需要。

根因与修法。偏置之所以有效，是因为问题出在取样口径：左端点取样造成单边误差，
偏置只是把它挪到中间。把表改为中点取样、镜像改为 `1023-idx`、删去 `idx == 0` 的退化分支，
误差天然居中，常数回到数学值 `0x171547`，即 3.2 与 3.3 节的形态。
现形态的最大相对误差 3.56e-4，贴住中点取样的理论上界 3.39e-4，量化之外没有别的误差源。

原判据为什么没有覆盖到它：注释里的事实断言没有任何检查；冻结的逐位参考只回答"行为是否改变"，
若直接改常数并重新冻结参考，所有判据都会通过，而平均误差已经增加 60%。
这一轮的正确性由与 RTL 无关的数学参考 `verify_sfu.py` 承担，它按 libm 计算相对误差并检查上限。

同一轮还统一了 NaN 的出口：指数单元原先把 NaN 原样透传，sNaN 进 sNaN 出，
与正弦余弦输出规范 qNaN 的做法不一致。现在输出一律为 `0x7FC00000`，契约见第 01 章。
