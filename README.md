本仓库提供两组可独立使用的 Verilog-2001 模块，二者采用同一套数值约定（输入 DAZ、输出 FTZ、规范 qNaN）：

- **fp**：加减、乘、比较、类型转换与近似倒数五个标量单元，以及一个定点窗口乘累加单元。
  加、减、乘、比较与转换在 FTZ 语义下与 IEEE-754 binary32 的就近舍入逐位一致。
- **sfu**：指数、正弦、余弦与平方根倒数四个超越函数单元，以定义域压缩、1024 项查表与字段还原实现，
  结果为近似值，误差预算写入契约。

两组模块面向的场景是 FPGA 上的加速器：控制核通常没有浮点单元，热点中既有标量浮点运算，
也有长点积与超越函数，逻辑资源以万计。设计上的主要取舍在两处：乘累加单元以一把 88 位、
基准跟随最大项的定点窗口代替 FP32 累加器，一块之内只舍入一次；超越函数单元以固定延迟的查表结构
代替迭代或多项式求值，并对精度给出可验证的预算。

## 2. 数值契约

承诺分为三档，顺序即优先级。完整条目见 [`fp/rtl/datapath-manual.md`](fp/rtl/datapath-manual.md) 第 11 节
与 [`sfu/rtl/sfu-manual.md`](sfu/rtl/sfu-manual.md) 第 5 节。

**A 档，不可协商。** 加、减、乘、比较、转换在定义域内正确舍入；在共同定义域上与软件浮点例程逐位一致；
同一输入永远得到同一输出；比较器对非 NaN 输入给出真实序关系；特殊值传播规则确定；
能在编译期检查的违约在编译期检查；文档中的每一个精度数字都有验证出处，并注明验证范围。

**B 档，明示偏离。** 输入 DAZ，输出 FTZ，下溢在舍入之后判定；只实现就近舍入到偶数；不产生异常标志；
算术结果保证为 quiet NaN；近似倒数误差不超过 4 ULP；超越函数单元为近似原语，
误差预算为指数相对误差 4e-4、正弦与余弦绝对误差 1.6e-3、平方根倒数相对误差 5e-4；
乘累加误差由一条不等式约束（第 4.5 节）。

**C 档，性能、面积与功耗**，排在前两档之后。

判断一条偏离属于取舍还是缺陷的标准是：能否用一句不带"通常""大多数"的话说清楚，
并且使用者据此能判断自己是否受影响。FTZ 在非规格化区间的相对误差是 100%，
但它是边界清晰、全域一致的规则，因此属于取舍；"某些输入恰好差一点"即使误差很小也不可接受。

## 3. fp：标量单元

五个标量单元均采用教科书做法，这里说明使用者需要知道的实现要点。

- **乘法器**两级流水：级 1 完成拆包、特殊值标志、24 × 24 位尾数乘法与阶码相加，级 2 完成规格化、GRS 舍入与组装。
  阶码中间量为 10 位带符号数，避免 8 位无符号在上溢时回绕成下溢。级 1 输出的未舍入 48 位积供乘累加单元使用。
- **加法器**三级流水：对阶、加减与前导零规格化、舍入与组装。异号精确相消的结果为 +0，
  FTZ 产生的零保留数学上的符号。
- **比较器**返回 -1、0、+1 三态码，输入 `gt_family` 选择 NaN 时的返回方向，使 lt、le、eq、ne 族与 gt、ge 族
  在调用方的判断下都得到"条件不成立"。三态码在含 NaN 时不构成全序，不能直接用作排序比较器。
- **转换器**两个方向不对称：整数转浮点需要前导零计数与舍入，浮点转整数向零截断并在越界时饱和。
- **倒数单元**由中点取样的 1024 项表给出初值，经一轮定点牛顿迭代，误差不超过 4 ULP，2 的整数次幂精确。
  它只作为显式运算提供，不用于替换除法：IEEE 754 要求除法正确舍入，以近似倒数替换会改变已编译程序的结果。

| 运算 | 保证 | 判据 |
|---|---|---|
| 加、减、乘 | FTZ 语义下与 IEEE-754 binary32 就近舍入逐位一致 | 45 万条随机向量 0 ULP；右移分支粘滞位定向用例 |
| 比较 | 三态码，NaN 按两族方向返回 | 约 20 万条随机向量与 32 条定向用例 |
| 转换 | 双向转换，越界饱和 | 10 万条随机向量与 36 条定向用例 |
| 倒数 | 误差不超过 4 ULP | 2 万条随机向量，容差判据 |
| 非规格化数 | 输入与输出均按同符号零处理 | 283 条定向用例 |
| 延迟 | 各值为实测量，不由流水级数推算 | `tb_fp_lat`，17 条判据，含调用契约注错 |

## 4. fp：定点窗口乘累加

### 4.1 逐项舍入的误差

通用 FPU 计算点积的方式是：乘一项，舍入为 FP32，加入累加器，再舍入为 FP32。
累加器只有 24 位有效位，每一项舍入两次，误差随长度累积。K = 64 的点积与无限精度求和对比，每档 300 组：

| 激励 | 88 位窗口 | 逐项舍入的同序 FP32 |
|---|---:|---:|
| 常规 | 0 | 1168 |
| 极小值 | 0 | 164 |
| 宽跨度（乘积阶码跨 210 位） | 0 | 79 |

右列是直接串接标量乘法器与加法器得到的结果。

### 4.2 精确累加的代价

另一种做法是把累加器做到足够宽，使 FP32 全指数范围内的任何乘积都能原样放入，全程不舍入，
最后舍入一次。这是 Kulisch 累加器，posit 的 quire 是它的标准化形式。FTZ 语义下两个 FP32 相乘，
最小非零乘积为 `2^-252`，最低有效位在 `2^-299`，最大乘积小于 `2^256`，覆盖其间每一位需要 555 位。

同一份 RTL 将 `GrowW` 由 15 设为 482 即得到 555 位的累加器。同一流程、同一器件（xc7a200t-1，20 ns，单 lane 离线综合）：

| 窗口宽度 | LUT | FF | WNS | 逻辑级数 |
|---:|---:|---:|---:|---:|
| 88 | 1278 | 496 | 7.528 ns | 17 |
| 555 | 9106 | 1956 | 0.605 ns | 49 |

面积为 7.1 倍；更主要的代价在时序：逻辑级数由 17 增至 49，20 ns 下的余量由 7.53 ns 降至 0.61 ns。
这条加法链位于反馈环内，环长增加一拍即意味着吞吐减半。

![design space](fp/docs/figures/fig-designspace.svg)

### 4.3 88 位窗口的构成

一次求和中决定结果的是量级相近的项，比最大项小 `2^-40` 的项不会影响结果的最低位。
因此窗口跟随最大项移动：基准 `B` 满足不变式 `B >= E + WinUp`，来了更大的项就把基准上抬，
累加器在同一拍算术右移相同位数。窗口宽度由四项相加得到：

```
 48   两个 binary32 尾数相乘的未舍入积，24 × 24
 16   WinG，基准量子化后最大项落点的区间宽度
  8   WinFrac，最大项最低位之下保留的位数，决定认证精度 Q
 15   GrowW = ceil(log2 N)，一次累加最多 32768 项的求和增长
  1   符号
 ---
 88
```

48 位一项是设计前提：乘积不先舍入。乘法器级 1 的 48 位原始积直接进入窗口，这就是融合乘加。
同一批向量下，若乘积先按 IEEE 舍入一次再进入窗口，最大误差由 0 变为 1027 ULP。

### 4.4 宽度由两条式子确定

```
AccW = 48 + WinG + WinFrac + ceil(log2 N) + 1
Q    = 46 + WinFrac − ceil(log2 N)
```

默认 `WinFrac = 8` 时，`N ≤ 255` 得 `Q = 46`，`N ≤ 4096` 得 `Q = 42`，`N ≤ 32768` 得 `Q = 39`。
88 位对应 32768 项这一档；只需 255 项的使用者可将 `GrowW` 设为 8，以 81 位得到 `Q = 46`。

在同一流程下扫描 `WinFrac` 与 `GrowW`：

| AccW | 认证精度 Q | LUT | FF | WNS | 逻辑级数 |
|---:|---:|---:|---:|---:|---:|
| 81 | 32 | 1215 | 475 | 7.333 ns | 17 |
| 84 | 35 | 1359 | 488 | 7.528 ns | 17 |
| 88 | 39 | 1278 | 496 | 7.528 ns | 17 |
| 92 | 43 | 1321 | 508 | 7.528 ns | 17 |
| 96 | 47 | 1348 | 520 | 7.200 ns | 17 |

81 到 96 位区间内面积与时序基本平坦：15 位认证精度对应约 11% 的 LUT，逻辑级数恒为 17，
相邻两档的非单调表明扫描噪声约为 ±5%。扫描 `GrowW` 得到相同形状，LUT 数只由 `AccW` 决定。
因此 88 位的选择由上面两条式子确定，面积与时序在这一段上不构成约束；代价的陡增发生在通向 555 位的过程中。

### 4.5 误差契约

一项进入窗口前要右移到共同刻度，信息损失有五处，分别处理：

| # | 路径 | 结论 | 依据 |
|---|---|---|---|
| 1 | 对齐右移，移出窗口的低位 | 受下式约束，不影响结果最低位 | 可算的界；254 项最不利构造实测 0 ULP |
| 2 | 抬基准时累加器整体右移 | 同上 | 反复换基 200 余次的定向向量 0 ULP |
| 3 | 负数右移的截断方向与正数相反 | 无系统性偏差 | 64 对镜像向量严格反号 |
| 4 | 移出位含决定进位方向的信息 | 在确定构造下差 1 ULP | 64 条定向构造中 56 条复现 |
| 5 | 基准重锚清空旧和之后发生抵消 | 结果可以整体丢失 | 结构固有代价，仍受下式约束 |

记 `A = Σ|tᵢ|` 为输入绝对和，`Z` 为末项舍入之前的窗口值，`S` 为精确和，则恒有

```
|Z − S| < 2^(−Q) · A
```

该界只依赖基准的不变式。抵消场景中 `S` 变小而 `A` 不变小，界依然成立，
代价是验收须按绝对误差与输入尺度检查，不能要求接近零的 `S` 保持固定的相对误差。
2352 组逐前缀检查（含 5093 次换基、1221 次清空）中，`|Z−S|·2³²/A` 实测最大值为 3.36e-07。

第 4 条不修正。修正方法是让移位器输出移出位的粘滞信息，实测增加 194 个 LUT（+15.2%），
且一个布尔粘滞位无法恢复被丢弃残差的符号，正负项抵消时可能把结果推向错误方向。
需要这 1 个 ULP 时，正确做法是加宽窗口，即 4.2 节的设计点。

第 5 条为任何"基准跟随最大值、长度有限"的累加器所共有。除写入契约外，模块输出 `mac_prec`，
在基准重锚时逐块置位，供调用方汇总；它只报告这一类事件，普通抬基准时不置位。

完整推导、反例构造与判据的注错验证见 [fp/docs/reports/08](fp/docs/reports/08-FP32乘累加换成定点窗口累加器.md)。

### 4.6 跨块

一块算完后，部分和转为 FP32 作为下一块的初值，每个块边界舍入一次。这属于分块接口的代价：

| K | 块数 | 88 位窗口 | 逐项舍入的同序 FP32 |
|---:|---:|---:|---:|
| 64 | 1 | 0 | 339 |
| 128 | 2 | 8 | 85 |
| 256 | 4 | 16 | 108 |
| 512 | 8 | 97 | 546 |

![accuracy](fp/docs/figures/fig-accuracy.svg)

分块求和的误差正比于条件数，而条件数没有上界，因此不存在"n 块最多 n 个 ULP"形式的上界。
回归闸门以实测值加余量设定。

### 4.7 调用契约

以下约定在网表中不检查，由仅仿真的断言接住（`fp/rtl/fp32_mac_assert.vh`，C1 到 C5 各带独立计数器）：

1. 相邻 `prod_valid` 的间隔不小于 `FP32_MAC_PACE`（当前为 1）。
2. `last` 与末项 `prod_valid` 同拍。
3. 末项之后到 `out_valid` 之前不得再喂积。此时流水线中仍有在飞的项，而模块内部没有任何忙标志为高。
4. 末项到 `out_valid` 的实测拍数等于 `FP32_MAC_OUT_LAT_F(FuseMul)`。
5. 一次累加进入窗口的项数不超过 `2^GrowW`。

第 5 条另有例化期检查：调用方通过参数 `MaxTerms` 声明每块最大项数，超过认证上限时在例化期报错。

## 5. sfu：超越函数单元

### 5.1 结构

四个函数采用同一结构：以字段拆分、移位、加法与常数乘法把输入压缩到有界区间并保存整数信息，
用 10 位地址读取 1024 × 32 的同步 ROM，再把保存的信息还原到结果的阶码或符号上。
没有迭代，没有反馈环，每个单元都是定长流水线，每拍可发起一条。

1024 项是一块 RAMB36（36,864 位）能容纳的最大二次幂深度。表项存完整的 FP32 位图，
还原时直接复用其符号、阶码与尾数字段。

### 5.2 各单元

- **exp_func。** 令 `a = |x| · log2(e) = n + f`，`exp(x) = 2^n · 2^f`，`n` 加入阶码，`2^f` 查表。
  表按区间中点取样，截断索引的误差区间居中，理论最大相对误差为 `ln2/2048 = 3.39e-4`；
  负输入映射为 `(n, idx) → (−n−1, 1023−idx)`，取样点与镜像常数成对确定。
- **sincos_func。** 令 `P = |x| / (2π)`，其小数部分即一个周期内的相位，一次乘法完成归约，与角度大小无关。
  负角通过对相位小数字段取二补数得到，表只存四分之一周期。`cos(x) = sin(x + π/2)`，
  两函数的差别只是乘法之后的相位偏移，由输入 `is_cos` 逐拍选择。支持 `|x| < 2^17`，
  超出范围的有限输入返回规范 qNaN，而不是一个看似合法的数值。
- **rsqrt_func。** `1/sqrt(m · 2^e) = 1/sqrt(m) · 2^(−e/2)`，阶码为奇数时剩余的 `1/sqrt(2)` 折入奇数表，
  两张表并行读取、按奇偶选择。出口阶码取表项自身的阶码字段加上偏移，整个单元不含乘法。

`sin_func` 与 `cos_func` 是把 `is_cos` 固定为常量的包装，供只需要一个函数的调用方使用。

### 5.3 精度

![sfu accuracy](sfu/docs/figures/fig-sfu-accuracy.svg)

| 函数 | 指标 | 预算 | 实测最大值 | 测量方法 |
|---|---|---|---|---|
| exp | 相对误差 | 4e-4 | 3.579e-4 | 9500 条固定激励，与 libm 对比 |
| sin / cos | 绝对误差 | 1.6e-3 | 1.501e-3 | 同上，`|x| < 2^17` |
| rsqrt | 相对误差 | 5e-4 | 4.881e-4 | 两张表全部 2048 个表项，各取区间误差最大端 |

预算是规格的一部分，改动后达不到预算时应修改算子，而不是放宽预算。

### 5.4 正弦与余弦共用一条流水

两函数的相位偏移加在乘法之后，因此共用同一次乘法、同一张表与同一条两拍流水，函数标签随 valid 传到出口。
与两个输入独立的单元相比，共用流水减少 252 个 LUT（47%）、34 个 FF 与 4 个 DSP48，最差路径余量不变。
两个单元若由同一路输入驱动，综合器会合并两份相同的乘法，此时差距缩小为 17 个 LUT 与 31 个 FF；
结构上共用使这项收益不依赖综合器的合并。

![sfu shared](sfu/docs/figures/fig-sfu-shared.svg)

### 5.5 表的生成与加载检查

四张表由 `sfu/sim/gen_luts.py` 从公式确定性生成，同时写出 JSON 与 Tcl 两份 manifest。
`$readmemh` 找不到表文件时，综合器只给出警告并生成无初值的 ROM，仿真器则读出全 X，两侧都不会报错。
因此设有三道检查：`gen_luts.py --check` 核对表与 manifest 逐字节等于生成器输出；
`sfu/syn/check_sfu_luts.tcl` 在综合前核对表的项数、首末项与 SHA-256；
单元测试台断言结果中不含 X。离线综合脚本另外检查每块 ROM 带有初值。

## 6. 结果

以下数字来自 Vivado 2025.2、`xc7a200tfbg676-1`、20 ns 时钟与 iverilog 12。更换器件或工具版本后数字会变化。

### 6.1 标量单元判据

| 判据 | 结果 |
|---|---|
| `tb_fp32_add` | 25 万向量，0 ULP |
| `tb_fp32_mul` / `tb_fp32_mul_r` | 20 万向量，0 ULP；定向 9 组，0 FAIL |
| `tb_fp32_cmp` / `tb_fp32_cvt` | 32 / 36 条定向判定与随机金标准，0 FAIL |
| `tb_fp_ftz` / `tb_fp32_denorm` | 25 条判定 / 乘法 173 条、加法 110 条，0 FAIL |
| `tb_fp32_recip` | 21 条判定，随机 20021 条最大 4 ULP |
| `tb_fp_lat` | 17 条判定，0 FAIL |

### 6.2 乘累加的面积回收

窗口形态初版单 lane 为 1470 个 LUT。经三处逐位等价的改写（最后一级只寄存舍入所需的 26 位、
前导零检测改为两级、数据寄存器与复位分离），降至 1275 个 LUT，所有测试台输出逐位不变；
当前版本增加 `mac_prec` 标志后为 1278 个。

![mac area](fp/docs/figures/fig-mac-area.svg)

其中数据寄存器与复位分离一项需要单独说明。数据寄存器写在复位块的 `else` 分支内，
意味着复位期间保持不变，这正是时钟使能的语义，综合器因此把 `rst_n` 接到这组寄存器的 CE 端。
在例化 32 条 lane 的设计中，数千个 CE 端挂在同一根复位网上，布线后的最差路径为零级逻辑、终点在 CE 引脚，
余量仅 0.053 ns；分离之后阵列内的最差路径余量为 1.550 ns。单 lane 离线综合无法观测此问题
（1275 与 1277 个 LUT，差异在噪声内），因为 88 个使能端不构成高扇出。
`fp/syn/scan_reset_as_ce.py` 可在 RTL 目录中扫描这种写法。

## 7. 已评估但未采用的方案

标量单元：

| 方案 | 依据 | 结论 |
|---|---|---|
| 以近似倒数替换除法运算 | IEEE 754 要求除法正确舍入，替换会改变已编译程序的结果 | 仅作为显式运算提供 |
| 正确舍入的迭代除法器 | 串行 24 步，面积与延迟代价高于目标负载中的收益 | 不实现 |
| 非规格化数的数值通路 | 需要前导零计数、变长移位与阶码修正 | 以 FTZ 写入契约 |
| 以截断代替 GRS 舍入 | 截断误差单向，在累加中线性增长 | 不采用 |
| 以时序余量数值作为准入门槛 | 余量随布局波动 | 改为全项满足且最差路径不为零逻辑直连 |

乘累加单元：

| 方案 | 实测 | 结论 |
|---|---|---|
| 把共享桶形移位器拆成两个专用移位器 | +28 LUT | 保持共享 |
| 为对齐移出位补粘滞位 | +194 LUT（+15.2%），且非无条件正确 | 写入契约 |
| 环内使用进位保存累加器 | LUT +24.4%、FF +22%，且与默认档不逐位等价 | 撤出支持集合，例化期拦截 |
| 按流水级把乘累加单元拆成多个模块 | 面积不变，接口复杂度上升 | 仅将仿真断言外提 |

超越函数单元：

| 方案 | 依据 | 结论 |
|---|---|---|
| CORDIC 或多项式求值 | 延迟与发起间隔受迭代次数限制，或需串联多个乘加 | 采用查表结构 |
| 线性插值 | 需要额外一组乘加 | 不做，误差由区间宽度决定 |
| 为正弦与余弦各接一块表 | 两函数不在同一拍占用地址口 | 共用一块 |

进位保存一项曾被判定为"与默认档逐位相同"，相应回归一直通过。改用会发生抵消的激励后，
64 组中 10 组结果不同：基准上调时两个分量各自算术右移并截断，不等于先相加再截断。
判据本身没有错误，缺失的是对"该结论须用何种激励验证"的规定。

## 8. 验证方法

验证分三层，每层覆盖其他层无法覆盖的一类缺陷。

**逐位金标准与独立参考。** 标量单元对照由 C 语言 float 生成的 IEEE-754 期望值（`fp/sim/gen_*_vectors.c`）。
乘累加单元有两层模型：一层逐位复刻硬件，一层以有理数精确求和后一次正确舍入，两层的输入侧代码各自独立实现；
将第一层的乘积阶码改动一位，两层对拍的最大误差由 0 变为 139809444 ULP，以此确认二者独立。
超越函数单元同时使用两类判据：冻结的逐位参考输出只判断行为是否变化，
`sfu/sim/verify_sfu.py` 按 libm 独立计算误差并逐条检查特殊值，二者不能互相替代。

**注错验证。** 判据本身须经过验证。乘累加单元对金标准注入五处错误（补粘滞位、换基改为对称截断、
清空改为保留、末项舍入改为截断、窗口加宽八位），逐位对拍必须报错：

```
==== 注错见红：金标准被改坏时上面那五条判据必须当场红 ====
  align_jam            注错见红 (56 组不匹配, 用 halfway 向量) -> PASS
  rescale_rtz          注错见红 (16 组不匹配, 用 cancel 向量) -> PASS
  clr_keep             注错见红 (32 组不匹配, 用 cancel 向量) -> PASS
  pack_trunc           注错见红 (72 组不匹配, 用 mirror 向量) -> PASS
  win_pad              注错见红 (56 组不匹配, 用 halfway 向量) -> PASS
```

一次注错未报错存在两种可能：判据无效，或被注入的路径在当前激励下不可达。不加区分会导致修改一个本来有效的判据。
超越函数单元的表加载检查、共用流水的标签逻辑与 flush 通路同样经过注错验证，结果记录在
[sfu/docs/reports/01](sfu/docs/reports/01-SFU查表架构与函数选型.md) 与 [05](sfu/docs/reports/05-正弦余弦共用一条流水.md)。

**报告层判据。** 所有入口脚本以失败计数决定退出码，并要求输出中至少存在一条通过标记；
全部通过返回 0，任何一条判据失败返回 1，可直接接入 CI。

## 9. 快速开始

```bash
# 依赖：iverilog >= 12、gcc、python3；lint 需要 verilator；综合需要 Vivado
git clone https://github.com/f0d471/Anchorfp.git && cd Anchorfp

bash fp/sim/gen_vectors.sh      # 生成标量单元的金标准向量（派生数据，不入库）
bash fp/sim/run_all.sh          # 标量单元逐位对拍、乘累加各档与延迟检查
bash fp/sim/run_mac_audit.sh    # 乘累加的定向反例、注错验证与误差报告
bash fp/sim/lint.sh

bash sfu/sim/run_all.sh         # 表校验、发起形态、逐位对拍与独立参考复核
bash sfu/sim/lint.sh

# 离线综合（在对应 syn 目录下执行）
cd fp/syn  && vivado -mode batch -source ooc_units.tcl -tclargs fp32_add
cd sfu/syn && vivado -mode batch -source ooc_sfu.tcl   -tclargs exp_func
```

## 11. 与其他开源实现的关系

| | 语言 | 覆盖面 | 累加语义 | 非规格化数 | 定位 |
|---|---|---|---|---|---|
| [FPnew / cvfpu](https://github.com/openhwgroup/cvfpu) | SystemVerilog | FP64/32/16/16alt/8，参数化 | 逐项舍入 | 支持 | RISC-V 通用 FPU |
| [Berkeley HardFloat](http://www.jhauser.us/arithmetic/HardFloat.html) | Verilog（Chisel 生成） | 指数与尾数位宽可配 | 逐项舍入 | 支持 | IEEE 合规参考实现 |
| [FloPoCo](https://flopoco.org/) | C++ 生成 VHDL | 任意精度算子生成器 | 含精确累加器算子 | 视算子 | FPGA 专用算术生成器 |
| Xilinx Floating-Point Operator | 闭源 IP | FP32/64 | 逐项舍入 | 可配 | 厂商 IP |
| Anchorfp | Verilog-2001 | FP32，FTZ | 每块一次舍入 | FTZ | 边缘加速器的标量、点积与超越函数通路 |

短流水的 FP32 加乘、GRS 舍入、查表加牛顿迭代的倒数，以及查表实现的超越函数，均为常规做法。
定点精确累加源自 Kulisch 在 1970 年代的工作，其 FPGA 设计空间由 de Dinechin 等人系统研究
（[Floating-Point Accumulation and Sum of Products](https://doi.org/10.1007/978-3-031-42808-1_21)、
[Design-space exploration for the Kulisch accumulator](https://hal.science/hal-01488916v2)），
posit 的 quire 是同一思想的标准化形式。

本仓库的工作集中在两点：一是精确累加与逐项舍入之间的设计点，即基准动态跟随的 88 位窗口、
一拍反馈环与未舍入乘积的融合，并把窗口截断造成的损失测量清楚、写成使用者可以推理的契约；
二是为近似的超越函数给出精度预算、表的可复现生成与加载检查。被推翻的判断与未采用的方案一并记录在开发记录中。
